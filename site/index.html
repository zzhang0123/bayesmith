bayesmith.

A graph of operators is a Bayesian model; its structure chooses the inference.

bayesmith is a Bayesian compilation layer that sits between the model declaration and the numerical backend. It records a model written as operators into an explicit, inspectable graph, discovers and verifies the graph's structure, eliminates exactly whatever admits a closed form, picks an execution backend for what remains, and hands back results that carry their applicability conditions, diagnostics and provenance. It is not another probabilistic programming language, and not a collection of samplers.

A model
def mixed(data):
    x  = sample("x",  lambda: dist.Normal(jnp.zeros(2), 2.0).to_event(1))
    nu = sample("nu", lambda: dist.LogNormal(0.0, 0.5))
    mu = det("mu", lambda x_, nu_: (A @ x_) * jnp.exp(0.1 * nu_),
             x, nu, linear_in=("x",))
    observe("d", lambda m: dist.Normal(m, 0.5), mu, obs=data)

plan = bayesmith.compile(trace(mixed, data))
print(plan)

linear_in=("x",) is a claim about the model, not a hint. It is probed at three scales and three outside points; if it does not hold the route is refused rather than silently used.

The problem it solves

Three sentences are the whole premise: a model is a graph of operators; the graph's structure decides which inference applies; a structural declaration must be checked, not trusted.

Premise one

A model is a graph of operators

Deterministic operators propagate dependence; probabilistic operators each contribute a conditional density; together they are the joint distribution. trace() runs an ordinary Python function once and records it as an explicit Graph: a static DAG whose declaration order is its topological order, whose nodes are equinox Modules, so the whole graph is a differentiable pytree.

Premise two

Structure chooses the inference

Within one graph, linear-Gaussian blocks take a Wiener / GCR exact solve, latents declared discrete are enumerated exactly, blocks that are affine in log space take log-GCR, and the rest goes to NUTS. compile() writes that decision down as an InferencePlan, block by block, with its evidence. "Eliminate before brute force" is the last of the ten invariants.

Premise three

Declarations are claims, and claims are checked

linear_in= promises the prediction is affine in that latent. exact.linearity compares the model against its own linearization; exact.gaussian reads (loc, scale) off a node's distribution and then verifies the reading against the node's own log_prob. A false declaration would otherwise produce a confident, wrong posterior instead of an error.

Five questions it should progressively answer

The top-level design defines "general" as generality of the workflow, not as implementing every distribution and every sampler. For any graph in the supported domain, bayesmith should be able to say:

  1. What joint distribution does this model actually declare?
  2. Which parameters, directions or combinations can the data identify?
  3. Which parts can be handled exactly, which inference path should the remainder take, and why?
  4. Is the posterior, evidence or predictive conclusion trustworthy, and under what conditions?
  5. After the current result, which next steps are legal and informative?

Positioning and boundaries

"Exploiting structure" is not precise enough on its own: libraries such as BlackJAX already ship algorithms for specific structures. bayesmith's differentiating job is to discover and verify structure from the whole graph, combine exact and numerical routes across subgraphs, and say why that combination is legal for the task at hand.

Semantics it owns

  • The Graph and its structural semantics: nodes, support, plates, dependence
  • Structure checks, exact elimination, compilation of the residual problem
  • A task-aware InferencePlan, and the reasons a route was chosen or refused
  • One result protocol across exact, sampling, optimization and external backends
  • Applicability, Refusal, diagnostics, provenance and quality gates
  • Exact algorithms that are narrow, mathematically clear and independently verifiable: the linear-Gaussian sampler, GLS, square-root information, chain recursions
  • Astronomy-shaped compiler passes and graph-native scientific diagnostics

What it explicitly does not do

  • Reimplement a full PPL, a distribution library or a general sampler zoo
  • Replace numerical capabilities NumPyro, BlackJAX, JAXNS or ArviZ already maintain well
  • Grow its own generic MCMC, SMC, VI, nested sampling, optimizers or NPE architecture families
  • Reimplement mature statistics such as R-hat, ESS, PSIS, LOO, WAIC
  • Become a DAG scheduler, task queue, chat framework or agent framework
  • Let an LLM rewrite statistical truth, lower diagnostic standards or bypass a gate
  • Modify the user's scientific model by default
bayesmith owns epistemic state transitions, not conversational agency.
top-level design §1.2 — it defines "given which evidence one may move from which state to which"; a future agent only chooses, explains and orchestrates among legal actions.

Five-layer architecture

Lower layers never depend on upper ones; the InferencePlan is the one authorised boundary through which a Graph reaches a backend; a Result must be read together with the Plan that produced it; when an upstream fingerprint changes, every downstream artifact is invalidated.

The six-step lifecycle

Declare a Graph and bind its data → Analyze to discover structure, verify premises and find what cannot be identified → Compile the exact eliminations, parameterization and residual backend into a Plan → Execute the Plan within budget into a Result → Evaluate numerical quality, calibration and predictive performance → Decide the legal next step from the gates, or stop formally with a reason. Today's code covers the first four steps; the fifth is being built in R3; the sixth is future work.

bayesmith.marginalcore
LAYER 3 · 12 modules · 27 public names
Each dataset's marginal likelihood, compressed to a fixed-size square-root information term [R | z].
The information F = RᵀR is positive semi-definite by construction, the working condition number is √κ(F), and accumulation is one QR, which is what keeps a thousand-epoch campaign inside float64. campaign derives each epoch's designs, constants, data and covariance from the graph; chain is a square-root Schur recursion for a nuisance that drifts across epochs; diagnostics says whether a campaign can be trusted from its stored terms alone; logdet is the premise-checked log-determinant ladder. It does not compute the graph-level evidence p(d): a term is a function of the parameters with only that dataset's nuisances integrated away. Core concepts

Graph
The single source of model truth: random variables and deterministic nodes, support, shape, plates, dependence, data binding. It carries no sampler configuration, execution state, diagnostic conclusion or workflow history.
linear_in
det(..., linear_in=("w",)) promises that, holding every other latent fixed, the prediction is affine in w. It is a checked claim: check_linearity compares the model to its linearization at 3 scales × 3 outside points and raises AffinityRefused on failure.
block / route
compile partitions the latents into blocks and gives each a route: GCR exact, GCR + SNIS, GCR + MH accept, NUTS; factor_partition adds log-gcr. A block's κ and the tol derived from it are printed side by side so a reader can check the division.
InferencePlan
What compile() produces: the partition, each block's evidence, the execution shape. It is the one authorised boundary between a Graph and a backend; plan.sample() / plan.estimate() read it and re-derive nothing.
Task → Result
Five questions with five answers: Posterior, Evidence, Predictive, PointEstimate, Simulation. A Task is the question itself and holds only references, fingerprints, a budget and bounded options, never a Graph or a callable.
Four posterior representations
DrawsPosterior, WeightedDrawsPosterior, AnalyticPosterior, FittedConditionalPosterior, tagged by class rather than flattened into "draws plus optional weights", because a weighted sample whose weights were dropped is a wrong sample, not a lossy one.
Refusal
A judgement at a statistical or capability boundary, carried as data rather than as an exception: a stable failed_premise code, non-empty grounds with the numbers measured, a ScopeRef, non-empty Remedy. Programming errors are exceptions; method inapplicability is a Refusal.
Gate
Several reports in, one status and one verdict out. Status is BLOCKED / INVALIDATED / ERROR / EVALUATED and only EVALUATED carries PASS / FAIL / ABSTAIN; a report's applicability is a separate axis, APPLICABLE / INAPPLICABLE / UNVERIFIABLE. Aggregation is order-independent and truth-table tested.
fingerprint vs artifact id
A fingerprint is a SHA-256 over canonical bytes and is semantic: the same model, data and task give the same digest on any machine, and caching, reuse and invalidation are decided by it. An artifact id is a UUID4 minted once: it says which artifact, never what it was made of.
RunRecord
Referenced by every Result: plan, fingerprints, seed, dtype / device / JAX configuration, backend and version, budget, termination reason, timing, warnings, approximation class. Run conditions are part of the result.
square-root information term
[R | z] with log L(x) = −½‖Rx − z‖² + const. One epoch's marginal likelihood compressed to a fixed-size sufficient statistic; rank deficiency is representable, accumulation is a QR, the condition number is a square root. A marginal-likelihood component, not the evidence.
ModelRef
How a model is referenced when persisted: identifier, graph fingerprint, source digest, data identity, build arguments. model_ref_from_callable derives the source digest automatically for a model defined in an importable module; a function typed into a REPL or built by exec must pass source_digest explicitly, and repr() is never a fallback because it carries a memory address.

1 · Declare, compile, sample

Whole graph exact: prints block 0 {x} GCR exact … execution: iid draws, no chain
import jax, jax.numpy as jnp
import numpyro.distributions as dist
import bayesmith
from bayesmith import trace, sample, det, observe

N  = 32
xi = jnp.linspace(-1.0, 1.0, N)
A  = jnp.stack([jnp.ones(N), xi], axis=1)

def straight_line(data):
    x  = sample("x", lambda: dist.Normal(jnp.zeros(2), 2.0).to_event(1))
    mu = det("mu", lambda x_: A @ x_, x, linear_in=("x",))
    observe("d", lambda m: dist.Normal(m, 0.5), mu, obs=data)

graph = trace(straight_line, data)
plan  = bayesmith.compile(graph)
print(plan)                              # see what it intends to do first
post  = plan.sample(jax.random.key(0), num_samples=2000)

2 · The typed task protocol (since R1)

Task in, Result or Refusal out, with fingerprints and a RunRecord
from bayesmith.artifacts import PosteriorTask, model_ref_from_callable, new_task_meta

def model(data):
    x = bayesmith.sample("x", lambda: dist.Normal(0.0, 2.0))
    bayesmith.observe("d", lambda v: dist.Normal(v, 0.5), x, obs=data)

graph = bayesmith.trace(model, jnp.array([1.0, 2.0]))
task  = PosteriorTask(meta=new_task_meta(label="radiometer posterior"))
ref   = model_ref_from_callable(model, identifier="radiometer")

planned = bayesmith.compile_task(graph, task, model_ref=ref, key=jax.random.key(0))
result  = bayesmith.execute_task(planned, key=jax.random.key(0))
# result: a PosteriorResult whose representation is a DrawsPosterior;
# result.run carries seed, dtype, devices, backend, budget, termination, timing, fingerprints

top-level design §1.4normative

Ten invariants

The ten package-wide rules from the design document. The engineering discipline below, and the shapes of Refusal and Gate, are what these ten look like once they reach code.

  1. One fact has one place of declaration. The Graph is the single source of model truth.
  2. Compile first, then execute. An optimization must verify its premise; when it fails, refuse or degrade, never apply silently.
  3. Keep statistical objects strictly distinct. prior, likelihood, marginal likelihood term, evidence and posterior may not share names.
  4. Every conclusion has an applicability. When a required diagnostic is missing, ABSTAIN rather than default to trusted.
  5. The approximation level must be visible. exact, certified deterministic, Monte Carlo and heuristic may not blur into one kind of result.
  6. Run conditions must be traceable. seed, dtype, device, backend, version, data identity and budget are part of the result.
  7. External backends do not define the core API. Adapters obey bayesmith's task and result protocol.
  8. An agent cannot bypass a gate. It may only choose among the legal actions the current state exposes.
  9. Failure is a first-class artifact. A Refusal states its evidence, the failed premise and the available remedies, not just exception text.
  10. Eliminate before brute force. Structure that can be reliably identified and eliminated exactly takes precedence over general, expensive algorithms.
CLAUDE.md (= AGENTS.md) · tests/ · .github/workflows

Engineering discipline

The most recognisable part of this repository is not an algorithm but the machinery that guarantees "numerically correct" rather than merely "runs". Each rule was written down after a failure, and CLAUDE.md records the date.

Test layering

Fast layer 2,853 · full 5,402

The heavy numerical-gate boundary and mutation grids are marked full and run nightly; everything else is the pre-commit habit. test_boundary_layering.py is a meta-test: if any registered gate loses its one fast-layer cell the suite goes red, so "fast" cannot silently collapse into "no numerical-gate coverage".

Numerical gate registry

107 gates, every threshold with a provenance

tests/numerical_gates/registry.py tags each threshold as derived, borrowed, magic, exact_or_domain or api_contract, and records its mutation mode (two-sided / static-only / policy-only). A repair that cannot show what it still kills is not finished.

Independent oracles

Three references that share nothing

tests/exact/oracle.py is a pure-numpy dense reference: it assembles A column by column on a basis, with no autodiff and no CG. NUTS is the cross-check for every exact route, since a graph that qualifies for an exact solve can always run NUTS. tests/crosscheck/ compares bitwise against the implementations rheplicant kept, and skips loudly, saying why, when no rheplicant checkout is present.

Mutation testing

Commit, then mutate, then restore

Restoration uses git checkout -- src/ rather than cp, because a cp within the same second lets Python reuse stale bytecode and record a false SURVIVED. The price is that HEAD must be what you want back. Only exit code 1 means a test failed; 2, 3, 4, 5 and 143 mean other things, and scoring any non-zero as KILLED lets a typo kill every mutant.

CI · four workflows

Suite · Seam · Cross-check · Publish

Suite runs on Linux, on push / PR / nightly, in two jobs: the source tree and the built wheel. It reads counts from JUnit, refuses a run that collected almost nothing, and logs numpy, scipy, jax, the BLAS and the CPU, because the ubuntu-latest pool is not one chip. Seam and Cross-check pull rheplicant's main and run its inference layer. Publish builds after the tag, tests the wheel, then uploads.

Platform lesson

A numerical fixture must not pin one machine's arithmetic

0.7.0 passed 5375/5375 on the development laptop and failed on the Linux runner with 16 failures and 2091 errors. None was a typo: macOS numpy uses Accelerate, Linux wheels use OpenBLAS, and they differ on whether C- and F-order products agree bitwise, on the last subnormal singular value, on whether dpotrf refuses a numerically indefinite matrix, on whether a dgemm microkernel fuses a multiply-add. The rule, in order: construct the stress deterministically (hex floats, integers, Decimal); failing that, assert a derived property band; failing that, make the platform premise conditional while keeping the contract assertions unconditional; failing that, skip loudly. Never widen a tolerance to get to green.

The roadmap advances by capability gates, not by calendar. Each stage has its own execution plan, a measured acceptance matrix and a close-out page; before a stage closes, rheplicant's own suite is run against the candidate.

  • R0 · Stabilise the existing core and baselineclosed 2026-08-30

    Graph, exact, marginal, diagnose, graph reduction and the bridge frozen as a trusted baseline; full suite, ruff and wheel verification reproducible; every module assigned a long-term owner.

  • R1 · Tasks, artifacts and provenanceclosed 2026-08-30

    Five Tasks, five Results, Refusal's grounds field, fingerprints and the invalidation matrix, the two-axis gate truth table; existing posterior routes adapted into the protocol with numerical results unchanged.

  • R2 · Full posterior and the predictive seamclosed 2026-09-02

    Four posterior representations; an explicit PredictiveTask; observed-data replay strictly separated from replicated observations; pointwise log-likelihood with its observation unit; optional ArviZ export; the amortized posterior encoded as an ESTIMATOR artifact.

  • R3 · Model checking and calibrationin progress · first two tasks shipped in 0.7.2

    A general model-checking layer: prior / posterior predictive checks, held-out prediction, SBC, LOO through ArviZ, identifiability and prior-sensitivity reports, each an EvaluationReport referencing a Result. Landed so far: SimulationTask executes, bayesmith.evaluation is open, probe_28 pins the seams. Stochastic acceptance uses fixed seeds, fixed budgets and a pre-declared false-positive rate α = 0.05.

  • R4 · Evidence foundationplanned

    Promote marginal's mathematical components to a graph-level EvidenceTask: proper-prior and absolute-normalization audits, exact Gaussian / linear / discrete / chain evidence assembly, EvidenceResult, Bayes-factor comparability.

  • R5 · Nested residual evidenceplanned

    A backend-neutral CompiledEvidenceProblem; BlackJAX nested sampling and JAXNS compete on the same budget and oracles; the nested sampler receives a smaller, smoother residual problem whose premises already hold.

Ecosystem and dependencies

Four runtime dependencies

jax ≥ 0.5, equinox ≥ 0.13, numpy, numpyro ≥ 0.15. numpyro is a hard dependency rather than an extra because every graph that qualifies for an exact method must also run through NUTS; that is how the exact routes are verified. bayesmith.

A graph of operators is a Bayesian model; its structure chooses the inference.

bayesmith 是一个位于模型声明与数值后端之间的 Bayesian 编译层。 它把一个用算子写成的模型记录成显式、可检视的图，先识别并验证图的结构， 精确消掉能解析的部分，为剩下的问题选择执行后端， 最后交出带适用条件、诊断和来源记录的结果。 它不是又一个概率编程语言，也不是采样器集合。

一个模型
def mixed(data):
    x  = sample("x",  lambda: dist.Normal(jnp.zeros(2), 2.0).to_event(1))
    nu = sample("nu", lambda: dist.LogNormal(0.0, 0.5))
    mu = det("mu", lambda x_, nu_: (A @ x_) * jnp.exp(0.1 * nu_),
             x, nu, linear_in=("x",))
    observe("d", lambda m: dist.Normal(m, 0.5), mu, obs=data)

plan = bayesmith.compile(trace(mixed, data))
print(plan)

linear_in=("x",) 是一个关于模型的主张，不是提示。 它会在三个尺度、三个外部点上被探测；不成立就拒绝，不会被静默采用。

它解决什么问题

三句话就是这个包的全部前提：模型是一张算子图；图的结构决定该用什么推断；结构上的声明必须被检查而不是被相信。

前提一

模型即算子图

确定性算子传播依赖，概率算子贡献一项条件密度，二者合起来就是联合分布。 trace() 把一个普通 Python 函数跑一次，记录成显式的 Graph： 静态 DAG，声明顺序即拓扑顺序，节点是 equinox Module，所以整张图是一个可微的 pytree。

前提二

结构选择推断

同一张图里，线性高斯块走 Wiener / GCR 精确解，声明为离散的潜变量精确枚举， 对数空间里仿射的块走 log-GCR，其余交给 NUTS。compile() 把这个决定写成 InferencePlan，逐块说明路线和证据。「先消元再蛮力」是十条不变量里的最后一条。

前提三

声明是被检查的主张

linear_in= 承诺预测对该潜变量是仿射的。exact.linearity 拿模型和它自己的线性化比对； exact.gaussian 从节点分布里读出 (loc, scale) 后再用节点自己的 log_prob 回验。 一个错误的声明否则会产出一个自信而错误的后验，而不是一个错误。

它要逐步能回答的五个问题

顶层设计把「通用」定义为工作流的通用，而不是实现所有分布和所有采样器。对支持域内的任何一张图，bayesmith 应能回答：

  1. 这个模型实际声明的联合分布是什么？
  2. 数据能够识别哪些参数、方向或组合？
  3. 哪些部分可以精确处理，剩余部分走什么推断路径，为什么？
  4. posterior、evidence 或 predictive 的结论是否可信，适用条件是什么？
  5. 当前结果之后，有哪些合法且有信息增益的下一步？

定位与边界

「利用结构」本身不够精确：BlackJAX 之类的库早就有利用特定结构的算法。bayesmith 的差异化职责是 从完整的图里发现并验证结构，跨子图组合精确与数值路线，并说明这个组合为什么对当前任务合法。

它拥有的语义

  • Graph 及其结构语义：节点、support、plate、依赖
  • 结构检查、精确消元、residual problem 的编译
  • task-aware 的 InferencePlan，以及选择或拒绝一条路径的理由
  • 跨 exact / sampling / optimization / 外部后端的统一结果协议
  • applicability、Refusal、diagnostic、provenance 与 quality gate
  • 范围有限、数学清楚、可独立验证的精确算法：线性高斯采样器、GLS、平方根信息、chain 递推
  • 面向天文观测的编译 pass 与图原生的科学诊断

它明确不做的

  • 不重造完整的 PPL、分布库或通用 sampler zoo
  • 不取代 NumPyro、BlackJAX、JAXNS、ArviZ 已有且维护良好的数值能力
  • 不自研通用 MCMC、SMC、VI、nested sampling、优化器、NPE 架构族
  • 不自己实现 R-hat、ESS、PSIS、LOO、WAIC 这类成熟统计量
  • 不变成 DAG 调度器、任务队列、聊天框架或 agent 框架
  • 不允许 LLM 改写统计真值、降低诊断标准或绕过 gate
  • 不默认自动修改用户的科学模型
bayesmith owns epistemic state transitions, not conversational agency.

五层架构

下层不依赖上层；InferencePlan 是 Graph 进入后端的唯一授权边界；Result 必须和产生它的 Plan 一起解释；上游 fingerprint 一变，下游 artifact 全部失效。

六步生命周期

Declare 构造 Graph 并绑定数据 → Analyze 发现结构、验证前提、识别不可辨识的部分 → Compile 选择精确消元、参数化与剩余后端，形成 Plan → Execute 在预算内执行，形成 Result → Evaluate 检验数值质量、校准与预测能力 → Decide 依 gate 给出合法的下一步，或正式停止并说明原因。 今天的代码覆盖前四步，第五步正在 R3 里建，第六步是未来。

顶层设计 §2、§4 · docs/artifacts.mdnormativemodule-spec

核心概念

Graph
模型真值的唯一来源：随机变量与确定性节点、support、shape、plate、依赖、数据绑定。它不承载采样配置、执行状态、诊断结论或工作流历史。
linear_in
det(..., linear_in=("w",)) 承诺固定其他潜变量时预测对 w 是仿射的。这是一个会被检查的主张：check_linearity 在 3 个尺度 × 3 个外部点比对模型与其线性化，失败抛 AffinityRefused。
block / route
compile 把潜变量分成块，每块一条路线：GCR exact、GCR + SNIS、GCR + MH accept、NUTS；factor_partition 还有 log-gcr。块的 κ 与由它推出的 tol 并排打印，读者可以核对那次除法。
InferencePlan
compile() 的产物：分区、每块的证据、执行方式。它是 Graph 进入后端的唯一授权边界；plan.sample() / plan.estimate() 只读它、不重推。
Task → Result
五个问题对应五个答案：Posterior、Evidence、Predictive、PointEstimate、Simulation。Task 是问题本身，只装引用、fingerprint、预算与有界选项，从不装 Graph 或 callable。
Posterior 的四种表示
DrawsPosterior、WeightedDrawsPosterior、AnalyticPosterior、FittedConditionalPosterior，按类打标签而不是压成「draws + 可选权重」，因为丢了权重的加权样本是错的样本而不是有损的样本。
Refusal
统计或能力边界上的判决，作为数据而非异常：failed_premise 稳定码、非空 grounds（量到的数字）、ScopeRef、非空 Remedy。编程错误用 exception；方法不适用用 Refusal。
Gate
多份报告进，一个状态与一个判决出。状态是 BLOCKED / INVALIDATED / ERROR / EVALUATED，只有 EVALUATED 才有 PASS / FAIL / ABSTAIN；报告的适用性另有 APPLICABLE / INAPPLICABLE / UNVERIFIABLE 一轴。聚合与到达顺序无关，有真值表测试。
fingerprint 与 artifact id
fingerprint 是 canonical bytes 的 SHA-256，语义的：同一模型、数据、任务在任何机器上得到同一摘要，缓存、复用与失效都靠它决定。artifact id 是一次性铸造的 UUID4，只说「哪一个」，不说「由什么做成」。
RunRecord
每个 Result 都引用：plan、fingerprints、seed、dtype / device / JAX 配置、backend 与版本、预算、终止原因、计时、warnings、近似等级。运行条件是结果的一部分。
square-root information term
[R | z]，log L(x) = −½‖Rx − z‖² + 常数。一个 epoch 的边际似然压成固定大小的充分统计量；秩亏可表示，累加是 QR，条件数取平方根。它是 marginal likelihood 的部件，不是 evidence。
ModelRef
持久化时引用模型的方式：identifier、图 fingerprint、源码摘要、数据身份、构建参数。model_ref_from_callable 在可导入模块里自动取源码摘要；REPL 或 exec 出来的函数必须显式传 source_digest，repr() 永远不做兜底，因为它带内存地址。

1 · 声明、编译、采样

全图精确：打印 block 0 {x} GCR exact … execution: iid draws, no chain
import jax, jax.numpy as jnp
import numpyro.distributions as dist
import bayesmith
from bayesmith import trace, sample, det, observe

N  = 32
xi = jnp.linspace(-1.0, 1.0, N)
A  = jnp.stack([jnp.ones(N), xi], axis=1)

def straight_line(data):
    x  = sample("x", lambda: dist.Normal(jnp.zeros(2), 2.0).to_event(1))
    mu = det("mu", lambda x_: A @ x_, x, linear_in=("x",))
    observe("d", lambda m: dist.Normal(m, 0.5), mu, obs=data)

graph = trace(straight_line, data)
plan  = bayesmith.compile(graph)
print(plan)                              # see what it intends to do first
post  = plan.sample(jax.random.key(0), num_samples=2000)

2 · 带类型的任务协议（R1 起）

Task 进，Result 或 Refusal 出；带 fingerprint 与 RunRecord
from bayesmith.artifacts import PosteriorTask, model_ref_from_callable, new_task_meta

def model(data):
    x = bayesmith.sample("x", lambda: dist.Normal(0.0, 2.0))
    bayesmith.observe("d", lambda v: dist.Normal(v, 0.5), x, obs=data)

graph = bayesmith.trace(model, jnp.array([1.0, 2.0]))
task  = PosteriorTask(meta=new_task_meta(label="radiometer posterior"))
ref   = model_ref_from_callable(model, identifier="radiometer")

planned = bayesmith.compile_task(graph, task, model_ref=ref, key=jax.random.key(0))
result  = bayesmith.execute_task(planned, key=jax.random.key(0))
# result: a PosteriorResult whose representation is a DrawsPosterior;

顶层设计 §1.4normative

十条不变量

设计文档里全包共守的十条规则。后面的工程纪律、Refusal 与 gate 的形状，都是这十条落到代码里的样子。

  1. 一个事实只有一个声明位置。Graph 是模型真值的唯一来源。
  2. 先 compile，后 execute。优化必须验证前提；不满足时拒绝或降级，不能静默套用。
  3. 严格区分统计对象。prior、likelihood、marginal likelihood term、evidence 和 posterior 不得混名。
  4. 结论总有适用性。缺少必要诊断时应 ABSTAIN，而不是默认可信。
  5. 近似级别必须可见。exact、certified deterministic、Monte Carlo 和 heuristic 不能混成同一种结果。
  6. 运行条件必须可追溯。seed、dtype、device、backend、版本、数据身份和预算属于结果的一部分。
  7. 外部 backend 不定义核心 API。adapter 服从 bayesmith 的任务和结果协议。
  8. agent 不能绕过 gate。它只能选择当前状态公开的合法动作。
  9. 失败是一等 artifact。Refusal 说明证据、失败前提和可采取的修复，不只是异常文本。
  10. 先消元再蛮力。能可靠识别并精确消除的结构，优先于通用高成本算法。
