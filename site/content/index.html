bayesmith compiles a Bayesian model, written as a graph of operators, into an inference procedure that can be audited. It finds and checks the structure of the graph, solves exactly the parts that admit a closed form, hands the remainder to a numerical backend, and returns results that carry their conditions, diagnostics and provenance. It sits between the model declaration and the sampler. It is not a probabilistic programming language and not a collection of samplers.

One model, before an algorithm

Let \mathbf z collect all unknowns, \mathbf d the observed data, and \mathbf c the fixed inputs. A model combines probability factors with deterministic calculations. After evaluating the deterministic nodes, its posterior has the general form

p(\mathbf z\mid\mathbf d,\mathbf c)\propto\prod_{a\in\mathcal F}\phi_a(\mathbf z,\mathbf d;\mathbf c)

Each factor depends on the variables it names: a prior or conditional prior, an observation likelihood, or an explicitly declared graph-level density term. A deterministic node computes s_k=f_k(\mathrm{pa}(s_k)); its value is substituted into downstream factors. It contributes neither a free sampled coordinate nor a separate probability factor in this expression. The factors need not be Gaussian, the functions need not be linear, and a vector-valued likelihood can describe correlated data. Which parts admit a supported inference route is a separate question.

For exactly this drawing, with \mathbf z=(\theta,x,\psi), the joint density is

\begin{aligned}\eta&=g(\theta),\qquad s=f(x,\mathbf c),\\p(\theta,x,\psi,\mathbf d\mid\mathbf c)&=p(\theta)\,p(\psi)\\&\quad\cdot p(x\mid\eta)\,p(\mathbf d\mid s,\psi).\end{aligned}

The drawing has four probability factors, two deterministic calculations and one fixed input. It assumes independent root priors for θ and ψ; other models can connect those variables or add a joint prior factor. Each symbol may represent a scalar, vector or field. No Gaussian law, linear response or repetition axis is assumed.

A sample node can have parents

A hyperparameter is a modeling role, not a separate node type. When it is unknown, declare it with sample and give it a hyperprior; when fixed, use a constant; when derived from other nodes, use det. A downstream sample can use any of these as parents to construct its conditional distribution. Parameters can control a mean, covariance, scale or shape. Inference conditions on the data and infers the unknown hyperparameters together with the other latents.

During trace, these calls record the model rather than draw a simulated dataset. plate annotates repeated structure, and joint_prior supplies an additional density factor under its own contract; neither is an extra node class. Why structure should choose the inference

Holding the other unknowns fixed, a block can have a tractable conditional posterior even when the complete model does not. For example, a Gaussian conditional prior and Gaussian observation factors with means affine in the block and covariances independent of it give a Gaussian conditional posterior, provided no other factor involving that block breaks this form. bayesmith checks the supported structural and numerical conditions before assigning an exact route. A log-space route additionally requires the transformed prior and likelihood to have the corresponding Gaussian form; positivity or an exponential response alone is insufficient. Approximate noise transformations retain their approximation status.

In common practice this choice is made by hand. Applying a general sampler to the whole model can ignore exploitable structure; hand-written conditional updates can silently become invalid when the model changes. bayesmith derives a plan from the graph and the statistical task, checks the conditions its routes require, and records their evidence. A chain using exact conditional updates can still be correlated and must reach its target distribution.

A model is a graph of operators

trace records an ordinary Python declaration as an explicit Graph. Probabilistic nodes supply density factors; deterministic nodes propagate their inputs into those factors.

Structure chooses the inference

Eligible Gaussian blocks use exact conditional updates; supported continuous remainders use NUTS. {{api:bayesmith:factor_partition}} also checks supported log-space routes. Route eligibility depends on all relevant factors and the task.

Structure is found and checked

Automatic analysis can certify supported affine computations; numerical probes check departures at tested points. A linear_in declaration is a claim to verify. The plan records the basis and limits of its decision.

A concrete example: infer the hyperparameters too

The runnable example below instantiates the same diagram. θ is theta, η is scale, ψ is sigma, c is the fixed matrix A, and s is signal. The prior width of x and the observation noise are both inferred:

\begin{aligned}\theta&\sim\mathcal N(0,0.5^2),\\\eta&=\exp(\theta),\\\mathbf x\mid\eta&\sim\mathcal N(\mathbf 0,\eta^2 I_2),\\\log\sigma&\sim\mathcal N(-1,0.3^2),\\\mathbf s&=A\mathbf x,\\\mathbf d\mid\mathbf s,\sigma&\sim\mathcal N(\mathbf s,\sigma^2 I_4).\end{aligned}

Normal distributions here use variance or covariance as their second mathematical parameter; the Python constructors use standard deviation. The defining dependency is visible in the declaration:

theta = bs.sample("theta", lambda: dist.Normal(0.0, 0.5))
scale = bs.det("scale", jnp.exp, theta)
x = bs.sample(
    "x", lambda sd: dist.Normal(jnp.zeros(2), sd).to_event(1), scale
)

The final argument scale is a parent node reference. Its current value is passed to sd when the distribution is evaluated. This declares x | scale, while the deterministic node computes scale = exp(theta). The observation likewise has two parents: signal and sigma.

With θ and σ fixed, the prior on x is Gaussian, the forward response is affine in x and the Gaussian noise covariance is fixed with respect to x. The plan therefore gives x an exact conditional update and sends θ and σ to NUTS. The derived scale and signal and fixed A add no sampled coordinates. They still affect the density and the inference: changing θ changes the prior for x, and changing σ changes its likelihood. Each sweep uses the current hyperparameter values.

What the independent density check verifies

The script checks the full density at 27 parameter settings against an independent formula, including the scale normalization of the conditional prior and the LogNormal density of σ. theta is the sampled coordinate, so computing exp(theta) introduces no extra Jacobian factor; the density of the sampled sigma does include its LogNormal Jacobian. These checks verify the declared model, not convergence of a sampling run.

Through the typed task interface, a run returns a Result together with the plan that produced it and a run record: seed, precision, backend, budget, termination reason and whether the answer is exact or Monte Carlo. In the task protocol, a question the available routes cannot answer returns a Refusal naming the failed premise and the measurements behind it. Faults in the model itself and failed convergence are raised as exceptions.

How it differs from the libraries it uses

Inference libraries already provide algorithms for particular structures, such as latent-Gaussian or Laplace-marginalized models. bayesmith's own job is to find and verify structure in the whole graph, combine exact and numerical routes across its parts, and state why the combination is valid for the task being asked.

What bayesmith owns

  • The Graph and its structural meaning
  • Structure checks, exact elimination and compilation of the remainder
  • A task-aware plan, and the reasons a route was chosen or refused
  • One result protocol across exact, sampling, optimization and external backends
  • Applicability, refusals, diagnostics, provenance and quality gates

What it does not do

  • Reimplement a probabilistic programming language, a distribution library or a general collection of samplers
  • Replace numerical capabilities that NumPyro, JAXNS or ArviZ already maintain
  • Become a task scheduler or an agent framework
  • Let an automated agent lower a diagnostic standard or bypass a gate
  • Change the user's scientific model by default
