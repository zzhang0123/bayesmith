Structure and inference routes

A plan is the compiler's answer together with its evidence: which latents share a block, which route each block takes, what was measured to justify it, and how the blocks run together. This page reads one line by line.

How to read a plan

This is the plan for a model whose prediction is affine in x once nu is fixed. The table summarizes it; open the printed plan underneath to follow the paragraphs below.

A plan prints one head line per block, its evidence indented under it, and one execution line for the whole graph.

  • The head line names the block's index, its members and the route. Next to the route is the basis for it: structurally certified when an analysis of the traced computation proved the block affine over its whole valid domain, or numerically validated (global affinity unproved) when only the probes passed. It is followed by the size of the probe, as scales × points, and the worst departure measured over them.
  • The conditioning line reports kappa and the tol derived from it, then says whether the solver's own convergence guard can run.
  • The indented paragraph states what the checks held fixed and why, in the classifier's words. In the plan above it records that the noise does not move with the block, and that the non-Gaussian nu was held at its prior centre because it has no prior draw for this module to take.
  • The execution line says what will actually be run: independent exact draws, NUTS, or the combination of the two with the exact block solved once per sweep.

Condition number and tolerance

An exact block is solved iteratively, so the plan states the accuracy that solve is asked for. kappa is an upper bound on the block's conditioning and tol is derived from it, as the convergence target divided by that bound. The target is a relative error of 10−3. The pair is printed to eight significant digits because it is meant to be checked: three digits cannot round-trip the division.

The bound is an upper bound and a loose one, so a block whose printed kappa is large may still be solved accurately. That is why the plan prints the number instead of refusing on it.

Two further clauses can appear on that line. guard hoisted out of the sweep means the block is solved inside a compiled Gibbs sweep, where the solver's concrete-valued convergence guard cannot run, so tol carries the discipline alone. guard reachable, off by default means the graph is solved outside any trace and the guard can be switched on. A third replaces them when the requested tol is below what the current precision can deliver: the plan says the tolerance is unattainable at this dtype, and prints the product that establishes it. See installation and precision.

Which structure takes which route

Core concepts lists the five methods a block can carry. This table reads the same decision from the model's side.

StructureRouteBoundary
Linear-Gaussian with an eligible covarianceWiener solve and constrained realizationConditioning and precision checks still apply.
A supported log-linear formThe same solve in log spaceThe transformation and the noise law must justify it.
Conditionally Gaussian affine groupsExact conditional updates inside a chainEach update is exact; the joint draws stay correlated.
An eliminable exact blockCollapse the block and sample the residual targetReconstruction and target semantics must stay explicit.
A general differentiable modelNumPyro NUTSGeometry and diagnostics decide practical reliability.
An explicit proposal scheduleGLS, log-linear or Gauss–Newton proposalsThe Metropolis correction is the default; disabling it changes the approximation class.

Affinity is a joint claim

A model such as a * b is affine in a with b held fixed, and affine in b with a held fixed. It is not jointly affine in both. The compiler certifies whole candidate groups with the complementary latents kept symbolic, then checks the prior and covariance requirements. This distinction controls whether several conditional Gaussian updates can be scheduled, whether a whole-graph exact posterior exists, and whether analytic evidence is admissible. A conditional certificate is not a whole-graph claim.

When a premise fails

A failed premise does not stop the plan. The block takes a general route and the plan records what was measured: the Overview shows a false affinity declaration refused with its departures, and a model with no exact block at all compiles to NUTS with the reason on the block's own line. In the typed protocol the same judgement is returned as a Refusal rather than printed.

Inspect both compile and execution products

The compact API returns a runtime InferencePlan. The typed API returns a planned task with its analysis and a serializable plan record, or a Refusal. The run that follows records backend, budget, termination and approximation class.

Backend options are bounded inputs, not arbitrary dictionaries. An unsupported control is refused rather than ignored. See sampling policies for initialization and stopping.

Compatibility entry points

compile, InferencePlan.sample, InferencePlan.estimate, fit and their runtime result objects remain useful compact interfaces. Prefer typed Tasks and Results when storing or coordinating work. Their coexistence does not imply identical return types.

Reference: compile_task, execute_task, factor_partition, fit.
