**This page exists because a commit message said "20 applied, 20 killed, 0
surviving" and no table existed anywhere.** Red line 1 of the R5 plan says, in
as many words, that a mutation table must name every survivor individually and
that **a count is not a table**. The second adversarial review could not
corroborate that count — its own reconstruction from the same source found three
survivors — and it was right to call the number unfalsifiable rather than wrong.

**Protocol.** Each mutant: apply to `src/`, `rm -rf __pycache__`, run the suite
redirected to a file, read **pytest's own exit code with no pipe in between**,
`git checkout -- src/` (HEAD holds the work, which is why the batch commits
before it mutates), `rm -rf __pycache__` again. **Exit 1 alone is a kill** — 2 is
interrupted, 5 is nothing collected, and scoring any non-zero as a kill turns a
typo into a KILLED for every mutant. The script refuses to start on a dirty
tree, which it has already had to do once, after a timeout left a mutant behind.

## Two mutants that are EQUIVALENT, measured rather than asserted

Neither is a gap, and both are recorded so the next reader does not spend an
afternoon on them.

* **`.get_trace()` without `observed={}`.** Over all 54 shipped graphs the two
  give bitwise-identical latent draws — 0 of 54 differ, and
  `improper_outside_prior` raises on both.
* **`_latent_shape` broadcasting `plate[-1]` instead of `plate[0]`.** The
  longest `plate` tuple on any `Probabilistic` node in the repository is 1, so
  the two indices name the same plate everywhere. Nested plates are refused at
  the graph level (`test_nested_plates_are_refused_with_a_reason`).

## What each cluster of survivors cost, before it was closed

The table above is the state after two adversarial reviews. Both BLOCKED, and
the survivors they found came in clusters with one shape: **a dimension the
fixture family holds constant.**

| review | cluster | why nothing was red |
|---|---|---|
| first | M1–M4, the graph-level terms | `joint_prior` and `evidence_terms` are absent from **0 of 54** shipped graphs, so both branches were dead |
| first | M11, M12, M13 | no test passed a non-empty `exact_elimination`, read `shapes`, or built an overlapping term pair |
| second | M12, M12c | `batch_shape + event_shape != ()` holds for **0 of 54** latents — every non-scalar layout came from the plate alone, so the expression the FIRST repair introduced was itself dead |
| second | R5, R11 | `prior_sample` was value-graded only on single-latent graphs |

**M12 was not a test gap.** `shapes` really was always `()`, because the code
read `graph.shape` behind a `hasattr` guard and `Graph` has no such attribute —
the mutant and the code agreed, so no mutation of that line could have shown it
and "SURVIVED" had to be diagnosed rather than counted.

The second review's clusters are the first review's repairs. **A repair's tests
inherit the repairer's blind spot**, and the enumeration that found the first
set stopped one row short of the dimension it was fixing.
