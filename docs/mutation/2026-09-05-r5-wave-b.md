## The review BLOCKED, and the reconstruction is itself a finding

Three reviewers ran in isolated git worktrees, each instructed to enumerate from
the **fixture family's constant dimensions** rather than from the diff. **All
three died on a session usage limit before returning a structured result**, so
the table below is reconstructed from their tool traces — every exit code is one
a run printed, not one anybody inferred. What was lost is the tail of each
reviewer's set: the instrument lens had reached M12, the guards lens M5, the
fixtures lens had 29 mutants written and was running them.

Two process defects the run exposed, recorded because they cost the review:

* **The three reviewers shared one scratch directory** and overwrote each other's
  driver script. The instrument lens caught it — `mutate.py` was replaced at
  14:56:33 between its M10 and M11 runs — and correctly **voided its own M11 and
  M12** rather than reporting them. A reviewer that cannot tell its own run from
  another's is measuring nothing; a private directory per agent is the fix.
* **The workflow lost all three results to a null-handling bug of mine.**
  `agent(...).then(r => ({key, ...r}))` turns a `null` return into a truthy
  object with no `verdict`, so the `.filter(Boolean)` after it removed nothing
  and the synthesis crashed. `r && {...}` is the fix.

## Protocol

Each mutation: apply one change, `rm -rf` every `__pycache__` under `tests/` and
`src/`, run the suite **redirected to a file**, read pytest's **own** exit code
with no pipe in between, restore, clear the caches again. **Exit 1 alone is a
kill** — 2 is interrupted, 4 a usage error, 5 nothing collected, 124 a timeout,
and scoring any non-zero as a kill turns a typo into a KILLED for every mutant.
`-q` is never added: `pyproject.toml` carries one already and a second makes it
`-qq`, which deletes the summary line.

## What this cost, and the lesson it repeats

**My own red line 13 checks caught none of it, and the reason is exactly the one
red line 1 gives.** Eight repairs were made during Wave B and each was graded by
restoring the old code and re-running — all eight went red, and every one of
those mutants was enumerated **from my own change**. The single mutant the review
scored KILLED, M5, is the one I had written the grading test for myself. An
author's list of what to mutate is isomorphic to the change they made, and the
axes it omits are the axes the change never made them think about.

Wave A's page ends on the same sentence one level up: *a repair's tests inherit
the repairer's blind spot*. This page is Wave B's instance of it, and the
repairs above are now themselves owed a second review.

### Two findings that are one bug wearing different clothes

**M23.** `tail = inc * r / (1 - r) if r < 1 else inf` relaxed to `r < 2` is
NEGATIVE for `r` in (1, 2); negative is finite and compares less than any
demanded level, so a **diverging** refinement certifies. One guard was deciding
convergence *and* keeping the arithmetic meaningful, and only the first job was
pinned.

**B1.** The same shape: a condition that reads as exhaustive while the value
that breaks it slips through the arithmetic rather than through the comparison.

### The power arm wins 24 of 24 edges

Measured across a Gaussian, an exponentially cut Cauchy prior and a genuine
`z**-4` tail, `max(geometric, power)` is `power` every time, by 1.09× to 2.11×.
So `rho` only ever enters the LOSING arm and squaring it moved nothing. The
geometric arm is not dead weight: `_power_tail` returns `0.0` where the fit has
no meaning, and an **inner edge** — one closer to the origin than its neighbour —
is that case. A span of `(2, 10)` around a mode at 8 has one.

### M15 is EQUIVALENT, measured rather than argued

`_structural_class` reads `exact` only through `bool(exact)` in every branch, so
`("*",)` returns an identical label on **all 49 plans, 0 differ**. The property
the review was worried about — which latents are eliminated — is now pinned by
reading the plan directly.

## What the closed-forms lens found besides the two false docstring numbers

* **MUT-X was LIVE in the shipped test.** The closed forms had no precision
  guard, and two discrimination calls had drifted below the end of their
  `enable_x64` block. At float32 the Cauchy reference is 1.87e-07 out —
  **187× `AGREEMENT_FLOOR`** — returned silently. The test passed because what it
  discriminates is orders away: latent, not failing, which is the only reason it
  survived to be found.
* **Neither fixture added by the first repairs had a closed form.** They were
  graded only by collapsed-versus-uncollapsed agreement, which grades the
  ELIMINATION and cannot grade the FIXTURE — change the data and both sides move
  together, still agreeing.
* **`undeclared_family_parts`'s documented protection was untested.** All nine
  graph builds sat inside `enable_x64`, so nothing crossed the boundary it exists
  for. Built outside and read inside: reading gives a gap of 2.1e-08, recomputing
  **2.185 nats**.
* The reviewer's sharpest count: **8 of the 32 graphs with an exact block have a
  TWO-MEMBER block, and `CLASS_B` selects 0 of 8.**

## One near-miss in the confirmation itself

**F25's first re-application mutated the wrong line.** It replaced the GRID read
rather than the DATA read, and the grid is the same expression either way, so the
mutant was equivalent and came back green — a false SURVIVOR that was caught only
because the diagnosis did not match the mechanism. The noise draw is what differs
across precisions; against that line it dies.

Which is the same lesson as the rest of this page, applied to the instrument
rather than the code: **a mutant that does not reach the thing it names measures
nothing, and it reports the same green as a coverage gap.**
