**Goal:** raise the marginal-likelihood arithmetic that already exists at the array level into
a graph-level `EvidenceTask`. The number `Z = p(y | M) = ∫ p(y | θ, M) p(θ | M) dθ` is
computed by exact assembly only; where an exact assembly is impossible the layer refuses and
names the residual integral R5 will supply. Every constant, Jacobian and log-determinant that
enters `log Z` is carried as a named `EvidenceComponent`, graded against an oracle that shares
no arithmetic with the implementation, and swept across prior scales in both directions from
1.0.

**Architecture:** two modules inside two existing units, and no new top-level subpackage.
`src/bayesmith/dispatch/evidence.py` owns the numeric assembly, the eligibility predicates and
the compile-time refusals; `src/bayesmith/evaluation/evidence.py` owns the normalization-audit
report, the `evidence@1` gate and the comparability report. Dependency direction is unchanged:
`graph → dispatch → evaluation`, and `tests/test_layering.py` pins it. `bayesmith.evidence`
is untouched — it stays the deprecated alias it is.

**Tech Stack:** Python 3.11 frozen/slots dataclasses, JAX, NumPy/SciPy for oracles,
`decimal`/`fractions` where an exact reference is cheaper than a stable one; pytest, ruff;
`tests/numerical_gates/registry.py` for any new threshold.

## 0. Frozen rulings and execution boundary

These are R4's implementation inputs. They are not re-invented during execution. Every ruling
says what was measured and where; where a number is carried from a `record` page rather than
measured for this plan, the ruling says so and the owning task re-measures it.

### 0.1 The home is `dispatch/evidence.py` + `evaluation/evidence.py`, and no new subpackage

**Ruling.** Numeric assembly, eligibility predicates and compile-time refusals go in
`src/bayesmith/dispatch/evidence.py`. The normalization-audit report, the `evidence@1`
`GateDefinition` and the comparability report go in `src/bayesmith/evaluation/evidence.py`.
`_run_evidence` in `dispatch/task.py` is a thin adapter that calls the first. Nothing is added
under `marginal/`, and `bayesmith.evidence` is not touched.

**Why.** Four constraints intersect on exactly this location. (a) `bayesmith.evidence` is a
permanent tombstone — top-level design §7.2 line 810, and `docs/ownership.md`'s own row for it
ends "It must never host the future EvidenceTask implementation." (b) `bayesmith.marginal`
means `L_i(θ)`, a function of θ with nuisances integrated out, and its package docstring
spends twenty lines saying it is not `Z`; putting `Z` there would undo the rename. (c) The
dependency chain in §7.2 is `model/graph → analysis/compiler → execution adapters → evaluation
→ workflow`, so the compiler-side half belongs beside `dispatch/collapse.py` and the report
half beside `evaluation/gate.py`. (d) A new top-level subpackage costs a `_LAZY_SUBMODULES`
registration, a `test_public_api` expectation and two `test_layering.py` edits for no semantic
gain, because both halves already have a home whose direction is right.

**Note for the layering guard.** `tests/test_layering.py`'s edge builder is spelling-dependent:
`_absolute_module` returns the bare string `bayesmith` for both `from bayesmith import
dispatch` and `from .. import dispatch`, and `_module_scope_imports` drops any name with no
dot, so **those two spellings create no edge and trip nothing**. Task 1 repairs the builder
before relying on it; a guard that a rename walks past is the failure family CLAUDE.md
documents twice.

### 0.2 Term ownership is settled before any constant is touched

**Ruling.** Task 1 is `dispatch/collapse.py`'s double count. Every other task depends on it.

**Why.** `marginal_log_density` compresses `for observed in sorted(block.data)` — every
observed node in the block operator — while `collapse_graph` absorbs only
`observed_descendants(graph, exact)`. An observed node that is not a descendant of the exact
block is therefore counted **twice**: once inside the marginal term and once as the explicit
likelihood that survives in the reduced graph. `observed_descendants`'s own docstring says
this is the thing it exists to prevent ("absorbing it would count its density twice"); the
function is correct and its result is not used by the term.

**Measured for this plan**, in this checkout at `fb1c21f`, under `jax.enable_x64(True)`, on a
graph with `w` (exact) → `mu` → `observe d` (6 points) and `tau` (NUTS) → `nu` →
`observe e` (3 points):

| quantity | value |
|---|---|
| `observed_descendants(g, ("w",))` | `('d',)` |
| `block.data` keys | `['d', 'e']` |
| `log_joint(collapse_graph(g, ("w",), ("tau",)), {"tau": 0.7})` | `-11.464648494020468` |
| dense numpy oracle | `-8.549138548349081` |
| surplus | `-2.9155099456713867` |
| `log p(e | tau)` | `-2.915509945671389` |

The surplus **is** `log p(e | tau)`, to better than 1e-9.

**Scope and severity.** The collapse arm is opt-in (`collapse: bool = False`,
`dispatch/plan.py:645`) and its only current guard is `plan.exact.method != "gcr"`
(`execute.py:774-783`). So this is not "every mixed model is wrong": it is an opt-in arm
returning a silently sharpened posterior for a graph shape the shipped fixture in
`tests/dispatch/test_collapse.py` does not have (it has one observed node). A likelihood
counted twice is a posterior narrowed by √2, with no warning. **This is a live posterior
defect, not only a future evidence concern, and the owner may prefer to ship it as a patch
release before R4 opens.** Either way R4 cannot build on the function until it is repaired.

**Direction of the fix** (the executing session confirms it): restrict the compression loop to
`observed_descendants(graph, exact_names)` rather than `sorted(block.data)`. The alternative —
absorbing every `block.data` node in `collapse_graph` — is wrong, because a node independent of
the block is not part of the Gaussian integral over it.

### 0.3 `log Z` is five named terms, each re-derived, never one opaque scalar

**Ruling.** The exact block's contribution is carried as five `EvidenceComponent`s:
`data_log_normaliser`, `prior_log_normaliser`, `combine_corner`, `integral_log_two_pi`,
`block_log_determinant`. Each is **re-derived from the block's own inputs** (the per-sample
sigma or `Precision`, the declared prior scales, the pivots) and independently graded; the
production `offset` is then asserted equal to their sum. `log_evidence` is not defined as the
sum of whatever components happen to be present.

**Why.** Defining `log_evidence := sum(components)` is an identity that survives a dropped
term: drop a component and the sum still equals the field. Two independent derivations are
what catch a constant that was mis-split or lost, and §9.1 says so directly — "不能用同一实现的
两个入口互相证明正确", and names normalisation constants, Jacobians and log determinants as the
place it matters most. Measured decomposition of the existing arithmetic, for the assembler to
reproduce: `compress` contributes `-0.5 log det(2π N)`; `nuisance_prior` contributes
`-Σ log std - 0.5 n log 2π`; each `SqrtInfo.combine` contributes `-0.5‖corner‖²`;
`marginalise_arrays` contributes `+0.5 n_block log 2π − Σ log pivots[:n_block] − 0.5‖corner‖²`.

### 0.4 The determinant's sign is written the right way round, and pinned by a test

**Ruling.** R4 writes the integral term as
`+0.5 · n_block · log 2π − 0.5 · logdet(F_bb) − 0.5 · ρ²`, and Task 2 adds a standing numeric
assertion that `−Σ log pivots[:n_block] == −0.5 · logdet(F_bb)`.

**Why.** `dispatch/collapse.py:30-31` states the opposite: "The `-sum(log pivots[:n_block])`
folded into the offset by `marginalise_arrays` **IS** `0.5 * logdet(F_bb)`." Measured,
`−Σ log pivots[:n_block] = −2.1914870216494005` against `−0.5·slogdet(F_bb) = −2.1914870216494`.
The **code** is right and only the prose is wrong, which is worse than a code bug: this is the
sentence an R4 implementer would copy. A docstring cannot be pinned, so the repair is a test,
not only an edit.

### 0.5 Propriety is three-valued, decided by consequence, and separate from normalisation

**Ruling.** The prior audit returns `PROPER` / `IMPROPER` / `UNVERIFIABLE`, and reports
**propriety** and **absolute normalisation** as two verdicts, either of which can fail alone.
The verdict is graded against the declared density's own mass — a closed form where one
exists, otherwise fixed-node Gauss–Legendre quadrature over the declared constraint — and
never by `isinstance(d, dist.ImproperUniform)`. `UNVERIFIABLE` refuses; it never guesses.

**Why.** Three measured reasons. (a) There is no properness predicate anywhere in `src/`
today — confirmed with quoted patterns so zsh `nomatch` cannot fake the negative — so R4
builds it. (b) The two questions genuinely differ: `dist.Uniform(-2, 5).log_prob(0)` is
`-log 7`, correctly normalised and proper, while `ImproperUniform` over the same interval
returns `0.0` — proper in mass, unnormalised in density, **and** returning `0.0` outside its
own support. A single boolean cannot carry that. (c) A spelling guard is walked past by any
user `Distribution` subclass whose `log_prob` returns a constant; `unwrap` strips only
`Independent`. This is the `ProducerRef as _PR` disease, and the plan's red tests build the
bypass rather than arguing about it (§red line 4).

### 0.6 A `JeffreysPrior`-covered latent reads as NO prior declaration, not as an improper one

**Ruling.** Coverage by `graph.joint_prior` gets its own premise, `evidence_prior_undeclared`,
distinct from the improper-prior premise.

**Why.** `diagnose/priors.py:246` **requires** `ImproperUniform` on a Jeffreys-covered latent:
the node-level declaration is deliberately absent because the graph-level prior is the
declaration. Routing that through a generic "improper prior" refusal would report this
package's own mandated configuration as a user error, and would give the wrong remedy. The two
states need different messages because they need different fixes.

### 0.7 A log-space graph is refused in R4; the Jacobian is recorded, not silently added

〔Execution write-back, §red line 9: **this premise was declared and then
removed, because nothing can raise it.** A graph reaches log space only through
`dispatch/factor.py`'s `log-gcr` route, which is already outside §0.14's
admitted class, so the structure gate refuses it first. Both directions of the
premise-vocabulary test passed it — it had a remedy row, and no fixture named
it — because neither asked whether anything CAN name it. A reachability test
now does. Task 7 still lands the `log_jacobian` field, for the release that
admits `log-gcr`.〕

**Ruling.** An `EvidenceTask` on a graph produced by `exact/loglinear.py::log_space` is
refused with `evidence_base_measure_undeclared`. Task 7 (post-seam) adds `log_jacobian` as a
new field on `LogSpace`, accumulated at transform time, with the rebuilt graph's `log_joint`
asserted **bitwise unchanged** before and after; `dispatch/evidence.py` folds that field into
`Z` and nothing else reads it. Only then is the refusal lifted.

**Why.** `log_space` replaces the observed values with their logs and the distribution with a
Normal in log space, and drops the change-of-variables Jacobian. Measured: `log_joint(original)`
exceeds `log_joint(log_space(graph).graph)` by `0.744791` against `Σ log d = 0.744790` on a
3-point fixture. Two graphs describing the same model would report different `Z` and a Bayes
factor between them would be pure Jacobian. Adding the term to the rebuilt graph's `log_joint`
instead would shift every existing `LogSpace` consumer's density by a data-dependent constant —
invisible in every posterior shape and every diagnostic, which is the exact class of silent
change this plan exists to prevent. `LogSpace`'s fields are `(graph, kind, fractional,
skipped)`; there is no slot for it today.

### 0.8 D107: the agreement band is a derived FORM with a measured coefficient

**Ruling.** `D107` is the agreement band between the assembled exact `log Z` and a dense
analytic `log Z`, in nats, of the form

    atol = C · n · eps(dtype) · κ₂(C_marginal)

The **form** is derived from backward stability of the QR route; the **coefficient C** is
measured in Task 3 as the worst observed ratio across the full prior-scale sweep. The registry
prose states which half is which. A fixed absolute tolerance is refused.

**Why.** §9.1 and the sixteen Linux repairs: a scale-blind absolute tolerance is precisely the
fixture that had never been exercised because both sides agreed exactly on one machine.
Measured agreement in this checkout is `5.9e-16` at `std = 0.05`, `8.7e-16` at `std = 1.0` and
`7.8e-12` at `std = 60` — four orders of magnitude of spread, so any single float is either
slack at one end or wrong at the other.

**Linux rule.** C is measured on macOS/Accelerate first and **re-measured under
`docker --platform linux/amd64 -e OPENBLAS_CORETYPE=ZEN`** before registration. If the two
disagree by more than a factor of 4, the plan stops and the owner rules: the candidates are a
wider band with both figures recorded, or a property assertion that does not name a coefficient
at all. `ubuntu-latest` is a heterogeneous pool (three different CPUs measured across three
runs), so **the band must not be tuned to a CPU**.

### 0.9 The prior-scale sweep spans both directions, and its own canary is an assertion

**Ruling.** Every prior-scale sweep covers at least `{0.05, 0.25, 1.0, 4.0, 60.0}`. Task 3
additionally asserts that deleting `prior_log_normaliser` **survives** a sweep narrowed to
`std = 1.0` and **dies** on the full sweep.

**Why.** `-Σ log std` is exactly zero at `std = 1.0`. `docs/evidence-layer-readiness.md` §5
records that removing it fails 7 tests and **none of them** under a narrowed sweep — that is
rheplicant's historical blind spot, reproducible on demand. A sweep lopsided upward from 1.0
tests one side of the term. The 7-and-0 figure is carried from a `record` page and Task 3
**re-measures it** rather than citing it; its value to this plan is the shape of the blind
spot, not the count.

### 0.10 Comparability is an EvaluationReport, not a Refusal

**Ruling.** "Comparing models with different data semantics is refused" is delivered as an
`EvaluationReport` of kind `evidence_comparability` over two `EvidenceResult`s, with
`INAPPLICABLE × ABSTAIN` when the data does not match. Two results are comparable iff
`FingerprintKind.DATA` is absent from `changed_fingerprints(a, b)`. Both sides assert
`meta.fingerprints == run.fingerprints` before comparing.

**Why.** A `Refusal` cannot express this: `Refusal.__post_init__` calls `task_kind(self.task)`,
which raises `TypeError` for anything that is not one of the five Task types, so there is no
Refusal whose subject is a pair of Results. `MODEL_SOURCE` and `GRAPH_STRUCTURE` differ by
construction in any model comparison, so `DATA` is the only slot that can be required. And
nothing in `_envelope` checks that a Result's `meta.fingerprints` equals its `run.fingerprints`,
so a rule reading `meta` on one artifact and `run` on the other would compare two different
bundles while looking symmetric.

### 0.11 The evidence prior-sensitivity report is a new kind, and it reports rather than judges

**Ruling.** The report kind is `evidence_prior_sensitivity`; its quantity is
`d log Z / d log s`, in nats per e-fold of prior width. R4 **reports** it and does not threshold
it. It does not reuse R3's `prior_sensitivity` kind.

**Why.** R3's `prior_sensitivity` is a posterior **mode displacement** in posterior sigmas.
`Z` and a mode are different objects, and §1.4 invariant 3 forbids letting two statistical
objects share a name. The two also disagree in the worst way: centre a prior on the mode and
`mean_offset = 0`, so R3's `shift_sigma = 0` and the report **PASSes** — while changing that
same prior's *width* moves `log Z` by exactly `−Σ log s`. Task 6 pins that disagreement as one
test, so the two reports are held against each other rather than merely coexisting. Not
thresholding it is deliberate: no derivation for a criterion exists yet, and `CRITERION_SHIFT`
is derived from a chain's MCSE of a posterior mean, which has nothing to do with nats of `log Z`.

### 0.12 Every dense-agreement assertion checks the dtype as a consequence

**Ruling.** Each oracle call asserts `jnp.zeros(1).dtype == jnp.float64` at its top, and the
`EvidenceResult` records the dtype context it was computed in.

**Why.** The package does not enable x64 — `grep -rn enable_x64 src/ pyproject.toml` finds
only docstrings telling callers to opt in. Under the default float32 the same assembly agrees
with the dense analytic value only to `2.5e-07` (`-12.626460075378418` against
`-12.626459824251436`), which no evidence band should accept. A requirement worded as "runs
inside `jax.enable_x64(True)` and says so in its name or docstring" is a spelling guard; the
dtype itself is the consequence.

### 0.13 Refused options are refused, not quietly ignored

**Ruling.** R4 refuses `repeat_count` other than `None` and `reconstruct_posterior=True`
through the existing `_option_refusal` seam. `posterior_representation`, `repeat_result_refs`,
`consistency_report_ref` and `residual_component` stay `None`/empty; `standard_error` is
`None`, not `0.0`, and the plan says why in the docstring: none was computed, as against one
measured to be zero.

**Why.** Both fields sit inside the TASK fingerprint slot, so a caller naming them gets a
different digest and reasonably expects different behaviour. Silently ignoring an option that
changed the digest is the worst of the three available behaviours.

### 0.14 The admitted structure class widens in one order, and each widening deletes its own refusal

**Ruling.** (a) whole-graph-exact linear-Gaussian — `classification.nuts == ()` and
`classification.exact.method == "gcr"`; (b) homogeneous per-epoch campaign; (c) all-discrete
enumeration. Anything else is refused with `evidence_residual_integral_required`, naming R5.
Chain evidence is **refused in R4** and its entry condition is written as an executable
checklist in Task 9, not as prose.

**Why.** Each of the four named exact families needs a different oracle, and R4's first gate is
agreement with a dense analytic value. The measured entry conditions: (b) `campaign.epoch_terms`
silently collapses an epoch-varying per-epoch prior to the first epoch's value, which must be
refused before any campaign evidence is assembled (see §0.15); (c) `exact/discrete.py`'s
`marginal_log_likelihood` is `logsumexp` over `log_joint`, which includes the **continuous**
latents' prior densities, so it is `log p(θ, y)` and not `log p(y)` — the exact conflation
§1.4 invariant 3 forbids, and the name already invites it; (d) `chain.py`'s docstring claims six
constants while `TestEachConstantIsWorthSomething` holds four deletion tests over three, so
three constants are unconvicted and the chain family is not ready to be graded.

## What R4 explicitly does not do

- **R5 in any form.** No nested sampling, no BlackJAX, no JAXNS, no `CompiledEvidenceProblem`.
  Where a residual integral is needed R4 refuses and names it.
- **The chain evidence family**, despite §8 R4 listing it. Its entry condition is written as a
  checklist in Task 9; three of its constants are unconvicted today.
- **Connecting the logdet ladder.** It is an island with no consumer outside its own five
  files, its rungs carry heterogeneous certificates (log-error bounds on two, condition numbers
  on two, nothing on two), and it does not share a determinant convention with `Precision`.
  Connecting it is a design decision, not a wiring job.
- **Teaching `campaign.epoch_terms` a heterogeneous per-epoch prior.** R4 refuses it (§0.15).
- **Repairing `EvidenceComponent`'s unconstructible `method: str = ""` default.** R4 supplies
  the value; changing the default is a schema change.
- **Renaming `Graph.evidence_terms`.** The field holds graph-level *likelihood* factors, which
  is the same confusion the `evidence → marginal` rename existed to end — but renaming a
  graph-level field is not R4's business. Recorded here so the next reader does not rediscover it.
- **Correlated / non-Gaussian observed nodes.** Note the asymmetry R3's close-out did not draw:
  `predictive_noise_unsupported` is about **predictive generation**. For **evidence**,
  correlated Gaussian noise reads through `Precision` with no special case, so the evidence
  coverage domain is not the predictive one. R4 admits correlated Gaussian noise **only** where
  a dense oracle exists for it; where none does, it refuses rather than shipping ungated.
