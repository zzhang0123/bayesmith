## 一、适配器的形态,以及三个不是任选的决定

### `to_graph` 交出的图永远是三层

一个 `sample` 节点 per 声明的 latent,一个 `det` 节点装**整个**前向模型,一个
`observe` 节点装似然。前向模型对 bayesmith **刻意不透明**——它是一个
Pipeline,缝的职责是把它**呈上去**,不是把它拆开。bayesmith 需要知道的**关于**
它的事情是被**声明**的:`linear_in` 点名 `linear=True` 的 latent,而那个声明在
被利用之前会在对面被检查。

三层的形状本身被钉住(`test_the_nodes_are_the_latents_plus_two_internal_ones`),
因为 G7 的约定是内部节点名不得进入后验的键空间,而这条约定最便宜的腐烂方式,
就是适配器长出第四个没人注意的节点。

### σ 问的是噪声模型自己,不是从它的字段重算

`observe` 的分布是 `Normal(mu, noise.std(mu))`——一行,同时覆盖
`HomoscedasticNoise` 与 `RadiometerNoise`,并且**没有第二处**写下 radiometer 的
floor 与绝对值。第二份拼写会静默地过期:两种读法都有限、形状都对。

这也把 D10 子裁决 (2) 的边界画清楚了:**生成侧不经过这里**。
`RadiometerNoise.realise` 是乘性的 `d(1+fw)`、不取绝对值、不带 floor,与
`std` 在预测过零处符号不同;让 `dist_fn` 兼任生成器就是静默换模型。

### `translate` 的三个家族,三种下场

- `AffinityRefused` → `LinearityRefused`,**带着同一批数字**(`errors` /
  `rtol` / `failed`,外加 bayesmith 独有的 `weighted` / `weighted_rtol`)。
  这是 G11 存在的全部理由,从本侧断言。
- 其余 `BayesmithError` → `SeamRefusal`(`ParameterSpaceError` 的子类),
  原文引用、site 点名、原异常留作 `__cause__`。
- `NotGaussian` / `NotLogLinear` → **捕获不外抛**。它们是答案不是错误:调用方
  问「这里有没有这一类精确路径」是为了分支。

**yield 一个 `Seam` 记录,而不是纯吞掉。** 计划把 `translate` 的形态定死为
「上下文管理器,捕获不外抛」,没说交出什么。纯吞掉的语义是:块在抛出处结束,
后面的语句不执行——于是调用方要读的那个变量**从来没被赋值**。所以裁决交出一个
`Seam`,`seam.blameless` 是那个判决或 `None`。这是把一条**已定的语义**变成可用
的语义,不是改判据;两侧都被钉住(`test_a_blameless_verdict_is_caught_and_reported_rather_than_raised`
与 `test_a_block_that_finishes_reports_no_verdict`),否则一个恒为「已拒绝」的
`Seam` 会让前一条永远通过。

### 预验证:凡图缝会抹掉证据的拒绝,住在 `to_graph` 之前

首例是计划点名的 σ 轴歧义。**过了这一点,σ 已经被广播进一个分布,歧义已经由
尾轴对齐静默地判决完毕**,没有任何下游能分辨。同一条规则下另外十条拒绝也在
这里:`FlaggedNoise`(σ=inf 没有图节点能承载,G1 未落)、`scope=per_epoch`
(Plate,Wave D)、`scope=linked`(G3)、`joint_prior`(G13 的 factor site)、
latent 取了内部节点名、latent 没有任何先验、`priors=` 指向不存在的 latent、
`priors=` 与声明同时存在、复 latent 的先验不是 `ComplexNormal`、复数 `observed`、
`observed` 形状不等。

**复 latent 的先验不做静默提升**,这一条值得单独说:把 `Normal(loc, scale)`
提升成 `ComplexNormal(loc, scale)` 需要决定 `scale` 是什么意思,而对面的约定是
**每一半携带 `scale**2`**——所以静默提升会把调用方声明的先验方差**翻倍**,并把
那个 √2 当成物理结果报出去。拒绝,并在消息里写明为什么不替你选。

## 二、§四式五节记录

### (1) fixture

`tests/seam/seam_models.py` 一处写下全部数值词汇(两个天空幅度、增益、网格),
`conftest.py` 建 fixture,例子各自声明不同的 `ParameterSpace`。**刻意如此**:
本程序上一个会话付过学费——一个图 fixture 漏了加性 offset,与手造孪生体差 0.16,
读起来完全像求解器 bug。每个 fixture 的数学只写一次。

复数例的设计矩阵是**复**的,所以虚部**不是**零空间方向:一个丢掉虚部的解会
可见地错,而不只是「未被约束」。这一条有专门的断言
(`test_the_imaginary_half_is_constrained_and_not_merely_carried`),因为一个
虚部为零空间的 fixture 会让稠密比对全绿而对半个 latent 一句话都没说。

### (2) 数值一致

**确定性层的参照是稠密正规方程**,在 NumPy 里从 block 自己的 `forward` 逐列
建 `A`、显式求逆——不走 CG、不走 tree map、不知道求解器如何表示任何东西。
判据 `rtol < 1e-12`。实测(x64):

| 例 | 实测最大相对偏差 |
|---|---|
| 1 线性 wiener | **4.17e-16** |
| 2 复数 alm 均值 | **8.30e-16** |
| 3 先验覆盖 | 同例 1 路径,< 1e-12 |
| 5 GLS 不动点(再解一次) | **4.04e-16** |
| 5 GLS 不动点对稠密参照 | < 1e-12 |
| 6 `plan.estimate` 全共轭整图 | < 1e-12 |

**抽样层**对同一个稠密后验比矩:400 次独立抽样,均值逐坐标 |z| < 4,协方差按
**相关系数尺度**(`|Ĉ-C| / sqrt(C_ii C_jj)`)< 0.25。

> **协方差为什么不能按相对误差比。** 第一版这么写,实测报 `inf`:近零的非对角
> 元让相对比较在一个统计上等于零的差上发散。按 `sqrt(C_ii C_jj)` 归一才是关于
> 代码的判据,而不是关于哪个非对角元恰好接近零的判据。

例 7(标量路径)与例 8(vmap 路径)对**同一个**稠密后验比,所以说的是「两条路
一个分布」,而不是各自与各自的参照一致。例 8 另有一条 `jax.eval_shape` 的断言:
vmap 可 trace 是硬约束,而 `eval_shape` 抽象地编译,不产出任何数组,所以它断言
的**正是可 trace 性**——校验与翻译都在 Python 侧、trace 之外。

### (3) 拒绝一致

`tests/inference/test_graph_bridge.py`(36 例)钉住上面列的每一条预验证拒绝与
`translate` 的三个家族。两条与「守卫还能不能失败」直接相关的:

- **`SeamRefusal` 的 pickle 往返**。必填关键字会破坏 Python 默认的 `cls(*args)`
  重建,而 pytest-xdist **跨 worker 序列化异常**——症状会以「缺少参数的
  TypeError」出现在离现场很远的地方,顶掉本该被报告的那个错误。与 bayesmith
  给它三个载荷类做的修复同一形状。
- **σ 轴歧义那条,原本 skip 了**。共享的 template state 是 8×4,不是方阵,所以
  长度 n 的 σ 只有一种读法,那条拒绝**根本无法被触发**。第一版写成
  `pytest.skip(...)`,而「一个 skip 顶替着最基础的那条预验证」读起来就是 pass。
  改成在测试里**就地造一个方阵 state**,断言 `prediction.shape == (8, 8)`,再
  触发拒绝。

## 三、四条实测发现,其中一条修正了一行已拍板的裁决

### (a) D19 的退化比登记簿写的**早一层**

D19 写的是:零先验中心 + `RadiometerNoise(floor=0)` 时 `iterative_gls` 的起点
σ=0、**首解退化**。实测 2026-08-27:退化根本轮不到 `iterative_gls`——
`linear_operator` 自己的**线性化点**就取在先验中心,于是 σ=0,
`check_linearity` 的噪声可用性检查抛 `StructureError`,消息点名「该节点的 scale
表达式」而不是任何 `linear_in` 声明。

**这不推翻 D19,它收紧 D19。** 裁决(数据锚定起步)不变,但 Wave B 的实现范围
要**同时**覆盖 block 的 `at` 与 GLS 的起点,否则修好了循环、块还是造不出来。
本批次把它编码成 `tests/seam/test_p1_ten_examples.py` 里一条
`@pytest.mark.xfail(strict=True)` 的回归 fixture,理由里写明这段:**strict**,
所以 Wave B 落地那天它会因为「意外地绿」而红,逼着把标记摘掉。

### (b) 一个乘性进入的 gain **没有** log 路径

例 9 原本用普通的 `GainOperator`,`log_space` 拒绝了。原因不是噪声:
`log(mu)` 对 `gain` **不是**仿射的(它对 `log(gain)` 才是),而 block 的 offset
是 `x=0` 处的预测,`log(0) = -inf`。所以例 9 改用一个**以 log 为参数**的 gain
(`seam_models.LogGainOperator`,`data * exp(log_gain)`)——这也正是仪器模型里
增益的自然声明方式。**改的是模型,不是判据**:那条拒绝是对的,它注意到了这个
模型没有 log 路径。

### (c) 「先验更紧则答案更紧」这条断言,第一版为**物理**而红

例 3 要证明 `priors=` 真的在起作用,写法是两次求解只差 `prior_std=`。第一版取
5.0 与 0.01,实测**几乎没动**(0.672 vs 0.701)。算一下就明白:每个 gain 乘的
天空是 120、跨四个频道、σ=0.5,所以似然对单个 gain 的精度约 **2.3e5**,而
`prior_std=0.01` 只带来 1e4——先验被票数压倒。改用 1e-4(精度 1e8)才让这条
断言问的是「先验有没有被丢掉」。**一条为错误理由而红的测试,和一条不会红的
测试一样没用。**

### (d) 线性检查的先验抽点会把预测推过零

例 5 的第一版用 `RadiometerNoise(floor=0)`,在**非**零中心的先验下也被拒:
`check_linearity` 的 at 点是从先验抽的,`Normal(1.5, 5)` 够宽到让预测接近零,
于是无 floor 的 radiometer σ 为零、协方差奇异。加 floor 是那条消息自己给的
补救,也是物理上正确的做法。记在这里,是因为下一波会在更宽的先验下反复遇到它。

## 四、两个 x64 会话,以及一句被证伪的话

`tests/seam/` 的确定性层做的是**机器精度**声明,float32 承载不了,而
`jax_enable_x64` 是进程全局的。所以本批次新增了**第二个 x64 门控目录**与它的
子进程驱动 `tests/test_seam_session.py`,与 `tests/evidence/` 的做法逐条同构。

**这让 `tests/test_evidence_session.py` 里的一句话变成假的**,原文写着
`tests/evidence/` 是全套里**唯一**带 x64 收集门的目录,并**由此推出**迁移末期
「两个会话合并」等于「删掉这个文件和那个 conftest」。已在那个文件里就地更正,
更正与它改变的推理放在一起,并写明真正要紧的区别:**证据层的 x64 需求随层
离开,适配器的不会**——适配器是本包**留下**的东西,不是它交出去的东西。
