## 一、两个函数,以及为什么它们必须相邻

`propagate_covariance` 线性化,`push_forward` 抽样。**成对存在就是内容**:
两者在映射相对后验宽度是仿射时**完全一致**,在不是时**必然分歧**,而一个带着
「我的预测的误差棒是多少」来的读者,无论知不知道,都正在这两者之间做选择。

守卫把这句话写成了两条测试:仿射图上两者一致(4000 抽,rtol 0.06),
`exp(theta_0)` 的图上两者**必须**分歧(> 10%)。**没有后者,两个偷偷是同一个
函数的实现会通过前者。**

## 二、本批次最重要的一处更正:观测节点交出的是 `loc`,不是它的值

**第一版是错的,而抓住它的不是它自己那条断言。**

`evaluate` 给一个被观测节点的值是**数据**——条件化就是这个意思——而数据**对
参数没有任何依赖**。所以把「节点的值」往前推,报出的雅可比恒为零、误差棒恒为
零,在每一个元素上、对任何模型都如此:有限、形状正确,并且是**可能范围内最自信
的错答案**。

**它是怎么被抓住的**:`test_the_default_node_is_the_single_observed_one` 那条
断言「`node=None` 与 `node="d"` 给同一个答案」——它**通过了**,因为两边都是零。
真正报警的是另一条测试里 `push_forward` 与 `predict` 的对比给出了两个相同的
~1e-5,而它们本该差一个 σ。

处置:`_predicted()` 一处集中——被观测节点交出它的 `loc`(即预测),
deterministic 节点交出它的值,**latent 被拒绝**(它自己的不确定度正是协方差
已经装着的东西,`FlatMatrix.block(name)` 就是那个子矩阵)。

### 顺带查明的一件事,写下来因为它出人意料

`Predictive` 跑在一个 `obs=` 已经写死的模型上,返回的是**观测节点的数据**,
每一抽逐比特相同。实测:3000 抽的 `ptp` **恰为 0**,而同一批抽样下预测本身的
标准差是 **0.26**。这是 NumPyro 的正确行为,但**不是**「后验预测」通常的意思。

两个后果都落地了:
* `bridge.predict` 的 docstring 被更正,明说被条件化的节点回来的是数据,并指向
  `push_forward`(无噪声预测)与 `observed={}`(真正的预测分布);
* `to_numpyro` 交出的模型长出 `observed=` 参数,`{}` 即「什么都不条件化」——
  这正是计划那一行写的 `model(observed=None)` 约定。默认 `None` 保持今天的行为,
  所以**既有调用方一行未改**。

> 用 `ptp` 而不是 `std` 断言「每一抽都相同」:float32 下对 3000 个**完全相同**的
> 值求 `std`,numpy 自己的累加仍报 ~5e-5——一个读起来像「几乎不变」的数字,而
> 待证的是「完全相同」。

## 三、§四式五节记录

### (1) fixture

`tests/exact/test_uncertainty_bridge.py` 内的 `affine_graph()` 与
`curved_graph()`。两处刻意的选择,**都是第二轮才改对的**(见 §四):

* **设计矩阵两列刻意相关**:`linspace(0.2, 2.0)` 不求和为零,于是 `X^T X`
  非对角,参数协方差有真正的非对角元。用对称的 `linspace(-1, 1)` 时两列正交、
  协方差近乎对角,**一个干脆忽略参数相关的 delta method 会与正确实现一致到
  任何容差以内**。
* **先验中心既不是零也不是真值**(`(1.3, -0.7)`,真值 `(2.0, -1.0)`):用
  `Normal(0, 10)` 时声明的中心**就是**原点,于是「`init_to_declared` 返回零」
  与「返回声明」无法区分。

### (2) 数值一致

| 断言 | oracle | 结果 |
|---|---|---|
| delta method | numpy 直接由设计矩阵形成的 `sqrt(diag(X Σ Xᵀ))`,**不共享任何代码** | rtol 1e-12 |
| 同上,对角化版本 | 同上 | 与正确值差 **> 5%**(fixture 非退化的证明) |
| 两法在仿射图上 | 互为 oracle | 4000 抽,rtol 0.06 |
| 两法在 `exp` 图上 | 同上 | **必须**差 > 10% |
| `push_forward(node="d")` vs `node="mu")` | 互为 oracle | 逐元素相等(观测节点交出 loc) |
| `predict` 的被观测节点 | — | `ptp == 0`(逐比特恒定) |
| `observed={}` 的预测分布 | `sqrt(quiet² + σ²)` | rtol 0.08 |
| `init_to_declared` 起点 | `prior_environment` | 逐元素相等,且**既非零也非真值** |
| NUTS 首抽(0 warmup, 1 draw) | 声明点 | atol 1e-6 |

### (3) 拒绝一致

| 拒绝 | 类 | 理由 |
|---|---|---|
| `kind != "covariance"` | `StructureError` | 精度矩阵与协方差**同形**,放错位置错的是「所有东西的平方」,下游无从察觉 |
| 块名不是本图 latent | `StructureError` | 雅可比的列会对着另一组参数取 |
| 每 latent 的**尺寸**与矩阵的 span 不合 | `StructureError` | 见下 |
| 目标节点是 latent | `StructureError` | 它自己的不确定度就是协方差本身 |
| 多个观测节点且未指定 `node=` | `StructureError` | 猜一个是静默的 |
| 抽样栈转置 / 缺 latent / 抽数不一致 | `StructureError` | 与 `predict` 同一条守卫、同一次实测 |

**尺寸那一条是 rheplicant 做不到而这里做得到的**:它的祖先只能比 pytree
structure,而它自己的 docstring 记着漏掉了什么——dict 的 treedef **只编码键名**,
所以「latent 名字相同、每个 latent 形状不同」的两个空间会通过检查,给出有限的、
错的误差棒。`FlatMatrix` 带着 `spans`,所以这里尺寸也被检查,那个洞不随迁移过来。

### (4) 独立 oracle

delta method 对**稠密构造**:`sqrt(diag(X Σ Xᵀ))` 由 numpy 直接从设计矩阵形成,
不经 `jacfwd`、不经图、不经 `FlatMatrix`。雅可比若转置、einsum 若缩错下标,是
这条断言会发现。

### (5) 有意的差异

* **不新增 `predict_from_samples` 这个名字**。`bridge.predict` 已是它,而
  「同一件事两个名字」正是本计划反复点名的形状。差异写进了 `predict` 的
  docstring 而不是一个别名。
* **`observed=` 的默认值保持 `None` = 用节点自己的数据**,而不是 rheplicant 那边
  「`None` 即不条件化」的读法。理由是兼容:反过来会翻转每一个既有调用方的行为,
  而本批次没有任何消费者需要那个默认。三种取值的语义写在 `to_numpyro` 的
  docstring 表里。
