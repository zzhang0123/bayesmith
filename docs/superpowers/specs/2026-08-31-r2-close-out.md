## ESTIMATOR 失效行裁决（§0.7 vs Task 7.1 措辞不一致）

`ArtifactKind.ESTIMATOR` 的失效矩阵行，C 实现成「**与 RESULT 同**」= 对
`model_source`/`graph_structure`/`data`/`task`/`compilation` 五槽都敏感
（`_MODEL_AND_INPUTS + COMPILATION`，见 `artifacts/identity.py` 的 `_DEFAULT_POLICY`）。

计划的 §0.7 写「对 model/graph/data/task 敏感，**与 RESULT 同**」，Task 7.1 写「按
model/graph/data/task 失效」——两处措辞在 **compilation** 这一槽上不一致。C 取了 §0.7 的
「与 RESULT 同」。

语义上估计器权重不依赖编译（block partition/tol/fallback），所以 4 槽更准；但「与 RESULT 同」
是**过保守、安全向**（compilation 变了就重训，绝不会静默用错权重）。**本 close-out 裁决：保持
「与 RESULT 同」（5 槽，安全向），不改**。测试
`test_amortized_encoding.py::test_the_estimator_row_invalidates_on_model_graph_data_and_task`
已把这个行为钉死：5 敏感（MODEL_SOURCE / GRAPH_STRUCTURE / DATA / TASK / COMPILATION）→
`affected=True`，2 不敏感（EVALUATION / ENVIRONMENT）→ `affected=False`。
