## 一、谱隙表(裁决所要求的那张)

`docs/probes/probe_13_d9_precision_policy.py`。两分量幂律

```
mu = exp(a1) (nu/nu0)^-b  +  exp(a2) (nu/nu0)^-(b + delta)
```

`delta → 0` 时两个分量合一,四个参数塌成两个,于是 `delta` 把**真实**条件数
连续拉过十个量级。两个族:**A** 带一个自由总标度(与两个幅度精确退化,故任何
`delta` 下 nullity ≥ 1),**B** 标度固定(大 `delta` 时模型**是**可辨识的,于是
这一族也考验**误报**方向)。

对每个模型取 float64 与 float32 的列归一化谱,再问每个候选容差
(`1e-8`、`1e-7`、`1e-6`、`1e-5`、`1e-4`、float32 的 `sqrt(eps)`=3.45e-4)
能否复现 float64 的判决。

### 族 B 的关键几行(完整表在探针输出里)

| delta | float64 `s_min/s_max` | float64 nullity | float32 `s_min/s_max` |
|---|---|---|---|
| 1e-1 | 5.135e-06 | 0 | 5.162e-06 |
| **1e-2** | **5.204e-08** | **0** | **1.136e-07** |
| **1e-3** | **5.211e-10** | **1** | **7.243e-08** |
| 1e-4 | 5.211e-12 | 1 | 1.146e-07 |
| 1e-5 | 5.213e-14 | 1 | 9.653e-08 |
| 1e-6 | 5.486e-16 | 1 | 1.059e-07 |
| 0 | 1.112e-16 | 1 | 4.926e-08 |

**这张表说的不是「切点难放」,是被切的那个量没了。** float64 的最小奇异值一路
跟着模型(5.1e-6 → 1.1e-16,十个量级);float32 的从 `delta = 1e-2` 起就停在
~1e-7,并且**非单调**(1.14e-7 → 7.2e-8 → 1.15e-7 → 9.7e-8 → 1.06e-7)——那不是
信号,是舍入噪声。

加粗的两行是判决**发生变化**的地方:float64 把它们分开两个量级(5.2e-8 对
5.2e-10),float32 给出 1.14e-7 与 7.2e-8——**顺序甚至是反的**。没有任何切点能
跟上它们。

### 逐候选的结果

**没有一个候选复现全部判决。** 最好的 `1e-6` 在 20 个模型里错 2 个;`1e-8`
错 18 个;其余错 4 到 6 个。

### 类比在哪里断掉

D9 读成 (b) 的理由是「bayesmith 已经为 fisher 天花板从 dtype 推导过」。那条类比
不成立,而说清楚为什么很重要:

* **条件数天花板**是「算术还剩几位数」的陈述,`1/sqrt(eps)` 是它的定义,与模型
  无关——所以它当然从 dtype 推导。
* **秩的切点**是「谱从哪里开始不再描述模型」的陈述。在 float32 里,谱**在任何
  切点之上**就已经不描述模型了,所以没有 dtype 能推导出它。

### rheplicant 早就写过同一句话

`src/rheplicant/inference/identifiability.py` 的模块 docstring:

> A per-precision retune of ``rtol`` would therefore recover *this* model. It
> would not recover one a few decades worse conditioned, which float64 still
> resolves with eight decades to spare. **Forcing float64 is what lets one
> default be right for both.**

D9 那一行的 (b) 建议没有读到这一段。本页的探针是同一结论的**独立复现**,并且
把它从「一个模型」扩到了**一个族**。

## 二、于是取 (a),并实测它失败得响亮

D9 对 (a) 的顾虑逐字写着:「必须上下文内重建图并 cast 摄入数组(仅包调用是 B2
定罪的 no-op)」。这是对的,但它**不是静默的**:

| 做法 | 结果 |
|---|---|
| 图在 x64 **外**建,只把**调用**包进 x64 | `GraphError`:「the joint Jacobian came back float32 even though the ambient precision is float64…」——**指名拒绝**,并说出补救(在块内建图) |
| 图在 x64 **内**建 | 正确判决,`s_min/s_max = 8.0e-17`,nullity 1 |

所以 (a) 的「适配器长期义务」是一条**有守卫的**义务,不是记忆力。这改变了 D9
原文对 (a) 的估价,写在这里。

**rheplicant 今天怎么做的**,作为 (a) 可行性的现成证据:它的 `identifiability`
与 `prior_sensitivity` 各自用 `_in_float64()` 内部开 x64,并在里面
`jnp.asarray(..., dtype=jnp.float64)` 掉摄入的值。这正是 (a) 的机制,只是位置在
诊断里而不在适配器里。**bayesmith 不采这个位置**(它的规矩是 `src/` 从不开 x64
上下文,理由是那是进程级全局状态,且 rheplicant 自己的 docstring 也承认它不是
线程安全的)——但这条差异现在是**记下来的**,而不是碰巧的。

## 三、找反证时查出的两个洞(本批次真正改的代码)

`refuse_ambient_float32` 有**三**个调用方,而 D9 那一行只点了两个
(「同门管 identifiability 与 prior_sensitivity」)。第三个是
`JeffreysPrior.information`。逐个问「给它一张会截断的图,它拒绝吗」:

### 洞一:`JeffreysPrior.information` 根本没有图侧守卫

实测,在**精确退化**的 `doubled_graph` 上:

| 图在哪里建 | 半对数行列式 |
|---|---|
| x64 **内** | **-338.05**(诚实的零密度) |
| x64 **外**,调用在内 | **-27.52**(一个说得通的有限数) |

**310 nat**,静默,而且在 NUTS 会取指数的那一项上。

**特征值地板一直在工作**——它把低于阈值的特征值替换成 `jnp.finfo(dtype).tiny`,
而 `log(tiny)` 在 float64 是 **-708**、在 float32 是 **-87**。所以同一个奇异矩阵
仅因为算术的 dtype 不同就差约 310 nat。这正是 `JeffreysPrior` 模块 docstring 里
那句「**A determinant that came back finite is not a guard**」描述的故障,只是
从一条地板看不见的路进来。

处置:`information` 调用 `refuse_single_precision(dense_operator(block), ...)`,
与 `identifiability` 守卫它的雅可比是同一条。

### 洞二:`prior_sensitivity` 的守卫钉在一个会自动提升的标量上

它原本是 `refuse_single_precision(neg_log_posterior(x0), doing="the log-posterior")`。
`neg_log_posterior` 累加进一个 `jnp.zeros((), dtype=x.dtype)`(`x0` 在 x64 下是
float64),又加上先验的 float64 二次型——**所以无论图做了什么,它都回来 float64**。
守卫形同虚设。

实测后果:一张会截断的图**穿过**这条守卫,三十行之后以 `ConvergenceError` 失败,
消息里把 float32 列为**三个候选成因之一**,把诊断留给读者。

处置:改守**观测节点的预测**(`gaussian_parts` 的 loc)——那是 `identifiability`
取雅可比的对象,也是截断真正所在的地方。

### 这两个洞是被**普查**找到的,不是被清单

`test_every_diagnostic_that_refuses_float32_refuses_a_truncating_graph_too`
对每个入口问**同一个问题**,而不是列一张名单。D9 那一行点了两个而不是三个,正是
手工列名单的产物。

## 四、§四式五节记录

### (1) fixture

`tests/diagnose/models.py::two_component(delta, dtype, free_scale=)`——**新增,
且探针与测试共用它**。探针把仓根加进 `sys.path` 去 import 它,而不是自己带一份:
「把模型写两遍」是比较悄悄变成比较两个模型的方式,本仓已为此付过学费。

该 fixture 有**自己的** `D9_NU0` / `D9_N_FREQ` / `D9_N_TIME`,不复用模块里的
`NU0` / `N_FREQ` / `N_TIME`:它回答的是一个关于**精度**的问题,把尺寸耦合到别的
fixture 上,会让那边一次重调在这边悄悄移动一个测量。

### (2) 数值一致

见 §一 的表。判据是**判决是否复现**,不是数字是否相等——因为争点就是判决。

比值而非原始值、量级而非位数:这条断言是关于**数量级**的,钉住位数会把它变成
一条关于 JAX 版本的测试。

### (3) 拒绝一致

| 拒绝 | 谁 | 状态 |
|---|---|---|
| ambient float32 | identifiability / prior_sensitivity / JeffreysPrior | **三个都在**(本批次前也是三个) |
| 图自身截断 | identifiability | 原有 |
| 图自身截断 | prior_sensitivity | **修好**(原先钉在会提升的标量上) |
| 图自身截断 | JeffreysPrior.information | **新增** |

### (4) 独立 oracle

float64 的判决就是 float32 的 oracle,而两者只共享「模型」这一件事——同一个
fixture 在两个精度下各建一次。这不是两个实现的比较,是同一个实现在两种算术下的
比较,而那正是本项要判的东西。

### (5) 有意的差异

* **bayesmith 不学 rheplicant 内部开 x64**(§二)。差异与理由都记下来了。
* **条件数天花板那一半没有做**。D9 还有第二项功课:`parameter_covariance` 切换后
  新获 `1/√eps` 天花板拒绝,要逐 fixture 冒烟。那些消费者要到 Wave A 切
  `uncertainty` 才出现,**而且在 (a) 下它们遇到的是 float64 的天花板 6.71e7,
  不是 float32 的 2.90e3**——与 D9 原文设想的情形不同。见 §七。
