## 〇、三件都落在 `sample_factors` 上,而这是计划自己的一条法则

计划 v2→v3 的第一条修正逐字写着:v2 以为 bayesmith 没有多块执行器,**是假的**;
另起炉灶「将在 bayesmith 内部违反本计划自己的一份实现法则」。所以三件都是**加在
既有执行器上**,一个新的执行循环也没有。

`estimate_factors` 是唯一新写的循环,而它循环的是**求解**不是抽样,与
`sample_factors` 的 sweep 共享块的选择、源图的选择(`_source_of`)与
`unchecked_operator` 的调用形态——不共享的只有「解还是抽」那一行(D36)。

## 一、(iii) `declared_partition`:探测数实测为 0,而拒绝的是簿记

**探测数是数出来的**:装一个 spy 在 `check_linearity` 上跑一次
`declared_partition`,**0 次**。这与 `factor_partition` 的差别不是参数,是路径。

**它接受一个 `factor_partition` 会拒绝的块**:`cubic_tail` 在派生路径上整个掉进
NUTS,声明成 `"gcr"` 就是 `"gcr"`。**块的 `reason` 里写着 `declared` 与
`not probed`**,所以一张事后读到的 plan 不会被当成派生的——一个 plan 是「量到了
什么」的记录,而这里什么也没量。

**仍然拒绝的六条,全部是簿记而不是建模主张**(D34):名字不是 latent、一个 latent
在两个块里、空块、未知方法、第二个 `nuts` 块、以及**不完整覆盖**。最后一条是本项
的裁决点:`factor_partition` 会把剩下的扫进 NUTS 块,声明入口照做等于**替调用方
作一个他没作的决定**,而一个漏掉的 latent 与一个被判给 NUTS 的 latent 在返回的
plan 里长得一模一样。

## 二、(i) `on_sweep`:报什么,以及为什么在 NUTS 路径上**拒绝**

`SweepReport` 五个字段:`index` / `warmup` / `values` / `log_joint` / `residuals`。

* **χ² 用 `log_joint` 拼写。** D14 写的是「联合 χ² 轨迹」。高斯模型下
  `-2 log_joint` **就是** χ²,差一个不随轨迹动的常数;非高斯模型下只有前者存在。
  一个字段两种模型都成立,好过两个字段其中一个有时无意义。
* **`residuals` 是本来就被丢掉的东西。** `gcr_sample` 一直返回逐块相对 CG 残差,
  而这个执行器写的是 `drawn, _ =`。不是精度(乘以块的 `kappa` 才是),但它是唯一
  的逐解数字。

**NUTS 余项存在时拒绝,理由是实测**(D35):那时 sweep 变成 `HMCGibbs` 的
`gibbs_fn`,而 numpyro **追踪**它。计数:两块 plan 跑 **5** 个 sweep,`gcr_sample`
在 Python 层被调用 **2** 次(等于块数,即一次追踪),而不是 10 次。所以一个 Python
回调只在追踪期触发一次,交回一个**从未发生过的** sweep,里面的值形状与 dtype 全对。

**拒绝的对象是钩子,不是混合 plan**——混合 plan 一直能跑,兄弟测试钉住这一条。
没有这条兄弟断言,一个把混合 plan 整个拒掉的实现同样会绿。

## 三、(ii) `estimate_factors`:D14 点名的那个缺口,以及为什么 G2 必须先做

`InferencePlan.estimate` 对**不是处处精确**的图直接拒绝,而那是**普通情况**——
分区存在的理由就是它。本项的答案:精确块解出条件均值,余项交给 `fit`(G2)。

**同一个目标。** 高斯条件的**均值即众数**,所以 Wiener sweep 是对联合密度的精确
坐标上升;`fit` 上升的是**同一个**联合。所以 `history` 是一条轨迹,不是两条拼起来的。

**三种块一起估**(headline):`gcr` + `log-gcr` + `nuts` 一个 plan,实测

| latent | 估出 | 模拟真值 | 由谁估 |
|---|---|---|---|
| `log_gain` | **0.469** | 0.470 | log 空间的 Wiener 解 |
| `centre` | **0.1033** | 0.100 | 联合上的梯度步 |

两条走的是**不同机器**,所以两条都点名——一条断言分不出它们。
**反空洞子句**:同一张图交给 `_refuse_unless_whole_graph_exact` 会被拒,所以上面
那条不是在重复一条本来就能走的路。

## 四、G12:语义是既有的,而**触发条件与计划的读法差一层**

计划 v3 的第二条修正说:「冻结在块当前值」的语义在 rebuild 分支**已经存在**
(`precision_at(source, current)`,current 含块自身最新值)。**对**——但只在
rebuild 分支被走到时。

**实测**:`_sigma_needs_rebuild` 问的是「有没有**块外**的 latent 到达观测节点」。
于是

| plan 形态 | 分支 | sigma 冻在 |
|---|---|---|
| 两块以上,sigma 依赖预测 | **rebuild** | 块自身**当前值** ← G12 要的那个 |
| **整图一块** | hoist | **先验中心** |

单 latent radiometer 的 `_sigma_needs_rebuild` 返回 **False**(实测)。所以
「声明成 gcr 就得到冻结在当前值」这句话**不对**,要加一句条件——本页第一版的
docstring 就是那么写的,由这次测量改掉。

**两条都是近似,都不是正确性证明。** 转移核是历史依赖的,产生的链一般不对声明的
后验不变。注记照 D8 写成「近似声明:历史依赖核,非严格不变」。

**`gcr+mh` 构造期拒绝,且给它自己的消息**——不是那条通用的「未知方法」。理由:
一个伸手去要 `gcr+mh` 的调用方心里有一个真实的模型,他需要的是**论证**而不是一张
词汇表。消息里写出那条论证:`_mh_step` 的正确性论证是**单块**的,而它由一个
**签名**执行(`_precision_at` 收不到 `x`,所以冻结的提议无法被静默地在移动点上求值);
逐块逐 sweep 的 Metropolis 是另一个论证,而它还没被写下来。三条出路各自点名。

**G12 的语义可达性是量出来的**:spy 在 `precision_at` 上,两块声明 plan 跑 4 个
sweep → **8 次**调用,每次收到的 values **都含两个 latent**,且这些点**在动**
(hoist 会重复同一个点)。

## 五、两次测量各自改掉了一条测试,不是代码

1. **`collinear_pair` 上的交替不收敛,而它看起来收敛了。** 我原本写的是「交替达到
   联合解」。实测(x64,图建在块内):

   | sweeps | 与联合解的最大绝对误差 | 联合对数密度自 -12.051890 移动 |
   |---|---|---|
   | 5 | 1.0195 | 0.000931 |
   | 50 | 0.9745 | 0.010900 |
   | 300 | **0.7583** | 0.052515 |

   **全程单调**。第一个 sweep 把联合从 **-476.54** 拉到 **-12.05**,之后 300 个
   sweep 一共再移动五百分之一 nat,而参数离众数还有四分之三个单位。
   **每一个调用方能看的数字都说收敛了。** 于是:
   「达到联合解」那条 oracle 换到**正交**模型(`two_linear_latents`,5 个 sweep 后
   误差 **4.4e-16**),`collinear_pair` 变成一条**反例**,把它自己 docstring 里
   记着的那个危险量化出来。**补救是分区,不是 sweep 数**:同一个模型一块一 sweep
   就解完。

2. **图建在 `enable_x64` 块外面**,于是 float32 的常数被带进一个 float64 的解,
   上表每个数字都不一样。这与 `uncertainty` 那批从另一头撞到的是同一条
   ——加宽是**算术所处上下文**的性质。fixture 移进块内之后重测,数字才是上表。

### W8 是本批唯一的真洞,而它的形状正是本程序最常付学费的那个

变异把每个块**自身的当前值**换成它的**先验中心**放进重建的精度里——**恰好是 G12
要的那件事的反面**。测试**通过了**。

它当时的三条断言:8 次调用、每次都带两个 latent、这些点在动。**三条在变异下全部
仍然为真**,因为**另一个** latent 还在动。

「fixture 分不出『对』与『貌似对』」——本程序反复付学费的那一条,以它最纯的形式
出现了一次,而唯一会有人去看的理由是一条变异幸存了。

修好的断言是本来就该在那里的那条:调用按 block a / block b 交替,所以第 k 个 sweep
里 block a 那次必须看到 `a` = 它自己在第 k-1 个 sweep 的抽样,block b 那次必须看到
`a` = 第 k 个 sweep 刚抽的、`b` = 它自己第 k-1 个的。**对着返回的链核对**,不是对着
一个记下来的数字。

**修补先提交再重跑**(五行协议第 (0) 条的第二半)。

登记的期望是 `test_a_two_block_sweep_reaches_the_joint_wiener_answer`;实际红的是
`test_the_joint_never_decreases_across_sweeps`。两条都是本批写的,而**后者的
