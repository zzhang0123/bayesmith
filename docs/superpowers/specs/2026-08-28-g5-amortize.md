## 〇、缝在哪里是**读出来的**,不是划出来的

`NoiseModel.realise`」,而这句话的字面读法**在本包里做不到**:bayesmith 没有
`NoiseModel`,也不能有(§〇「零射电天文」),两仓的依赖边是单向的。所以「迁移」

**但这一条不必判断,只要读签名。** 上游 `inference/npe.py` 四件公开件:

|---|---|---|

## 一、fixture

一维线性高斯,**闭式后验写在 numpy 里**:

```
theta ~ Normal(0.5, 2.0);  x = A theta + Normal(0, 0.4),  A = linspace(0.5, 1.5, 8)
precision = A·A / 0.4² + 1/2.0² = 55.61   ->   后验 sd = 0.1341
```

后验比先验**紧 15 倍**(2.0 / 0.134),所以「学到了东西」是一个**大效应**的断言
——按 `2026-08-27-ci-flat-chain.md` §三 的判别法,任何机器的舍入都够不到它。

**先验中心 0.5、宽 2.0 都远离标准化变换的不动点**(均值 0、宽 1),这不是随手挑的:
`log_prob` 里那一项 `- sum(log(theta_scale))` 是标准化的雅可比,而在一个 theta 恰好
零均值单位宽的 bank 上**它等于零**,于是每一条归一化检查都会在删掉它之后照样通过。
`test_the_bank_really_does_rescale_theta` 是说这条的那句话
(实测 `theta_scale = 2.017`)。

**bank 一律用 `jax.random` 直接从联合抽**,不经任何模拟器对象——这是 §〇 的直接
后果,也让这份测试与 rheplicant 完全无关。

## 二、独立 oracle:**三条互不相关的仪器**,不是一条

计划要求「独立 oracle 测试」。本批用三条,而它们彼此不共享算术:

| 仪器 | 它能说什么 | 它**不**知道什么 |
|---|---|---|
| **格点求积** `∫ exp(log_prob) dθ` | 密度是不是密度;**对雅可比敏感** | 分类抽样、混合权重怎么来的 |
| **采样器** `sample` 的前两阶矩 | `sample` 与 `log_prob` 读的是同一个混合 | 格点 |
| **闭式后验**(numpy) | 拟合出来的密度**应该**是什么 | 网络、Adam、标准化 |

实测:求积质量 **1.00000000**;采样器与求积的均值差 0.0036、sd 差 0.0034(在
sd = 1.425 上);训练后三个观测点上均值最坏偏 **0.36 后验 sd**、宽度比
**0.938–0.985**。

**一个混合分量对高斯后验是精确的**,所以这条比较是**锐利**的而不是指示性的
——容差 0.6 sd / [0.75, 1.35] 各自留了约一倍的余量,而它们要区分的东西差 15 倍。

## 三、**D43**:一次发散的训练有**两个**结果,只拒绝其中一个

D33 已为 `minimize` 立规矩:发散就拒绝,不要把 NaN 交回去。NPE 用的是同一个
Adam,但它多了 D33 没有的**留出集选择**,而那把同一次发散劈成了两半。
实测,工作学习率的一千倍(`lr=1e3`,60 步):

| `validation_fraction` | 返回的估计器 | 历史 |
|---|---|---|
| `0.1` | **有限、可用**(`log_prob` = **-45.46**) | `best_step` 塌到 **1**;`validation` 带 NaN |
| `0.0` | **参数就是 NaN**;此后每次 `log_prob`/`sample` 都是 NaN,**形状与 dtype 全对** | `train` 带 NaN |

**只拒绝第二种**,`eqx.error_if`,挂在**参数**上(它是返回物,是后面每次查询读的
东西;`error_if` 而不是 Python `if`,因为守卫要在 jit 下也响——`wiener_solve` 与
`minimize` 的同一条机制)。**第一种报告而不拒绝**:那里没有错答案,留出集选择留下的
是最后一批有限参数,而发散这件事的**唯一记录**在 `history` 里,所以历史里的非有限项
**不清洗**。

**发散不总是走到 NaN**:再高一千倍(`lr=1e6`)两条路都回来有限,损失 88.8。
**本模块不拒绝一个差的拟合,只拒绝一个不存在的。**

## 四、同批**量了之后没有新增**的一条拒绝,以及一条真的新增

这两条并排写,因为它们看起来是同一件事而不是。

**`min_scale = 0`:不拒绝。** 上游 config 层有一条针对它的语法拒绝,读起来像是
数值层也该有一条。实测**没有**:scale 是 `softplus(raw) + min_scale`,而 `softplus`
**严格为正**,零地板碰不到零。一个刻意可塌缩的 bank(八个不同 theta、八个分量、
1500 步)在两种地板下都训练到有限密度(max log-density **3.71** 对 **3.63**)。
**为一个造不出来的故障加一条拒绝,就是造一条永远不会失败的守卫。**

**`min_scale < 0`:拒绝,构造期。** 负地板从一个严格为正的 softplus 里减出来,
足够负的分量拿到**负的** scale,密度里的 `log(scale)` 于是对每次查询都是 NaN,
而网络参数**完全有限**——所以 §三 那条 `error_if` 够不到它。实测:`min_scale=-1.0`
在一个**未训练**的估计器上就返回 NaN。代价实测为零。

> 两条并排的价值在于**它们的判据是同一条**(「这个故障造得出来吗」),而答案相反。

## 五、**接受 float32**,而这是与 D41 相反的一次选择

`exact.reduced_basis`(D41)与 `diagnose.local` 都**拒绝** ambient float32。本模块
**接受**,理由写进模块 docstring 而不是留在某个人的记忆里:那两条底下压着**秩判决**
与 **Gram 矩阵**——一个判决住在舍入之下。**这里没有判决**;一个用网络拟出来的近似
密度,受限于拟合远早于受限于算术,而 float32 正是这种网络通常训练的精度。

**这是一条有意的差异,不是遗漏**,所以它写在 docstring 里、并在本页登记。

### 六.1 Z8:错的是我写下的期望

登记的红是 `test_the_posterior_width_matches`,它没红。原因是算术的:偏差修正只影响
最初约 `1/(1-β)` 步,而那条 fixture 跑 2000 步,早就洗掉了。真正红的三条全在
**过拟合那一类**——512 对样本跑 8000 步,对早期动力学敏感。**守卫没问题,期望值写错
了**,照 W5 的先例更正登记而不改测试。

### 六.2 Z9:**一条读了自己被优化的那个量的守卫**

登记的红是 `test_training_reduces_the_loss`,它**没红**——而这才是本批最值得写下来的
一行。`history.train` 记的是**正在被最小化的那个量**,所以它对任何还在工作的优化器
都会下降,**包括一个正沿着错误符号下降的**。不用推测,量了:

| | `train[0]` | `train[-1]` | 那条断言(`train[-1] < train[0] - 0.5`) |
|---|---|---|---|
| 正确符号 | +2.379 | **-0.583** | 通过 |
| 符号翻转 | -2.379 | **-4.5e+22** | **通过,而且比正确的那次更"漂亮"** |

**与 W8、X4、G3 的常数类同一族**:一条守卫够不到它要守的那个条件。这次的成因很纯
——**断言读的是被优化的那个量**,于是它按构造为真。

**修法不是把容差收紧,是换一个量**:优化器**从未被打分**的那个量——返回的估计器给
**新抽的**联合样本对的密度,与训练**起点**给同一批样本的密度相比。fixture 因此改成
同时交回起点(否则「变好了」的另一半会是一次**第二份构造**)。

**并且把这次测量本身变成常驻守卫**:`NegatedDensity` 不改 src 就复现符号错误,
并钉住「留出密度分得出来、损失曲线分不出来」。这正是 G2 的 `check_loss_sense`
(D32)问的那个问题,只是这里问的是训练器——`train_posterior` 内部固定方向,没有
`scoring=` 给调用方写错,所以符号唯一可能错的地方就是代码本身。

## 九、一个**搬过来就不再为真**的数字,以及它把成因也说错了

上游 `train_posterior` 的 docstring 写着:「8192 条模拟,1500 步宽度是精确的
**0.88**,4000 步四个分量是 **0.60**」。**在本包重测,两个都不复现**——同一条线性
高斯问题上,8192 对、四分量、4000 步回来是 **1.002**。

那不是上游写错了,是**那句话是关于另一个系统的测量**(另一个前向模型、另一个 bank),
过了仓库边界就不再是关于任何东西的陈述。这是本程序 §七 第 5 条的最便宜的一种形态:
**没有任何东西会失败**,估计器是好的,错的只是那句话。

**重测之后连"是哪个旋钮"都变了**:过拟合在这里由 **bank 大小对容量**驱动,不是步数。

| bank | 分量 | 步数 | `validation_fraction` | 宽度比 |
|---|---|---|---|---|
| 8192 | 4 | 4000 | 0.0 | **1.002** |
| 512 | 4 | 8000 | 0.0 | **0.271**,而训练损失**一路在改善** |
| 512 | 4 | 8000 | 0.2 | **0.844**,返回自第 **423** 步(共 8000);validation 从 **-0.605** 走到 **+34.08** |

原文把账记在**步数**上,而 4000 步在一个够大的 bank 上什么也不做。docstring 已按
实测改写,并**点名**这是一次更正。第三行那组数字就是
`TestOverFittingIsVisibleOnlyInTheHeldOutSplit` 的 fixture。
