### 2. Exact 与 fallback 有独立 oracle

- Exact linear posterior 由 `tests/exact/oracle.py` 的 dense NumPy construction、closed-form fixtures 以及 `tests/exact/test_{solve,extremes}.py` 验证；它们不通过被测 CG/GCR 路径重建答案。
- 用户实际执行的 hybrid/exact route 由 `tests/dispatch/test_acceptance.py` 对 dense linear algebra 或 `log_joint` grid quadrature 验证；文件明确拒绝把 exact 与 NUTS 的共同实现路径当作唯一 oracle。
- NumPyro NUTS fallback 由 `tests/test_conjugate_oracle.py` 对解析 conjugate posterior 验证；bridge density 另由 `tests/test_bridge.py` 的手写逐 plate truth 约束，而不只检查两个入口彼此相等。
- Logdet ladder 的 exact/approximate rungs 对独立 `slogdet`、解析 trace 与拒绝边界验证；graph reduction 的绝对 density 对稠密积分验证，并以未归约 double-count mutant 必红证明守卫方向。

### 3. 公共文档与实际行为一致

- README 的版本和 test count 由 `tests/test_readme_count.py` 读取真实 source metadata/collection 并按等号钉住。
- `tests/test_public_api.py` 验证所有 public submodule、lazy export 和 deprecated `bayesmith.evidence` deep import。
- README 没有宣称 R1 Task/Result、graph-level EvidenceTask、Bayes factor 或 dispatcher-selected discrete enumeration 已经存在；已知缺口仍在 Status 中显式列出。

### 4. 核心对象有清晰 owner 与兼容策略

`docs/ownership.md` 是当前 inventory。关键裁决是：Graph/dispatch/exact/marginal/graph-native diagnose 与 linear sampler 为 first-party；NumPyro 是 thin backend adapter；generic optimizer 与本地 NPE 为 reference/upstream candidate；deprecated `bayesmith.evidence` 不承载新功能并于 1.0 removal/tombstone。
