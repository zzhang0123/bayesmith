# 多数据集联合后验：不同 graph、共享参数的累积推断

## 0. 先把词汇钉死

这个 programme 最贵的几个缺陷都是「两个名字指一件事」或「一个名字指两件事」。所以先固定词汇，后文严格遵守。

### 0.1 四个量，只有一个是目标

| 记号 | 名称 | 是什么 |
|---|---|---|
| `p(theta)` | **共享先验**（the shared prior，applied once） | 对共享参数 `theta` 的、在看到任何 `d_i` 之前的陈述。整个联合分析中**只有一个** |
| `L_i(theta) = INT p(d_i \| theta, zeta_i) p(zeta_i \| theta) d zeta_i` | 数据集 `i` 的**边缘似然**（marginal likelihood） | 一个 `SqrtInfo` 项存的就是这个东西 |
| `p(theta \| d_1..d_N) ∝ p(theta) PROD_i L_i(theta)` | **联合后验** | **← 本文唯一的目标** |
| `p(d_1..d_N) = INT p(theta) PROD_i L_i(theta) d theta` | **evidence**（证据） | 只有模型比较需要它。**范围外** |

**不要写「joint evidence」**——这个词组不指称任何我们想要的东西。**不要重用「joint prior」**——`Graph.joint_prior` 与 `JeffreysPrior(over=...)` 在本代码库里已经指「若干 latent 上的、不可分解的联合密度」，见 `src/bayesmith/graph/graph.py`。需要指「多数据集情形下的那个先验」时，说 **the shared prior, applied once**（共享先验，只施加一次）。

evidence 的范围外地位是可测的事实，不是约定：`grep` 全仓库没有任何 Bayes factor、模型比较或 log-evidence 的消费者。它在本文只出现在 §5.5 一处，用来说明**哪些常数不是它**。

### 0.2 第五个量：本文引入的、词汇表里没有的东西

推导过程中出现了一个**四个量都不是**的对象，必须单独命名，否则它会被误当成 evidence：

- **`rho^2`（QR 角落质量，corner mass）**。它是拟合优度统计量，不是先验、不是似然、不是后验、不是 evidence。§3.5 给出它的正确解释（以及为什么「dataset tension（数据集间张力）」这个叫法**被驳回了**）。

### 0.3 代码名到概念名的映射（以及三处**名字说谎**的地方）

| 代码名 | 实际指称 |
|---|---|
| `bayesmith/evidence/` 整个模块 | 生产的是**每数据集的边缘似然项**，不是 evidence |
| `SqrtInfo` | 一个 `L_i` 的平方根信息表示 |
| `SqrtInfo.combine` | 两个项的**乘积**（对数域的和），即 `L_i L_j` |
| `marginalise` / `marginalise_arrays` | 对 nuisance 的**精确积分** |
| `compress` / `compress_epoch` | 从设计矩阵与数据造出 `L_i` |
| `Factorization` | 一个 graph 的 latent 按 plate 归属二分（**见 §8.4 的更正**） |
| `chain_marginal` + `HyperTransition` | 一个 `eta -> SqrtInfo` 的映射，**不是**一个固定的项 |

**名字说谎的地方**（本次实读确认，采纳本文的范围界定后这些 docstring 的理由变成错的）：

- `src/bayesmith/evidence/compress.py:94` —「that constant is what a campaign's *evidence* is」。这是本仓库**携带常数的官方理由**。§5 用「它依赖 theta 吗？」这个更锐利的判据取代它。行为不变，理由作废。
- `src/bayesmith/evidence/compress.py:158` —「so its *evidence* is not defined」，指的其实是这一项自己的对数密度。
- `src/bayesmith/evidence/chain.py:272` / `:258`、`factorize.py:46` / `:270` — 「evidence」在这几处指边缘似然贡献或对数密度差。
- `src/bayesmith/evidence/sqrtinfo.py:222` —「what this hands back instead is the *evidence* -- `pivots`」，这里是**取证义**（呈堂证供），与统计义同名不同物，且与上面几处在同一个模块里。

## 1. 记号与设定（只说一次）

`N` 个数据集 `d_1..d_N`。数据集 `i` 有自己的 graph `G_i`、自己的局部 nuisance `zeta_i`、自己的噪声 `N_i`、自己的前向模型。它约束共享 latent 全集中的一个子集 `S_i`。

**并集框架（union frame）** `U = UNION_i S_i`，按一个**固定一次**的列序 ravel 成 `x in R^{n_U}`。

线性-高斯情形（下文闭式解都在这个类里）：

```
d_i = A_i theta + B_i zeta_i + c_i + e_i ,   e_i ~ N(0, N_i) ,  zeta_i ~ N(m_i, S_i)
```

白化量带波浪号：`Jt = N^{-1/2} J`，`Gt_i = N_i^{-1/2} A_i`。

一个**项（term）**就是 `SqrtInfo`，其五个字段在 `sqrtinfo.py:72-76` 实读确认为 `factor, target, offset, names, shapes`，其中只有 `names`、`shapes` 是 `eqx.field(static=True)`：

```
log L_i(theta) = offset_i - 1/2 || R_i x_i - z_i ||^2          (1.1)
```

`sqrtinfo.py:120-123`：`log_prob = offset - 0.5 * jnp.sum(residual**2)`。
`sqrtinfo.py:60-62` 明确写着 `r < n`（行少于列）是「the normal case for a single epoch, not an error」——这一点在 §3.6 与 §7 都是承重的。

## 2. 因子分解定理

### 2.1 定理

**定理 1（多数据集因子分解，充分条件）**。设：

- **(H1) 一个先验，只用一次**。`p(theta)` 是共享参数上唯一的密度，且没有任何 `L_i` 含有它的幂。
- **(H2) 局部 latent 分解**。对每个 `i`，`zeta_i` 恰是 `d_i` 的密度所依赖的、除 `theta` 以外的全部 latent；且不同 `i` 的 `zeta_i` **互不相交**。
- **(H3) 给定 theta 的条件独立**，强形式：
  `p(d_1..d_N, zeta_1..zeta_N | theta) = PROD_i p(d_i|theta,zeta_i) p(zeta_i|theta)`，
  它同时要求 **(H3a)** `d_i` 只依赖 `(theta, zeta_i)`——不依赖任何 `zeta_j`，**也不依赖任何 `d_j`**——与 **(H3b)** 诸 `zeta_i` 在给定 `theta` 下互相条件独立。
- **(H4) 观测互异**。没有一次观测出现在两个 `d_i` 里。
- **(H5) 可积**。`L_i(theta) < inf` 几乎处处，且 `INT p(theta) PROD_i L_i(theta) d theta` 有限非零。

则

```
p(theta | d_1..d_N)  ∝  p(theta) * PROD_i L_i(theta)                    (STAR)
```

### 2.2 证明

分两步，两步的假设不同、失效方式也不同。

**第一步（边缘化恒等式，不需要任何独立性）**：

```
p(d_i|theta) = INT p(d_i, zeta_i|theta) d zeta_i = INT p(d_i|theta,zeta_i) p(zeta_i|theta) d zeta_i = L_i(theta)
```

这一步只需要 (H2) 中「`zeta_i` 恰好是 `d_i` 依赖的那一组」。**注意 `p(zeta_i|theta)` 可以依赖 `theta`**——推导中 `theta` 全程固定，任何一步都没禁止层次结构。这是 §4.3 的全部依据。

**第二步（乘积与积分交换）**。把 (H3) 对全部 `zeta` 积分：

```
p(d_1..d_N|theta) = INT PROD_i [p(d_i|theta,zeta_i) p(zeta_i|theta)] d zeta_1..d zeta_N
                  = PROD_i INT p(d_i|theta,zeta_i) p(zeta_i|theta) d zeta_i
                  = PROD_i L_i(theta)
```

**用到假设的恰是第二行的交换**，它合法当且仅当被积函数分解成积分变量互不相交的若干组。其余全是记账。再配合 Bayes 与 (H5) 即得 (STAR)。∎

### 2.3 **被驳回并已更正的论断**（原 Q1 C1）

原推导声称 (STAR) **分解为** 两个逻辑独立的断言「(2) `p(d_1..d_N|theta)=PROD_i p(d_i|theta)`」与「(3) `p(d_i|theta)=L_i(theta)`」，并给出失效条件「Never」。

**这被驳回了，且反例来自推导自身。** 更正如下：

1. **(2)∧(3) 是 (STAR) 的充分条件，绝不是必要条件。** (STAR) 是关于 `theta` 的**正比关系**；(2)、(3) 是密度**等式**。任何**不依赖 theta** 的差异对 (STAR) 完全不可见。
2. 反例（对手实测，脚本 `adv_c1/ce2_generic.py`）：两个异质数据集（`n1=5, n2=7`，局部 nuisance 维 2 与 3），一个共享标量 `zeta_s ~ N(0,1.7)` 同时进入两者且**不与任一设计正交**。此时 (2) 明确为假——`I(d1;d2|theta) = 0.26686411 nats`，`||Sigma_J - Sigma_P||_F = 5.0556`——然而 `D(theta) = -3.832449707982` 在 `theta = [0,0], [0.9,-0.4], [-2,3], [5,5], [-30,17]` 上**完全常数**（spread `1.421e-12`），两条路线给出**同一个后验**：mean `[1.06339716, -0.36799638]`、sd `[0.3456076, 0.24064582]`，逐位相同。
3. 反向也失效：若每个存储项带一个 **theta 无关**的误归一化（例如未归一的局部 `zeta` 先验，这正是一个 `SqrtInfo` 约定能造出来的），则 (3) 对每个 `i` 都假而 (STAR) 仍精确。对手实测：`c = [3.7, 0.02, 155.0]`，`SUM log c_i = +2.439735`，后验差 `0.000e+00`。这是一个**开集**，不是刀锋。
4. 「Bayes 不需要任何假设」也是假的：Bayes 需要 `0 < p(d) < inf`。平坦先验 + 全部项在 `theta` 上秩为 0（一个全被 flag 掉的夜晚）时，(2)(3) 都成立、右端 `PROD L_i` 定义良好、**左端不存在**。这就是 (H5)，原论断把它从链条里漏掉了。

**设计后果，这不是学究气**：因为蕴含是单向的，**`¬(2)` 不是合法的拒绝判据**。一个「只要某 latent 出现在两个 `zeta_i` 里就拒绝」的守卫，会拒绝掉乘积形式恰好正确的模型。正确表述是：**(H1)–(H5) 是一张充分性证书；它的否定不证明任何东西。**

### 2.4 「独立」与「给定 theta 条件独立」互不蕴含

两个方向都被实测（Q1 C3，且该论断经对手攻击后**站住**）：

- 边缘相依、条件独立：`theta ~ N(0,v)`、`d_i = theta + e_i`，`Cov(d1,d2) = v = 2.890000`，corr `0.781081`，MI `0.470917 nats`，而 `Cov(d1,d2|theta) = 0`。**边缘相依不是缺陷，它正是要合并数据集的理由。**
- 边缘独立、条件相依（collider）：`d_1, d_2` iid，`theta = d_1+d_2+eps`，`s2=0.25`。`Cov(d1,d2) = 0` 精确，而条件相关 `-1/(1+s2) = -0.800000`。乘积形式在此给出 sd 比 `1.8605`、均值偏 `0.615`。

**因此 (H3) 不能通过测量数据集之间的相关性来检验。**

### 2.5 但「只能靠声明」这半句**被驳回了**

原推导的失效条件写「must be established from the model's structure by declaration」。对手用一个**结构无关的数值检验**推翻了它：只暴露一个 `simulate(theta) -> (d1,d2)` 采样器，在**固定 theta** 处估计条件互协方差，共享 `zeta` 模型的最大奇异值 `226.3550`（次奇异值 `0.7914`），健康对照 `13.6292`（次 `2.5164`）——17 倍的秩一尖峰，且在 `theta = [0,0], [50,-50], [-3,7]` 三处都给出条件相关 `+0.993780`，**不依赖于知道真值**。

失效条件的另一半**被确证**：从**观测到的数据**做残差相关检验没有分辨力——3000 次实验中违规模型的 5% 拒绝率 `0.664`，健康模型 `0.633`。

**更正后的表述**：(H3) **不能**由观测数据集的相关性检验；它**可以**在压缩之前、由固定 theta 处的仿真证伪，前提是选到有功效的统计量。这条区分是承重的——它意味着**压缩前有探针，压缩后没有**（后者见 §6.4）。

另外一个未被原文警告的坑：`N >= 3` 时**两两条件独立不蕴含互相条件独立**。Rademacher 反例 `d3 = d1*d2`：三个两两相关系数都 `~5e-4`，而 `P(1,1,1) = 0.25038` 对边缘乘积 `0.12519`。**把 (H3) 实现成两两检查的守卫会放行一个违反因子分解的模型。**

### 2.6 (H3a) 的「不依赖任何 `d_j`」不是修辞（原 Q2 C2 被驳回的部分）

原推导把 (H2) 的**不相交性**当成充分条件（「Under disjoint local nuisances the product form is exact」）。对手给出两个反例，两者的局部 nuisance 都真正不相交：

- **CE1：跨数据集相关噪声，模型里没有任何 latent。** 联合噪声协方差的交叉块直接写在 `N` 里。gap spread `7.133023563 nats`，**变号**（`+3.206563828 / +1.250115937 / -3.286911154 / -3.926459735 / +1.417110457`），后验均值移动 `0.791835` 真 sd，`KL(prod||true) = 0.319607567 nats`。
- **CE2：联合选择效应。** 两台探测器、块对角噪声、模型完美可分，但仅在符合触发 `d_1*d_2 > 0` 时记录。全部误差恰是 `-log Z(theta)`——一个**纯归一化项且依赖 theta**。gap 逐位等于 `-log Z`，spread `0.682495970 nats`，`d/dtheta = -0.399871100` at `theta=0.4`。这一条直接证伪了「including all normalisation」。

更糟的是：原推导 Part A 的「精确到 `7.1e-15`」证据是**退化的**——它的 oracle 用 `N = blkdiag(N1,N2)` 构造真值，于是乘积恒等式成为代数恒真。把同一构造用到 CE1 的数据上，仍然报 `7.105e-15`，而真联合相差 `7.1 nats`。

**更正**：定理 1 的 (H3a) 必须读作「`d_i` 的密度既不依赖任何 `zeta_j`，也不依赖任何 `d_j`」，其中「依赖 `d_j`」包含**跨数据集相关噪声**与**在多个数据集上求值的选择/flag 规则**。bayesmith 自己的代码已经把这两件事当作不同的东西：`campaign.py:369-406` 的 `_slice_precision` 拒绝一个不按 epoch 分批的协方差，理由写着 folding separately is wrong「in the same way a leaky latent does」——同样后果、不同成因。原论断的失效条件落后于它要辩护的代码。

### 2.7 破坏 (H2) 的确切代价（线性-高斯闭式）

设 `zeta_s` 为共享 nuisance。此时**每个 `L_i` 仍然是正确的边缘似然**（这一点是恒等式，无可反驳），失效的只是乘积：

```
Sigma_J = Sigma_P + offdiag( B_1 S_s B_2^T )
```

实测 `||Sigma_J - Sigma_P||_F = 12.752763713971248`，恰等于 `sqrt(2)*||B_1 S_s B_2^T||_F = 12.752763713971248`，对角块逐块相等。**乘积形式不是「另一个协方差模型下的近似」，它就是把一个特定分块置零的联合似然。**

**但「那个块是 `B_1 S_s B_2^T`」这句话本身被驳回了**（原 Q1 C5）。正确的一般律，对手逐元素验证到 `0.00e+00`：

```
Sigma_J - Sigma_P = offdiag( Cov(d_1, d_2 | theta) )                    (2.7)
```

只有在**噪声跨数据集块对角、局部 nuisance 先验跨数据集独立、(H3a) 与 (H3b) 都成立**时它才退化成 `B_1 S_s B_2^T`。三个 PSD 验证过的线性-高斯反例：

- 完全没有 nuisance（`B_1=B_2=0`）而噪声相关：C5 预测误差 `0.0`，实测 `||Sigma_J-Sigma_P||_F = 0.8426149773176358`，gap `-0.156927517 nats`。
- 局部先验跨数据集相关：C5 预测 `2.580728815692046`，实测 `4.338057544650635`，残差恰是 `||C_1 S_12 C_2^T||_F = 1.8417789623299887`（15 位吻合）。
- 推导自身 §2.2 的 collider：线性-高斯、**完全没有 nuisance**，`Cov(d|theta) = [[0.555556,-0.444444],[-0.444444,0.555556]]`，删掉的块 `-0.4444444444444444`。C5 在此连 `B`、`S_s` 都不存在。

此外该论断的**两项证据都无法证伪**：换一个 Frobenius 范数相同的任意交叉块 `Y`，`||Sigma_J - Sigma_P_wrong||_F` 逐位相同（`12.752763713971248`，`np.isclose` 为 True），对角块仍相等；而「对角块相等」本身是重言式——任何正确边缘的乘积都按构造有正确的边缘。

### 2.8 误差的符号与 N 标度：三个**被驳回**的说法

1. **「乘积形式过度自信」是错的。** 同号共享 → 过度自信；反号共享 → 欠自信，倍数 `1 + tau^2/sigma^2` **无界**。实测表：`F_true/F_prod = 0.528857`（over）、`9.163265`（under）、`1.000000`（exact）、`33.653061`（under）。同一个 fixture 里 `eig(C_true^-1 C_prod) = [0.876099, 1.046751]`——**一个方向更紧、另一个更松，同时发生**。
2. **「误差按 sqrt(N) 无界增长（不论共享方向如何）」是错的**（原 Q4 B2）。控制量不是设计的持久性（design persistence），而是**累积响应的相干性** `|SUM_i a_i|`（`a_i = Gt_i^T v_i`）。对手实测常数 `(bias/sd)/(|SUM a|/sqrt N) = 0.010414 ... 0.010243`（跨 balance 分数与 `N=256..4096`，恒定到 0.4%）。于是：
   - `SUM_i a_i = Theta(N)` → `sqrt(N)` 无界；
   - `SUM_i a_i = O(sqrt N)` → 饱和；
   - `SUM_i a_i = 0` → **恒为零**。
   **持久设计既不充分也不必要**：设计每晚逐字节相同、耦合按 `u_i = (-1)^i u` 变号（beam switching / nodding / parallactic 翻转，**是工程上刻意做出来的**），bias 精确为 0、宽度比 `1.0045` 从 `N=2` 平到 `N=4096`；in-span 版本宽度比 `3.9170` 同样全程平坦。反过来，设计每次重抽但 `E[a_i] != 0` 时，`sqrt(N)` 增长完整存在（slope `0.4997`）。
   原推导之所以读错，是因为它的 fixture（以及 rheplicant 的 `campaign_bank`）把「设计持久」与「耦合相干」拧在同一个旋钮上。
3. **「Delta = 0 当且仅当 |S| = 1」是错的**（原 Q4 B1）。`p=1` 时 `Delta` 是标量、设计空间连通、`Delta` 连续，而推导自身证明了持久设计 `Delta > 0`、重抽设计 `Delta < 0`——**介值定理保证每个 `|S| >= 2` 都有零点**。对手在两端之间做同伦二分，`|S| = 32`、32 个设计全不相同、每个 `a_i` 非零：`F_true = 91.6109097923749` vs `F_prod = 91.61090979237501`（相对 `1.24e-15`）。而且此时两条规则**仍然不一致**：sd 精确到 15 位相同，均值差 `-0.166 sigma`。
   正确表述：`Delta = 0` 当且仅当 `(SUM a_i)(tau^-2+SUM k_i)^-1(SUM a_i)^T = SUM_i a_i(tau^-2+k_i)^-1 a_i^T`（一个设计上的**平衡条件**）。`|S|=1` 与 `a_i ≡ 0` 是充分的，不是必要的。而且 `Delta = 0` **不蕴含**两条规则一致——信息差与均值偏移的零集不同。

**依然成立且承重的部分**：`u` 落在设计列空间内且响应相干时，in-span 误差按 `sqrt(N)` 无界（实测 `0.049059` @ `N=640` 与 `0.024537` @ `N=2560`，比值 `0.5001586`）；`u` 与列空间**正交**时乘积形式在每个 `N` 上精确（`1.000000`）——**这是一个退化 fixture，不能用作探针**（推导者自己第一次就误建了它）；`N=1` 时所有列都读 `1.000000`，**任何单数据集 fixture 都无法定罪 (H2)/(H3)/(H4) 的任何违反**。

### 2.9 (H4)：同一份数据进两次

`p(d_1,d_2|theta) = p(d_1|theta) delta(d_2-d_1)`，Dirac 因子与 `theta` 无关，所以真后验 `= p(theta|d_1)`，重复项**贡献为零**。实测联合协方差秩 `6 of 12`（奇异）。而乘积形式给 `F_post = F_prior + k F_L`，宽度收缩 `sqrt((F_prior + k F_L)/(F_prior + F_L))`。

**但「均值不动、宽度按 sqrt(k) 收缩」这个特征签名被驳回了**（Q5 C5 的对手实测）。它是**平坦先验的产物**：8x2 设计上，`tau=1e6` 给 `[1.414214, 1.414214]` 与均值移动 `[0.0000, -0.0000]`；`tau=1.0` 给 `[1.405662, 1.403073]` 与 `[+0.033, -0.064]`；`tau=0.3` 给 `[1.337162, 1.318007]` 与 `[+0.341, -0.557]`。信息性先验下它既不是 `sqrt(2)` 也不保均值。

**设计后果**：重复数据集**不能**靠数值签名侦测，必须靠身份记账。而今天 `SqrtInfo` 的五个字段里**没有任何身份**（本次实读确认）。rheplicant 的 `CompressedLikelihood` 协议有 `epoch_id`、`estimator`、`prior_share`、`inputs`（`compressed.py:64-91`, `:110-119`）。多数据集下的规则不是「不重复计一次 recording」，而是**「不重复计一次观测」**——一个关于诸 graph 观测节点并集的陈述。真实场景是「一次定标扫描同时用作 calibrator 与 science target」，本文与卷宗都**没有解决**它（见 §10.6）。

## 3. 组合定理（本文核心）

### 3.1 嵌入：选择矩阵，以及它乘在哪一边

定义 `E_i in R^{n_i x n_U}`：`(E_i)_{j,k} = 1` 当且仅当并集列 `k` 是数据集 `i` 的第 `j` 个 ravel 坐标。于是 `x_i = E_i x`，代入 (1.1)：

```
R~_i := R_i E_i   (r_i x n_U) ,   z~_i := z_i ,   off~_i := offset_i        (3.1)
```

**选择矩阵右乘。** 理由是一个关于「哪个指标在被重标」的陈述：`R_i` 的行是**数据侧**指标（`r_i` 个白化残差方向），列是**参数侧**指标。嵌入只改列指标，改列指标就是右乘一个「行按旧列集编号、列按新列集编号」的矩阵——`E_i` 的形状 `(n_i x n_U)` 正是为此。左乘会声称在重标残差方向，那不是正在发生的事。

`R_i E_i` 的闭式就是「把 `R_i` 的列散射（scatter）进并集布局，其余精确为零」。

两条恒等式，后文都要用：

```
E_i E_i^T = I_{n_i}                                    (3.2)  行正交：每个坐标只命名一次
P_i := E_i^T E_i = diag(1 if col in S_i else 0)        (3.3)  坐标子空间的正交投影
```

(3.2) 使嵌入无损（`R_i = R~_i E_i^T`）；(3.3) 使不同数据集的局部量精确不交互（§3.7）。

嵌入后的信息：

```
F~_i = R~_i^T R~_i = E_i^T F_i E_i                                          (3.4)
```

——把 `F_i` 散射进并集，`S_i` 之外的行列精确为零。这是选择矩阵的合同变换，保 PSD，且不能凭空造秩。

**`z_i` 与 `offset_i` 完全不动**：`z_i` 活在数据侧指标上，`offset_i` 根本没有指标。这就是为什么嵌入**零成本**、可以对一个早已写到磁盘的项事后施加——在累积式设计里，数据集 1 的项可能在数据集 5 存在之前、也就是在 `U` 已知之前就写好了。

#### 3.1.1 **被驳回并更正**：哪一种「乘错边」是静默的（原 Q2 C1）

原推导说 `E_i^T R_i` 在 `r_i == n_i`（方块 padded block、`SqrtInfo.null` 的常见形状）时「合法且错误」。**这是错的，且方向反了。**对手穷举了全部四种乘错边形式（脚本 `adv/c1_boundary.py`），实测：

- **真子集且 `r_i != n_i`**：`E^T R`、`E R`、`R^T E`、`R E^T` **全部 numpy 非法**。形状检查是完备守卫。
- **真子集且 `r_i == n_i`**：`E_i^T R_i` 形状 `(n_U, r_i)`，被 `SqrtInfo.__check_init__` **拒绝**（本次实读 `sqrtinfo.py:91-96` 的列宽检查）：`"SqrtInfo.factor has 3 columns but the named latents ['p','q','r','s'] ravel to 7 values."` **静默错误的是 `R_i^T E_i`**：形状 `(r_i, n_U)`、被接受、log_prob `-3.817621` vs 正确 `-4.585911`（gap `+0.768289 nats`，依赖 theta），`||F_wrong-F_ok||/||F_ok|| = 1.073`，**两者秩都是 3，秩诊断看不见**。
- **`n_i == n_U`（项已横跨并集、只有列序不同）**：`R_i E_i^T` 被接受且错 `-5.661283 nats`；若同时 `r_i == n_i`，**四种乘错边全部被接受且全错**（gap `-21.550961 / -28.561503 / -16.452474 / -3.368356 nats`）。
- **`SqrtInfo.null` 永远不会展示这个故障**：真子集上形状不匹配被拒；全框架上 `E` 是置换而 factor 全零，`E^T R` 与 `R E` **逐位相同**。

**正确的失效条件**：当且仅当乘错边的乘积能通过类型检查**并**落在形状 `(r, n_U)`（`r = len(target)`）时，错误被静默接受。危险区间是**「项已横跨并集、只有列序不同」**——也就是 §3.8 的排序风险——外加 `r == n` 的方块情形经由 `R^T E`。**这不是 padding 风险。**

另外，「其余精确为零」在有非有限元素时是假的（`0*inf = nan`）：一个 `inf` 会经矩阵乘法**污染该数据集根本没有命名的 latent 的列**。所以 matmul 闭式与 scatter 实现**不等价**，且 matmul 扩大了爆炸半径。

#### 3.1.2 `E_i` 何时不是选择矩阵

三种，**没有任何代码能侦测**：

1. 同一个**名字**在两个 graph 里指不同的量（单位、符号约定、向量内分量顺序）。真关系是 `x_i = M_i x`（`M_i` 非选择矩阵），(3.1) 就是一句假话披着恒等式的外衣。
2. 两个**不同名字**指同一个物理量。`U` 过参数化，联合出现一个**伪零方向**（§3.6(c)）。
3. bayesmith 的 tracing 层**已经故意排除了从名字推断身份**：`NodeRef._owner` / `PlateRef._owner` 拒绝来自另一次 `trace(...)` 的 handle（本次实读 `graph/trace.py:100-118` 与 `:120-151`，错误信息写着「A handle is only valid inside the trace(...) that created it」）。

**因此跨 graph 的共享关系必须是一个被声明的对象** `iota : (graph index, latent name) -> shared symbol`，不能从字符串相等推断。从名字推断会反转本包刻意做出的决定。

### 3.2 组合定理

令 `M~_i := [R~_i | z_i]`，`y := [x; -1]`。则 `M~_i y = R~_i x - z_i`，且

```
|| R~_i x - z_i ||^2 = y^T G_i y ,     G_i := M~_i^T M~_i                   (3.5)
```

`G_i` 是**增广 Gram 矩阵**，同时装着 `F~_i`、右端 `b~_i = E_i^T R_i^T z_i` 与残差常数 `z_i^T z_i`。竖直堆叠：

```
G := M~^T M~ = SUM_i G_i                                                    (3.6)
```

这是恒等式，不是近似。取 QR，`M~ = Q U`，`Q^T Q = I`：

```
U^T U = U^T Q^T Q U = M~^T M~ = G                                           (3.7)
```

**这就是「QR 精确保持它」的全部内容**：Gram 是正交不变量，而 `G` 同时装着 `F`、`b` 与残差常数，所以三者一次性被保持，不需要对 target 单列一个论证。

`combine` 保留 `keep = min(m, n_U)` 行（本次实读 `sqrtinfo.py:188-189`：`keep = min(upper.shape[0], width)`；`corner = upper[keep:, width]`——**只切 target 那一列**，所以被丢弃块的严格三角性是承重的）。因为 `U` 上三角，指标 `>= n_U` 的行在前 `n_U` 列全零。写

```
U = [ R_keep  z_keep ;  0  rho ]
```

逐块比对 (3.6) 与 (3.7)：

```
R_keep^T R_keep = SUM_i E_i^T F_i E_i            信息，精确守恒
R_keep^T z_keep = SUM_i E_i^T R_i^T z_i          右端，精确守恒
z_keep^T z_keep = SUM_i z_i^T z_i - rho^T rho    target 自身，掉了 rho^2       (3.8)
```

**target 本身不守恒，守恒的是配对 `R^T z`。** 说「targets are preserved」是错的。掉的那一份恰是 `rho^2`，这就是 offset 必须吸收它的全部理由：

```
offset_joint := SUM_i offset_i - 1/2 rho^2                                  (3.9)
```

于是对每个 `x`：`offset_joint - 1/2||R_keep x - z_keep||^2 = SUM_i log L_i(x)`。这正是 `sqrtinfo.py:193` 的
`offset = first.offset + second.offset - 0.5*jnp.sum(corner**2)`，`N > 2` 由归纳得到，因为结果是同类型的项。

**我本次的验证**（脚本 `/private/tmp/.../scratchpad/final/verify.py`，`/Users/zzhang/projects/rheplicant/.venv/bin/python`，`jax_enable_x64(True)`，对真实 `bayesmith.evidence.sqrtinfo`）。并集 `("a","b","c")`、shapes `((2,),(),(3,))`、`n_U=6`；三个项分别在 `("a","b")`、`("b","c")`、`("a","c")` 上，行数随机（含 `r_i < n_i` 与 `r_i > n_i`）：

```
combine 与嵌入项之和的 gap              = 0.000e+00
||F_QR - SUM E^T F_i E|| / ||F||        = 2.806e-16
rank(F_joint) = 6 of 6，而各项秩 = [3, 4, 2]
```

最后一行就是「联合约束」这件事本身的度量：三项之和为 9 > 6，上界松，且**任何单项都不满秩**。

### 3.3 归一化常数：`2 pi` 一个也不产生在这一层

**嵌入与 `combine` 都不引入任何 `2 pi`。** 这是个正面结果，也正是让 `N` 数据集的记账保持可控的原因。全部 `2 pi` 产生在**单个数据集自己的压缩内部**：

1. `compress`（本次实读 `compress.py:143`）：观测自身的高斯归一 `-1/2 SUM_{seen} log(2 pi sigma_j^2)`，带 mask，所以被 flag 的样本贡献 0 而不是无穷。
2. `nuisance_prior`（`compress.py:253-258`）：`-SUM_j log(std_j) - (n_b/2) log 2pi`。
3. `marginalise_arrays`（`sqrtinfo.py:244-249`）：`+(n_b/2) log 2pi - SUM_j log|R_bb,jj| - 1/2 rho_b^2`。

### 3.4 **被驳回**：`2 pi` 的相消「恒成立」，以及 `-SUM log std` 「无可相消」

两条都被驳回，且方向不同。

**(a) `2 pi` 的相消不是恒等的**（Q5 C5 对手）。`nuisance_prior` 的 `-(n_b/2) log 2pi` 由 `size = factor.shape[0]`（**带先验行的 latent 宽度**）算出，`marginalise_arrays` 的 `+(n_block/2) log 2pi` 由 `n_block`（**被积掉的列宽**）算出。二者在 `compress_epoch` 路径上按构造重合，但**部分边缘化**（积掉局部 nuisance、保留共享 nuisance——正是本文存在的理由）时不重合：两个 nuisance `b1,b2` 各带先验行，`marginalise(joint, ("b1",))` 给出 `-5/2 log2pi` 对 `+2/2 log2pi`，净 `-2.7568155996140176`，而结果**是正确的**（对 dense 参考 `4.3e-14`）。剩下的是 `b2` 仍然存活的先验归一。

更要紧的是**跨数据集共享的 nuisance 的 `2 pi` 产生在并集框架里**，而不是「在项到达并集框架之前就已经结清」。对手实测：两个数据集（6 和 5 个样本）共享 `theta in R^2` 与 nuisance `b in R^2`，先验 `N(m=(0.3,-1.2), std=(0.7,3.0))`。正确构造是 compress 各自 → combine → **共享先验只施加一次** → combine → `marginalise(["b"])`，对 dense `N(d; A th + B m, N + B S B^T)` 吻合到 `5.3e-15 / 1.6e-13 / 2.8e-14`。`marginalise` 在并集框架里加的常数 `-1.348489030127` 精确分解为 `+1.837877066409` (= `0.5*n_b*log 2pi`) `- 3.186366096536` `- 0.0`。删掉那个 `1.837877` 就差 `1.837877 nats`。

而**推导自身 §4.4 强制的路线**（「marginalise before embedding, always」）在此**是错的**：每数据集一份先验 + 每数据集一次边缘化 → 净 `2 pi` 为 0（正如原论断所言）**且答案错**，误差 `-2.055196 / +3.418269 / +0.254858 nats`（**变号**，故依赖 theta，是错的后验而非 offset）。先验只施加一次但仍局部边缘化 → 净 `+1.837877` 未相消，误差 `+0.923296 / +6.637100 / +3.603447 nats`，而且 `marginalise` **没有拒绝**它（5 行数据对 2 列块，数据自己就约束住了 `b`，pivot 守卫通过）。

**更正后的规则**：`2 pi` 的收支由「**共享先验被施加了几次**」对「**发生了几次边缘化**」决定，而这是**在并集框架里做的决定**，不是在项到达之前就结清的。

**(b) `-SUM log std` 并非「无可相消」**（Q3 C4 对手）。两个带 `std` 的项的**净额**精确等于 `-1/2 logdet(I + S B^T N^-1 B)`（吻合到 `8.9e-16`，跨三种设计 × 四种 std）。在 `ker(B)` 上这个净额**精确与 std 无关**：令 `B[:,1]=0`，净额在 `std_1 ∈ {0.2, 1, 5, 50}` 上都是 `-2.671942099574`（250 倍变化下 spread `8.9e-16`），因为零方向上的 pivot **精确是 `1/std_1`**（实测 `3.3333333, 1.0, 0.1428571` at `std_1 = 0.3, 1.0, 7.0`），`marginalise` 恰好贡献 `+log std_1`。

同时被驳回的还有支撑论据：「marginalise ... never sees a std」是假的——`nuisance_prior` 把 `jnp.diag(1/std)` 直接写进 `R` 的行（`compress.py:246`），`combine` 再把它们堆进 `marginalise` 分解的那个矩阵。可辩护的弱化版本是：**`marginalise` 无法把 `det S` 与 `det(B^T N^-1 B + S^-1)` 分离开。**

**(c) 由此，那条广为流传的失效条件也是错的。** 「`-SUM log std` 在 `std = 1` 处恰为零，所以单位先验 fixture 看不见它缺失」——**盲区其实是 `prod(std) = 1`**。对手端到端实测（模拟省略该项）：`std=[0.5,2.0,1.0]` 与 `[0.25,4.0,1.0]` 的 defect 都是 `0.000e+00`，**它们都是非单位先验**。这戳穿了被规定的补救措施（`sqrtinfo.py:270-276` 与多处推导都说「用非单位先验」）。再加上 (b)：**带零 nuisance 设计列的 fixture 在任何 std 下都是盲的。**

### 3.5 `rho^2` 是什么——以及**被驳回**的那个解释

在 `R_keep` 列满秩且方阵（任何以 `SqrtInfo.null` 播种的 fold 之后的形状）时，

```
rho^2 = min_x SUM_i || R_i E_i x - z_i ||^2                                 (3.10)
```

实测：累积 offset 减各项 offset 之和 `= -6.22007087892706`，`-0.5 * lstsq` 残差 `= -6.22007087892706`（gap `1.776e-15`，堆叠秩 6 of 6）。

**被驳回的部分**：原推导把它命名为「the tension between the datasets（数据集间张力）」并建议作为一致性诊断上报。对手证明这是错的。正确分解是

```
rho^2 = SUM_i (数据集 i 相对自身存储原点的不可约残差) + (真正的跨数据集张力)
```

第一项只在**每个存储项都行满秩**（宽而独立，或方阵可逆）时消失——**那是存储形式的性质，不是数据集的性质**。而 bayesmith 的主要项生产者产出的是**高矩阵**：`compress` 返回 factor = 白化设计，形状 `(n_data, n_params)`，`compress_epoch` 在没有 nuisance_design 时原样返回（`compress.py:377-385`，「this reduces to compress」）。所以**一个没有局部 nuisance 结构的数据集**——异质 campaign 里再平常不过的成员——存下的项自身残差卡方是 `O(n_data)`，且被完整计入 `rho^2`。

对手的三个反例：

- **参数集完全不相交**（张力按构造为零）：`rho^2 = 73.9946206705`，恒等式 (3.10) 成立（gap `2.84e-14`），而跨数据集张力 `= 0.000e+00` 精确，数据集内份额 `100.00%`。
- **`N = 1`**：`rho^2 = 40.7908189418`，累积 factor `(2,2)` 列满秩。**根本没有第二个数据集。**
- **混合 nuisance 结构，完全走公开 API**：A 有局部 nuisance（marginalise 后方阵），B 没有（高矩阵）。`rho^2 = 154.535844`，真实跨数据集张力 `0.040596`——**占 0.03%**。

而且两种读法互斥：同一份数据（`n_data=200`, `bias=0.6`），直接 fold 原始 compress 项 → `rho^2 = 722.194` = 联合最小卡方（不是张力 `331.318`）；先 `marginalise(t, ())` 再 fold → `rho^2 = 331.317890` = 张力精确（不是联合最小卡方）。**哪一个取决于流水线，不取决于数据。**

另外，原论断给出的条件「累积 factor 列满秩」也不充分——真正承重的是「**且为方阵**」。一个裸 compress 项 factor `(60,2)` 列满秩、`rho^2 = 0`（它从没进过 combine）而最小卡方 `40.79`。

**更正后的表述**：`rho^2` 是**存储项相对其自身原点的联合最小卡方**。若要报告「数据集是否一致」，正确的量是

```
tension := min_x SUM_i ||R~_i x - z_i||^2  -  SUM_i min_x ||R~_i x - z_i||^2   (3.11)
```

它**不是**角落里装着的东西，除非每个项都事先被方化。而且这个诊断**永远不能脱离联合秩单独读**（见 §3.6 与 §3.9）。

### 3.6 秩

因为 `F_joint = SUM_i E_i^T F_i E_i` 是 PSD 之和：

```
x^T F_joint x = SUM_i || R_i E_i x ||^2                                     (3.12)
N(F_joint) = INTERSECT_i N(R_i E_i)                                         (3.13)
max_i rank(F_i) <= rank(F_joint) <= min(n_U, SUM_i rank(F_i))               (3.14)
```

**一个方向只有在每个数据集都对它盲时才存活进联合零空间。** 上界通常取不到（各项在共享坐标上重叠）。我本次实测的 `[3,4,2] -> 6 of 6`（和为 9）就是这句话的度量。

**充分条件**：若每个 `R_i` 列满秩（每个数据集确定自己的子集）且 `UNION_i S_i = U`，则联合满秩。**覆盖是必要的**：若并集坐标 `k` 不在任何 `S_i` 里，`e_k` 在联合零空间中。

**仍然亏秩的三种方式**：(a) 未覆盖坐标（纯记账可查，不该用 SVD 查）；(b) **所有相关数据集都盲的共享方向**——对任何逐数据集检查都不可见，实测联合秩 `5 of 6`、谱尾 `8.18e-16`、零方向 `(0.7071, -0.7071, 0, 0, 0, 0)`，且 `||R_i E_i n|| = 4.5e-16 / 2.9e-16 / 7.1e-16` 三者皆盲；(c) 并集过大（一个量两个名字），代数上与 (b) 完全相同而补救相反。

#### 3.6.1 **被驳回**：`F_joint` 是「似然信息」，以及「proper 先验恢复正定」

两条都被驳回（原 Q2 C6）。

**(1) `F_joint` 不是似然信息**，只要任何 `L_i` 是通过 **factor 或 offset**（而非残差）依赖共享 latent 的。这正是 §5.4 的 `HyperTransition` 情形。缺失的假设、从未被陈述的是：**每个 `L_i` 必须在完整并集框架里是精确高斯，且 `R_i` 与 `offset_i` 不依赖任何并集 latent**。

对手的反例不是稻草人：三组数据 `d_ij = mu + b_i + eps_ij`，`b_i ~ N(0, tau^2)` 局部于 graph `i`，共享 `theta = (mu, tau)`，`tau` 被推断。每个存储项**精确**（`max |log L_i - (offset_i(tau) - 0.5(R_i(tau) mu - z_i(tau))^2)| = 5.684e-14`），全部 `tau` 依赖坐落在 `offset_i(tau)` 里——那个 §1 声明为「a NUMBER」的字段。于是 `F_joint = [[4.005454, 0],[0,0]]`，秩 `1 of 2`，零方向恰是 `e_tau`，且 `||R_i E_i n|| = 0.000e+00` 对三个数据集全成立——(3.13) **字面成立**。而同一框架里的精确 Fisher 是 `[[4.005454,0],[0,7.064232]]`，秩 2，逐数据集 `I_tautau = 2.7546, 1.2800, 3.0296`——**没有一个数据集是盲的**。profile 对数似然在这个「联合零方向」上变化 `5.005 nats`。`mu` 块两边逐位相同（`4.005454`），这正是要害：**项是对的，`F_joint` 依然不是似然信息。**

误差方向是危险的那一侧，且与原论断的警告相反：原文只点了**假阴性**（先验掩盖真实亏秩），漏了**假阳性**（`F_joint` 凭空发明一个不存在的亏秩）。更糟的是 §3.6 规定的补救——「加一次共享先验」——在这里会给一个数据以 `I_tautau = 7.06` 精度确定的参数**装上先验**，用假设悄悄替换测量。

**(2) 「proper」不是正确的谓词。** `Uniform(-10, 10)` 是正规化的、proper 的密度，使后验 proper，而它在支撑内对精度的贡献**精确为零**：`F_post = F_joint + 0`，秩仍 `1 of 2`。bayesmith 自己就是这么说的（`diagnose/sensitivity.py:324`：「a Uniform exerts none at all inside its support」）。而且本次实读确认 `diagnose/priors.py:71-73` **要求**被 `JeffreysPrior(over=...)` 覆盖的 latent 必须声明为 **`ImproperUniform`**——贡献零信息，零方向上后验非 proper。**正确的条件是「先验在零方向上有严格正曲率」**，它与 proper 既不互相蕴含也不互相排斥。

**(3) 复数域下 (3.13) 直接为假**（见 §7.1）：`information()` 是 `factor.T @ factor` 无共轭，只有包含关系 `INTERSECT_i N(R_i E_i) SUBSET N(F_joint)` 存活。诚实的genericity 说明：2000 个随机复数 fixture **无一** 展示 `rank(R^T R) < rank(R)`——这是零测度事件，随机 fixture 会读作**确证**该论断。三个结构化 fixture 定罪它。

**(4) 规定的检验对象把条件数平方了。** `sqrtinfo.py` 自己的 docstring 说 `kappa(R) = sqrt(kappa(F))`。用本包自己的 `DEFAULT_RANK_RTOL = 1e-8`（`identifiability.py:154`）作用在 `F_joint` 上，一个在 `R` 里以相对强度 `1e-4` 被看到的方向会被判为联合零方向：`eps = 1e-4, 1e-6, 1e-7` 三处 `rank(stack) = 2` 而 `rank(F_joint) = 1`。**四个数量级的误判**，对比 §3.6.2 担心的 0.32 个数量级。

### 3.6.2 秩判定必须做列归一化

白化（可逆行运算）与列缩放（可逆列运算）都保零空间、都改谱；而秩的**切分**是比值检验。实测同一个近退化联合：`s_min/s_max` 未归一化 `5.092e-17`，列归一化 `1.053e-16`——**0.32 个数量级**，作用在一个与 `1e-8` 比较的比值上。并集混合不同单位（一个温度和一个无量纲增益，正是 `identifiability` 自己 docstring 的动机场景）时差距远大于此。**不做列归一化的秩判定报告的是单位的选择。**

float32 的方向**不可预测**：实测在 `eps ∈ {1e-3, 1e-5, 1e-6, 1e-7, 1e-9, 0}` 上 float32 与 float64 判定**完全一致**（所以显而易见的 fixture 什么也证明不了）；细扫才找到窗口 `[1.2e-8, 2e-8]`，例如 `eps=2e-8` 时 float64 见 `1.707e-8`（秩 6）而 float32 见 `6.812e-9`（秩 5）——此处 float32 **过度报告**退化，与 `identifiability` docstring 记录的方向相反（那一例是 float32 **隐藏**了真实零方向）。**「float32 在这里偏保守」不可推广。**

### 3.7 不同数据集的局部量精确不交互——以及由此得到的、**被驳回**的设计规则

由 (3.3)，对 `k in S_i \ S_j`、`l in S_j \ S_i`，`F_joint[k,l] = 0` 精确。联合信息是**块箭形**：共享块稠密，局部块块对角，只经共享列耦合。

两条路线因而在数学上等价：**路线 1**（各数据集内部先 marginalise 局部量，再嵌入小项、combine）与**路线 2**（全部嵌入大并集、combine、最后一次性 marginalise）。实测吻合 `7.1e-15 ~ 1.4e-14 nats`，offset `3.6e-15`，大并集里的交叉块 `F[u,v] = 1.7e-16`。

代价不等价：路线 2 携带稠密 `(n_shared + SUM_i n_local,i)^2` 累积器，路线 1 只有 `n_shared^2`。

**但由此得出的规则「marginalise before embedding, always」被驳回了**（§3.4(a)）：它只在 nuisance **真正局部**时有效。共享 nuisance 不是局部量，属于 `U`，而对它执行该规则会给出错误后验（`-2.055196 / +3.418269 / +0.254858 nats`，变号）。

**更正后的规则**：**局部量尽早消掉；共享量留在并集框架里，其先验只施加一次，且只积一次。** 并集框架应当只含**共享** latent 与尚未可消的局部量。

#### 3.7.1 而且这条交换律在操作上**不是无条件的**（原 Q4 A2 被驳回）

`marginalise` 的 pivot 下限是 `sqrt(eps) * float(jnp.max(pivots))`（`sqrtinfo.py:369-371`），其中 `pivots` 取自**整个置换后 factor** 的 QR ——包括其他数据集的 nuisance 列与共享 `theta`。于是**「`zeta_2` 是否被算作被约束」取决于框架里最大的 pivot 在哪儿。**

对手实测（`p=2, q=2, n=(9,7)`，`s = (1e-10, 0.9)`，nuisance 列不相交、先验各计一次、无别名）：

```
      s1 |  marg-before | both-at-once |    seq z1,z2 |    seq z2,z1
   1e-09 |    +7.11e-15 |      REFUSED |    +0.00e+00 |      REFUSED
   1e-12 |    +0.00e+00 |      REFUSED |    -3.55e-15 |      REFUSED
```

两种消元顺序返回**精确正确**的答案，两种抛异常。机制：块 `['zeta_2']` 在完整框架里 pivots `3.159/3.262` 对下限 `1.490e+02` → 拒绝；消掉 `zeta_1` 之后，**同样的数字**对下限 `6.181e-08` → 通过。

而且并集框架接受的是逐数据集路径的**真子集**，且差距随 `N` 扩大（`sigma_i` 对数均匀跨 8 个数量级，20 次试验）：并集拒绝率 `0/20 (N=2) → 1/20 (N=8) → 5/20 (N=16) → 9/20 (N=32)`，逐数据集路径全程 `0/20`。**这给了「先局部消元」第三个理由，是原推导没有的：晚消元是唯一一种条件良好的块也会被判为「不受约束」的框架。**

**注意这不影响代数**：`F_joint`、`b_joint` 与最终 `log_prob` 不受消元顺序影响。受影响的是**这个操作是否被允许执行**。

### 3.8 排序

**一致置换是精确的。** 令 `E'_i = E_i P^T`，则每个物理点上的 `log_prob` 与 offset 全不动，`F` 共轭为 `P F P^T`。实测：`(a,b,c)` 与 `(c,b,a)` 下同一物理点的 log-density gap `0.000e+00`（逐位），`||F' - P F P^T||/||F|| = 2.110e-16`。

**fold 顺序无关**——由 (3.6)，堆叠是集合运算。实测三个数据集全部 6 种顺序，offset spread `3.55e-15`，`log_prob` spread `1.42e-14`。

#### 3.8.1 **被驳回**：fold 顺序无关是**满秩 fixture 的产物**（原 Q2 C3）

当 `F_joint` **精确奇异**时，`R_keep^T z_keep = b_joint` **不再唯一确定** `z_keep`（只定到 `N(R_keep^T)` 的模），于是 `z_keep^T z_keep`、`rho^2`、`offset_joint` **依赖遍历顺序**。

**我本次实测**（同一脚本 `final/verify.py`）：三个项在 `("t",)`、shape `(4,)` 上，第 3 列在**任何**数据集里都不出现——也就是 §3.6(a) 的情形，**由 §3.1 的嵌入按构造制造出来**：

```
rank-deficient joint: offset spread over 6 fold orders = 2.224471 nats
log_prob spread over the same 6 orders                = 5.329e-15 nats
```

（对手在另一个 fixture 上得 `1.685360 nats`，同一现象。）

**声明的交付物毫发无伤**：联合后验完全不动，offset 的变化恰好抵消 `z^T z` 的变化。**坏掉的是任何把 offset 当成一个数来读的消费者**——§3.5 的张力诊断、断点续 fold、leave-one-out、以及（范围外的）evidence。

同一驳回还打掉两条：

- 「`SUM_i r_i <= n_U` 时角落为空、不折入常数」在**播种 fold** 下是假的。`SqrtInfo.null` 被 docstring 称为「the identity of combine」且是方阵，所以播种后总有 `m >= n_U + 1`，角落**从不为空**。实测 `SUM_i r_i = 6 = n_U` 且联合亏秩：未播种角落质量 `-2.2e-16`（如所称为空），播种后角落质量 `2.545243952`、offset 移 `-1.273 nats`，而 `log_prob` gap `0.000e+00`。
- 「行数少的 fixture 无法检验角落记账」在危险方向上是错的：这种 fixture **确实**折入了一个常数，只是不是被预测的那一个。

而且只有**播种**的 fold 才在亏秩下把 (3.10) 恢复成 `c - b^T F^+ b = 6.105278`（且顺序无关）；单次堆叠给 `5.461211`（低 10.5%），fold 各阶给 `2.730011 ~ 6.100731`。这是原推导不知道自己需要的补救。

**这不是条件数问题**：`eps` 从 1 扫到 `1e-10`（`cond(F_joint)` 到 `1.2e20`），offset spread 一直钉在 `6.7e-16 ~ 1.3e-15`；只有 `eps = 0` 精确才跳到 `8.7e-1`。**必须是精确退化——而嵌入正是靠零填充精确地制造它。**

### 3.9 排序的真正风险：`names` 是元数据，列才是真相

`combine` 只比较 `names` 与 `shapes` 元组（本次实读 `sqrtinfo.py:173`），**从不检查任何一列**。于是它在两个项**对标签元组有分歧**时报警，在两个项**标签一致而列散射不同**时**沉默**。后者正是一个多数据集嵌入层会批量生产的东西——`E_i` 逐数据集计算，两条对「规范并集序」有分歧的代码路径会造出两个都如实自称 `("a","b","c")` 的项。

实测：`combine` **不抛任何异常**；log-density 正确 `-9.862721141` vs 错误 `-4.262783307`，gap **`5.599938 nats`** 且依赖 theta；`||F_wrong - F_ok||/||F_ok|| = 1.038`；秩 `5 -> 4`。**两个数都貌似合理，什么也不会亮。**

**由此得到的规则**：`U` 的规范序必须由**一个**函数、从**一个**声明产出，每个 `E_i` 都从它派生，**绝不从项自己的 `names` 反构**。而且嵌入层应当是并集框架项的**唯一**生产者，并随项发出一个**可检验的见证（column witness）**——它所占据的并集列下标元组——使后续 `combine` 校验散射而非标签。今天 `names` 携带不了这个信息（见 §9.2）。

## 4. 三种 nuisance 情形

### 4.1 情形 A：每数据集自有的 nuisance

平方根形式：把先验行堆到数据行下、一次 QR、丢掉前 `q_i` 行与前 `q_i` 列。

```
log L_i(theta) = [ o_i + (q_i/2) log 2pi - SUM_j log|U_bb,jj| - 1/2 rho^2 ]
                 - 1/2 || U_kk theta - w_k ||^2                             (4.1)
```

等价的协方差形式（**这是定义**，(4.1) 是它的平方根拼写）：

```
d_i | theta ~ N( A_i theta + c_i + B_i m_i ,  N_i + B_i S_i B_i^T )         (4.2)
```

选 (4.1) 的理由是条件数：`kappa(R) = sqrt(kappa(F))`，且 `F = R^T R` 不会跑出 PSD 锥。这不是修辞——对手在 `std` 从 `1e-8` 到 `1e10` 的扫描中，用 mpmath 60 位仲裁：**包的平方根路线全程精确到 `<= 1.4e-14`，而 dense float64 参考在 `std=1e8` 处已经错 `1.571e+00`，在 `1e50` 处错 `290 nats`**。任何人在宽 nuisance 先验下复现「差 `1.8e-15`」会误判包坏了。

**别名（aliasing）**：两个真正独立的局部 nuisance 被赋予同名同形，`combine` **接受**（名字与形状都匹配），按位置把列等同起来，模型静默变成「一个共享 nuisance，其先验被计了两次」。实测均值移动 `bias/sigma_honest = [+1.071, -0.658]`，宽度比 `[0.969, 0.991]`——**答案移了一个多 sigma 并且变窄了，没有任何东西说出来。**

**但两条附带说法被驳回了**（原 Q4 A3）：

1. 「`q_1 != q_2` 使 `combine` 抛 StructureError，所以 nuisance 维不等的 fixture 根本无法展示这个 bug」——**错**。正因为 `combine` 要求 `shapes` 元组相同，维不等的调用者**必须先 pad 到公共框架** `combine` 才可调用；pad 不是异国情调，它是强制的。实测 `q_1=2, q_2=1` pad 进宽 2 的共享 zeta：`combine` 接受，后验移 `[-1.388, -1.595] sigma`，宽度比 `[0.958, 0.944]`。**一个信这条失效条件的测试作者会去造那个恰好错过 bug 的 fixture，还相信 bug 不可能存在**——这正是本 programme 反复付账的「守卫已经不能再失败」的模式。
2. 「变窄」的归因是错的。变窄是**定理**（500/500 从不变宽，`min eig(F_alias - F_honest) = +9.5e-05`），但它成立**只因为被重复计的先验**使别名分母恰等于 `SUM_i M_i`。把先验只计一次（对真正共享的 zeta 才是正确计数），匹配就断了：300 例中 23 例别名项**信息更少**，宽度比高至 `1.0133`——**更宽**。所以「变窄」属于 (R2)（先验计数）而不属于 (R1)（列等同）。**在一个按 §5 建议、最后才施加一次共享先验的流式 API 里，这个签名会消失甚至反转。**
3. 「更移过一个 sigma」不是性质，是旋钮：400 个种子下 `max|bias|/sigma` 中位数 `1.004`，超过 1 sigma 的比例 `50.5%`（掷硬币）；随耦合强度连续变化（`Bscale = 0, 0.02, 0.1, 0.3, 1, 3, 10` 给中位数 `0.000, 0.0023, 0.0455, 0.233, 1.011, 3.266, 11.03`）。

**先验计两次 / 漏计**：计两次的 gap `-2.2324 nats` at `theta=(0.3,-0.2)` vs `-2.2136` at `theta=0`——**随 theta 变**，故不是常数、不可吸收。漏计时 gap 从 `2.290` 跑到 `3.446 nats`，**信息矩阵本身**差 `1.341`——形状错了，不只是常数。

**但「marginalise 无法侦测先验漏计」被驳回了**（原 Q4 A4）：当先验真正在起作用时它**会**拒绝。实测三例全部「有先验→接受、无先验→拒绝」：`n=3,q=4` 与 `n=2,q=3` 触发形状检验（`sqrtinfo.py:328-338`）；**`n=6, q=2` 且 `B` 秩 1** 触发 **pivot 检验本身**（`sqrtinfo.py:387-395`）——六行数据对两列 nuisance 不是饥饿 fixture，只要有一个退化方向就够，而那正是给 nuisance 装先验的标准理由。原论断的前提「数据自己就约束住它」是一个**未陈述的假设**（`B_i` 列满秩且行足够独立）。

同样被驳回的还有 A4 的失效条件本身：先验计错的 **theta 依赖部分** 恒为零当且仅当 `A^T N^-1 B = 0`（白化下 theta 设计与 nuisance 数据足迹正交），**不是**「先验的对数密度为常数」。实测在该条件下，计两次的 gap 在五个 theta 上都是 `-2.139321273`，漏计都是 `+2.462173312`，且 `info(omit) - info(correct) = 0.0` **精确**——后验完全不动，全部误差是一个**范围外的** evidence 常数。边界双向扫描：泄漏 `eps = 0, 1e-8, 1e-4, 1e-2, 0.1, 1` 给 theta-spread `0.0 / 4.0e-8 / 4.0e-4 / 3.2e-2 / 0.51 / 83.2`——在真条件处精确归零，连续。

### 4.2 情形 B：被若干数据集共享的 nuisance（不感兴趣）

真值只积一次，乘积形式积了 `|S|` 次：

```
F_true = SUM_i Gt_i^T Gt_i - (SUM_i a_i)(tau^{-2} + SUM_i k_i)^{-1}(SUM_i a_i)^T
F_prod = SUM_i [ Gt_i^T Gt_i - a_i (tau^{-2} + k_i)^{-1} a_i^T ]
Delta  = F_prod - F_true                                                    (4.3)
```

`a_i = Gt_i^T v_i`，`k_i = v_i^T v_i`。公式对真实 `SqrtInfo` 流水线返回的信息矩阵验证到 `<= 1.5e-12`（`N = 2, 8, 32`）。符号与 N 标度的**更正**见 §2.8：`Delta` 不定号，零点是一个平衡条件而非 `|S|=1`，控制量是 `SUM_i a_i` 的相干性。

**两条正确的处理**：

**路线 (i)：把共享 nuisance 提升进共享列集。** 并集框架 `(zeta, theta)`，宽 `p + q`（**不是** `p + |S| q`），先验只加一次，最后（或永不）积掉。对 dense `N_tot + tau^2 u u^T` 验证：均值 gap `2.2e-16`，精度 gap `7.1e-15`。**每个项宽度不变**，所以 `lax.scan` 的 carry treedef 稳定，仍然是流式方案；数据仍然被丢弃（每数据集仍然从 `n_i` 行降到至多 `p+q` 行），只是最后那次积分被推迟。**这是默认选项。**

**路线 (ii)：在共享子集 `S` 上联合边缘化。** 当且仅当三条同时成立：`S` **封闭**（`S` 之外没有数据集碰 `zeta`）；`S` 全体**同时驻留**；`zeta` 的先验**没有被推断的超参**。QR 累积不可稳定地反演（这也是 leave-one-out 要从 archive 算而不是「减掉」的原因），所以**这个归约不可撤销**：晚到的、也共享 `zeta` 的数据集要么被丢弃，要么整个 `S` 从原始数据重压——而流式设计里原始数据已经没了。**路线 (i) 挺得住晚到，路线 (ii) 挺不住；这就是把 (i) 作为默认的理由。**

**为什么这件事无法从存储的项里侦测**（两个独立证明，都实测）：

- **证明 1：错项就是另一个模型的对项。** 把共享 `zeta` 错误地逐数据集积掉得到的项，与「数据集 1 真的有自己的 `zeta_1 ~ N(0,tau^2)`」这个**不同模型**诚实压缩出来的项，`factor / target / offset` 三者 `max|diff| = 0.000e+00`，**逐位相同**，`names` 都是 `('theta',)`。所以 `(model, data) -> term` 不是单射，正误落在同一纤维里，**任何存储项的函数**都不可能分开它们。区分信息在 (4.1) 丢列的那一刻被销毁。
- **证明 2：偏差恰好落在残差看不见的地方。** 零方差极限（一次固定的定标误差 `c` 施加于每个数据集）：把 `c` 分解为白化设计列空间内的 `c_par` 与正交的 `c_perp`。`c_par` 被 theta **精确吸收**——均值移动等于 `D^+ c`（`1.9e-16`），每个残差向量**不变**（`8.9e-16`），残差卡方**逐位相同**（`139.190873302390742` 两边）。而 `|bias|` 与 `N` 无关（每个 `N` 都是 `0.19170`），`sigma ~ N^{-1/2}`，于是 `bias/sigma = 1.16, 2.33, 4.66, 9.32, 18.65, 37.29` at `N = 1,4,16,64,256,1024`（log-log 斜率 `0.50002`）。`c_perp` 在每个 `N` 上产生**精确零**偏差，而且是唯一抬高卡方的部分（`chi2/dof` `1.101` vs `0.881` at `N=16`）。**诊断能看见的那部分恰好无害，造成伤害的那部分恰好不留痕。**

  诚实的收窄：proper theta 先验下吸收不精确，卡方差 `6.7e-06` 于 `139.19`（相对 `5e-8`）。**存在痕迹，不构成探测器。**

  （常被引用的「N=640 时 52.6 sigma」出自上游 map，**卷宗中无人重算，标记为未验证**。上面这些数字是本次卷宗算的。）

**但请与 §2.5 对读**：证明 2 说的是**存储项之后**没有统计量。§2.5 说的是**压缩之前**、用固定 theta 处的仿真**有**统计量（秩一尖峰 `226.36` vs `13.63`）。两者不矛盾，卷宗从未把它们放在一起说过。**设计后果是明确的：跨 graph 共享结构的探针必须在压缩之前跑，之后不可能。**

### 4.3 情形 C：层次结构，`zeta_i ~ p(zeta_i | eta)`，`eta` 共享且被推断

定理 1 的推导**完全不受影响**（§2.2 第一步已说明）。变的是**哪些常数还是常数**：

```
log L(theta, eta) = SUM_i log N( d_i | A_i theta + c_i , N_i + eta^2 B_i B_i^T )
```

`log det(N_i + eta^2 B_i B_i^T)` 是 `eta` 的函数。按 §5 的判据它**不是常数**，必须携带。实测（`p=2, q=2, N=6, n=10`）：

| eta | 正确 log L | 在 `eta_0=1.0` 处 pin 住的 log L |
|---:|---:|---:|
| 0.3 | -140.559089 | -73.702020 |
| 1.0 | -73.702020 | -73.702020 |
| 1.3 | -72.127143 | -73.702020 |
| 6.0 | -83.663389 | -73.702020 |

`d logL/d eta` at `eta=1.3`：正确 `1.492583`，pin 住 `0.000000`——**恒等于零，因为 `eta` 不在那个对象里**。后果：返回的 `eta` 后验**就是 `eta` 先验**，无任何警告；theta 后验是 `p(theta|d, eta_0)` 而非边缘（在 `eta_0=0.5` 相对 `eta_MAP=1.4073` pin 时移 `[-0.227, +1.062] sigma`，sd 比 `[0.989, 0.969]`）。正确构造恢复 `eta_MAP = 1.4073`（真值 1.3）、`eta_mean = 1.5014`、`eta_sd = 0.3466`。

**正确构造**（每次 likelihood 求值，即每个 leapfrog step）：由 `eta` 建先验行 `[I/eta | 0]` 与 offset `-q_i log eta - (q_i/2) log 2pi` → 堆到存储的 `(R_i, z_i)` 下 → 再三角化 → `marginalise_arrays(., n_block=q_i)`（**不是**受检的 `marginalise`，后者会 concretise）→ 求和 → 最后加一次共享先验。对 dense 验证 gap `<= 6.5e-13`（`eta ∈ {0.3,0.7,1.0,1.3,2.5,6.0}` × 两个 theta），`jit(grad(., eta))` 返回 `1.4925825885869877`，与 eager 相同。

这与 `bayesmith/evidence/chain.py` 的做法**架构完全一致**：`LinearGaussianTransition`（数值，滤波可以只跑一次）vs `HyperTransition`（builder，`.at(values)` 在 theta likelihood 内部解析）。本次实读确认两者都有 `hyper: tuple[str,...] = eqx.field(static=True, default=())`（`chain.py:103` 与 `:230`），`_plan` 在 `chain.py:335` 调 `transition.at(values)`。**区分必须活在 TYPE 里，不能活在注释里**——`chain.py` 的 docstring 自己说明了陷阱：「an OU chain with an INFERRED correlation time is still linear-Gaussian, so a caveat phrased that way is satisfied while its claim fails」。同一个陷阱逐字适用于 `zeta_i ~ N(0, eta^2)`。

**但「这种项永远不可压缩」被驳回了**（原 Q5 §5.2/§6 tier 2「Not storable, ever」）。对手用**已发货的代码**推翻：`chain_marginal(blocks, HyperTransition(...), values, ...)` **返回一个 `SqrtInfo`**，其 `offset` 由 `_initial_log_norm`、`_transition_log_norm` 与 `marginalise_arrays` 的 `-sum(log pivots)` 累积而成，实测在 `log_tau = -0.5, 0.0, 0.7, 1.5` 上为 `-6.8374017997, -7.0312473877, -7.2987004172, -7.5508255722`（跨度 `1.0146 nats`），`jax.grad` 给 `-0.3566732830`（有限差分 `-0.3566732829`），并可 `jit`。机制：`sqrtinfo.py:72-74` 里 `factor/target/offset` 是**动态** pytree 叶子（只有 `names`/`shapes` 是 static），所以它们可以是 tracer；「construction」在每次势能求值时发生一次。

对手还独立造出了一个**保留充分统计量的压缩**：丢掉原始数据、只留 `(A^T A, A^T d, d^T d, A^T G, G^T d, G^T G)` 共 **25 个数、与 n 无关**，由 Woodbury 每次重建 `SqrtInfo`，把 `-0.5 logdet(2 pi C(s))` 放进 `offset`。对 dense 边缘似然吻合 `0.0 ~ 7.1e-11`，`n=20000` 时相对 gap `1.15e-14`，存储仍是 25 个数。

**更正后的边界**：不是「数据类型 vs 函数」，而是

> **在压缩时求值一次（pin 住）** vs **每次求值时从保留的充分统计量重建**。

这个区分改变设计后果：**§3.2 的「累积器宽度由并集宽度决定」对 builder-backed 项不成立**——它们的 `R` 随 theta 移动，**不能** QR 折进 `R_E`，必须逐数据集保留、在每个 leapfrog step 组合。这一点卷宗任何一处都没有。

### 4.4 profiling vs marginalising

对线性-高斯 nuisance：

```
log L^prof(theta) - log L^marg(theta) = +1/2 log det( H_zeta / 2 pi ) ,
H_zeta = B^T N^{-1} B + S^{-1}                                              (4.4)
```

`H_zeta` 不含 `theta`，所以这是常数，**profiling 与 marginalising 给出相同的 theta 后验**。实测差为 `1.896853125785` 在 `theta = [0,0], [0.4,-0.7], [3,-2]`，`1.896853125786` 在 `[-5,7]`，对闭式 `1.8968531257850412`。

**`H_zeta` 一旦依赖 theta 就不再是常数**：非线性 `mu(theta, zeta)`、theta 依赖噪声（`sigma = f|mu(theta)|`，radiometer 情形，rheplicant 的常态）、或 theta 依赖的 nuisance 先验宽度。实测 `S = e^{2tau} I` 时该 gap 变为 `-1.5817, -1.3866, -1.3043, -1.2722, -1.2601`（`tau = -0.5..1.5`），tau 后验 mode `-0.2800`（marginal）vs `-0.3700`（profile），sd `0.4915` vs `0.5271`。

**这是本文最锋利的退化 fixture 警告**：**固定 nuisance 宽度的 fixture 同时看不见** (a) profile vs marginal 的差别、(b) 缺失的 `-SUM log std`、(c) 缺失的 pivot 和——三者在那里都是 theta 无关的。本 programme 历史上记录的三个 nuisance 归一缺陷全部躲在这后面。

## 5. 共享先验只施加一次，以及哪些归一化到达后验

### 5.1 判据

> **R2**。一个量可以从后验计算中丢弃**当且仅当**它在支撑上 `d/d theta` 恒为零。其余的都不是常数，是形状的一部分。

**不是**「evidence 需不需要它」。这个替换是 §0.3 指出的 docstring 作废的原因。

### 5.2 一个先验，只用一次

两种个别正确的约定：

```
streaming :  p(theta|d) ∝ p(theta) PROD_i L_i(theta)              存储项 s_i = 0
consensus :  p(theta|d) ∝ PROD_i [ p(theta)^{s_i} L_i(theta) ],   SUM_i s_i = 1，末端不加先验
```

`rheplicant` 的 `prior_share` 就是 `s_i` 的编码，本次实读确认它是 `tuple[int,int]`（`compressed.py:199` 附近，整数对而非浮点，理由写在源码里：浮点让「shares sum to exactly 1」成为一个真值取决于求和顺序的谓词），`memory.py:219-226` 拒绝任何 numerator 非零的项，因为 `log_posterior` 实现的是 streaming 约定。**混用两者才是 bug。**

设每项带 share `s_i`、访问器再加一次先验：

```
log p_hat = SUM_i log L_i + (1 + SUM_i s_i) log pi(theta)                    (5.1)
```

指数 `k = 1 + SUM_i s_i`。高斯形式：`F_wrong = SUM_i F_i + k F_pi`。

### 5.3 **被驳回**：`k` 折先验误差的三条描述

原 Q3 C1/C2/C3 的规范性规则（存储项在共享 latent 上必须无先验）**站住**，但三条描述被驳回：

**(1) 「这必定是 theta 依赖的误差，不是 evidence offset」是假的。** 对**在后验所在处平坦**的先验，`(k-1) log pi` 是常数，误差**恰是** evidence offset。而 `rheplicant/inference/graph_bridge.py:428` 的 `_flat_prior_for` 对每个被 `Graph.joint_prior` / `JeffreysPrior(over=...)` 覆盖的 latent 返回 `ImproperUniform`（本次实读确认该函数存在于 `:428`）。实测（400001 点网格）：`pi = 1` 时 `k = 1, 2, 4` 后验 mean `+0.703475460803909` 与 sd `0.074510766465945` **逐位相同**，`log Z` 也不动；`Uniform[-8,8]` 时后验同样逐位相同，只有 `log Z` 按 `(k-1) log 16 = 2.7725887222` 每单位 k 移动。这正是 R2 判据反过来打在原论断身上。

部分平坦给出第三种形状：先验对 `t1` 平坦、对 `t2` proper 时，误差**只在 `t2` 上**（`t1` 的 mean 1.0、sd 0.5 在 `k = 1, 2, 5` 上精确不变）。

**(2) `k = 1 + SUM s_i` 这个机制公式假定了一个本文场景明确否定的同质性。** 本文的设定里 `G_i` 只对自己的 latent 声明先验，而 `prior_share` 是一个**标量** `tuple[int,int]`，挂在 `latents = info.names` 的项上——它**表达不了** `pi_full^{s_i}` 当项只覆盖一个子集时。实得的是 `SUM_i s_i log pi_{A_i}(theta_{A_i})`，对任何 `k` 都不是 `k log pi(theta)`。实测（相关共享先验 `rho=0.8`，`G_1` 只约束 `t1`、`G_2` 只约束 `t2`）：实际超额与 `k` 公式差 `+0.408113, +2.942835, +0.630335, +7.442835 nats`——**不是常数，所以连「相差一个 offset 的同一个函数」都不是**。更要命的是 C1 陈述的逃生通道（「consensus 约定下 `s_i != 0` 是对的」）在此**为假**：`s = (1/2,1/2)`（`SUM = 1`）给后验均值 `[0.8888888889, -0.4736842105]` 对真值 `[0.4955489614, -0.2885756677]`（偏 0.99 与 0.62 sigma），且**每一个 consensus 变体的后验协方差非对角元都精确为 `0.000000`** 对真值 `+0.029674`——**数据集彼此不再联合约束任何东西**，而这正是本文要推导的事情。

**(3) N 标度的两条陈述都缺一个承重假设。** 「`k=N` 时均值冻结、差异按 `sqrt(N)` 发散、宽度误差有界」只在 **`SUM_i F_i` 关于 N 线性增长**（每数据集信息有下界离零）时成立。对手用推导**自己认证的**情形推翻它：`G_1` 有信息、`G_2..G_N` 在 theta 上无内容（§6.5 证明它们对真后验贡献为零，§4.2 说它们的正确表示在并集框架里，所以仍各带一份 `pi`；机制由 `graph/evaluate.py:164` 的 `log_joint` 无先验/似然标记地对全部 Probabilistic 节点求和所确保）。实测到 `N = 65536`：均值**不冻结**（`2.599608 → 0.000159`，一路被拖到先验均值）；`|shift|` 饱和在 `2.599608`（是被声称上限的 3.00 倍）；`shift/sigma` **收敛**到 `3.0016`；而 **`sd_w/sd_t = 2/sqrt(N) → 0.007812`，宽度误差才是无界的那一个**。次线性情形同样反转（`f_i = 1/i` 时发散是 `sqrt(log N)`；`f_i = 1/i^2` 时 `shift/sigma` 收敛而 `sd` 比 × `sqrt(N)` 收敛到常数）。

`k = 2` 情形（`prior_share` 碰撞）的「按 `1/sqrt(N)` 衰减」同样被驳回：控制量是 `u = N f1/f_pi` 而非 `N`，`shift/sigma = sqrt(f_pi/f1) * D * h(u)`，`h` 非单调，峰值 `h(u*) = 0.3002831060` 在 `u* = 1+sqrt(5) = 3.2360679775`。实测峰值 `0.300, 0.950, 3.003, 9.496, 30.028, 300.283` 于 `f_pi/f1 = 1, 10, 100, 1e3, 1e4, 1e6`——**先验比单个数据集紧 100 倍的 campaign 在 `N = 32000` 处会看到 30 sigma 的 `k=2` bug**。而且子集共享时宽度比**不趋于 1**：`t2` 的 `shift/sigma = 0.541820` 与 `sd_w/sd_t = 0.816497 = sqrt(2/3)` 在 `N = 1 ... 10^6` **六个数量级上逐位不变**。

**保留下来的规范性内容**（这是承重的，且经受住了全部攻击）：

> **R1**。存储项是 `L_i(theta)`，在每个共享 latent 上**无先验**。共享先验是**分析**的属性，不是任何数据集的属性，由求值后验的那一方施加一次。等价地：streaming 累积中每项 `prior_share = (0,1)`；consensus 累积中 `SUM_i s_i = 1` 且末端不加。**绝不两者兼有。**
>
> 并且：**总先验指数必须恰为 1**，而偏离在 `log pi` 非常数处是 theta 依赖误差。「无先验项」是充分实现之一，不是唯一。**在子集共享的一般情形下，标量 share 无法正确编码任何 consensus 约定**（上面 (2)），所以多数据集设计应当默认 streaming。

失效条件：R1 只管**共享**框架里的 latent。真正局部于 `G_i` 的 latent **必须**把先验带进 `L_i` 内部——那正是使 `L_i` 成为边缘似然的东西。压缩前把 `G_i` 的所有先验剥光会造出不适定、通常发散的 `L_i`。而且这个二分**在唯一能遵守它的时刻不可判定**：今天局部、其先验被折进项里的 latent，在后来某个数据集也约束它的那一刻变成 `k=2` 误差，而项本身没有变。

### 5.4 三个 offset 重组成一个 log-determinant

```
R_bb^T R_bb = B^T N^{-1} B + S^{-1}
=>  SUM_j log|R_bb,jj| = 1/2 log det( B^T N^{-1} B + S^{-1} )
    -SUM_j log std_j   = -1/2 log det S                    (仅 S 对角时)
```

由矩阵行列式引理：

```
-1/2 log det(2 pi C)  =  [-1/2 log det(2 pi N)]      <- compress 自己的归一
                       + [-SUM_j log std_j]          <- nuisance_prior 存活的一半
                       + [-SUM_j log|R_bb,jj|]       <- marginalise 的 pivot 和      (5.2)
```

实测 LHS `-10.577783077210464`，RHS `-10.577783077210466`，差 `1.8e-15`。

**(5.2) 是本节全部内容**：单一的量 `-1/2 log det(2 pi C_i)` 在 bayesmith 里存成**三个函数里的三个独立 offset**，所以 §5.5 的分类必须逐个施加，**不能施加到和上**。

**对手对 (5.2) 的攻击全部失败**（约 35 个配置：`q>n`、`rows<width`、masked 行、秩亏与零设计块、多名混形 nuisance 至 `q=10`、circulant 相关噪声、`std` 从 `1e-300` 到 `1e150`，全部 `<= 2e-15`）。**但需要四条修正**：

1. **`S` 必须对角**——原文未述且有后果。`-SUM log std = -1/2 logdet S` 只对对角 `S` 成立；相关 `S` 下误差高至 `1.611920 nats`（equicorrelated `rho=0.99`）。今天安全只因为 `nuisance_prior` 建的是 `diag(1/std)` 且 `campaign.py:106` 每名读一个标量。**但 `Graph.joint_prior` 正是相关先验的词汇**，而本文是一般数学。一般形式是行列式版本：行取 `S^{-1/2}`、offset 取 `-1/2 logdet(2 pi S)`。
2. **masking 下 `N`、`C` 与 `2 pi` 计数都在 SEEN 子空间上。** 对全维 `C` 检验时误差 `4.540 nats`，对 `C_seen` 精确（`0.0e0`）。
3. **improper 先验的注意事项原文说反了**：60 位 mpmath 下两边一同发散、无残差（`std=1e150` 时二者都 `-1042 nats`，差 `<= 1.2e-13`），极限是一致的。真正危险的是 **`q > n` 且平坦先验**，此时一个 pivot 精确为零、两项一起发散给 `nan`。
4. **pivot 必须取 `abs`**：LAPACK 不把 `diag(R)` 归一为正（实测符号向量含 6 个负号），不取 `abs` 的 `log` 返回 `nan`。原文引用的具体符号向量是 fixture 特有的。

另外一个调用者可以踩、而推导没点名的坑：`marginalise_arrays` 把 `n_block` 当自由整数收，`n_block < q` 会把「对全部先验行求和的 term2」配上「只对前导 pivot 求和的 term3」，静默失衡。`compress_epoch` 总是让两者一致，所以在用的入口是安全的。

**theta 无关（丢弃对后验精确无影响，这是恒等式不是近似）——每条各带自己的钉住条件：**

| # | 量 | 位置 | theta 无关的前提 |
|---|---|---|---|
| I1 | `-1/2 SUM_{seen} log(2 pi sigma_j^2)` | `compress.py:143` | `N_i` 不依赖 theta |
| I2 | `-1/2 rho^2`（`combine` 角落） | `sqrtinfo.py:193` | 两个 factor 的行都 theta 无关 |
| I3 | `-1/2 rho^2`（`marginalise_arrays` 内） | `sqrtinfo.py:249` | 同上，且 `S_i` 钉住 |
| I4 | `∓(n_b/2) log 2pi` 一对 | `compress.py:258` / `sqrtinfo.py:247` | **仅在被积块恰是带先验行的整块时相消**（§3.4(a)） |
| I5 | `-SUM_j log(std_j)` | `compress.py:253-256` | `S_i` **钉住**；且**净额在 `ker(B)` 上与 std 无关**（§3.4(b)） |

对手用**真实包路径**验证：`DiagonalPrecision(sigma=0.30)`（`N` 钉住）、`nuisance_prior_std = ones`（`S` 钉住）、`B = diag(nu^-gamma) B0`，`marginalise` 的 pivot 和从 `-21.107` 移到 `-17.581 nats`（`gamma: 0.0 → 2.8`），(5.2) 三分解吻合 `1.6e-14`。后验伤害：`shift/sigma = -0.335, -0.403, -0.767, -1.419, -3.109, -4.182` at `N_ds = 1, 4, 16, 64, 256, 512`，log-log 斜率 `0.428`，而**宽度一致**（`sd_drop/sd_keep = 0.999`）——所以每数据集卡方全清白，伤害是纯偏差。控制组（`B` theta 无关）在每个 N 上 shift 精确 `0.000e+00`。

同一驳回还打掉「推断 nuisance 宽度下 I1+I5+I6 是同一个 log-det 的三块，所以**两个**同时活化」：I6 可以**单独**活化（实测 I1 恒 `6.8408225069`、I5 恒 `0.0`，I6 移 `1.17 ~ 3.53 nats`）。

### 5.7 两个 graph 对同一共享 latent 声明了不同先验

`pi_1 = N(0,1^2)`、`pi_2 = N(2,0.5^2)`：

- **乘积读法**：mean `+1.600000`，sd `0.447214`——**比两个声明中更紧的那个还紧**（`0.447 < 0.500`），且中心不在任一均值。**零数据「学到」了东西。** 表面上就站不住。
- **几何/consensus 读法**（`s=1/2`）：mean `+1.600000`，sd `0.632456`。这是一个合法的正规化密度，也正是 `prior_share` 编码的东西。**但它回答的是另一个问题**：它是把**一个已达成一致的先验**拆给若干并行 worker 的正确机制，不是调和**两个分歧信念**的机制。
- 8 个单位设计样本、`ybar=1.0` 下四种读法的后验均值：`+1.230769 / +1.142857 / +0.888889 / +1.333333`——在 `N = 1` 个数据集时就差 1.2 个后验 sigma。

**规则 R4**：**拒绝，不要调和。** 论据不是数值的，是先验**是什么**：`p(theta)` 是在看到任何 `d_1..d_N` 之前对 `theta` 做出的陈述，一个联合分析里**恰有一个**这样的陈述。两个不同的陈述是模型规格里的**矛盾**，不是待合并的数据。悄悄选一个、相乘、或平均，都是在回答用户没问的问题，而答案是有限的、形状正确的、错的。不要提供带默认值的 `reconcile=` 开关。

**R4 的失效条件（比原推导多两条）**：

1. 「不同」必须按**密度**判定而非按**对象**：`trace.py` 的 `_owner` 刻意拒绝跨 trace 的 `NodeRef` 身份，所以两个 `Normal(0.0, 1.0)` 节点是不同对象、同一先验。相等性必须是结构的（分布族 + 参数数组），而浮点比较会在来自不同算术路径的值上产生伪拒绝。
2. **（本文新增，卷宗无人发现）朴素谓词会拒绝本包强制的配置。** `diagnose/priors.py:71-73` **要求**被 `JeffreysPrior(over=...)` 覆盖的 latent 声明为 `ImproperUniform`，而另一个不带该 Jeffreys 先验的 graph 会把同一 latent 声明为 proper。**这是本包自己支持的配置里被强制的分歧。** R4 的谓词必须知道「一个 graph 的 `joint_prior` 覆盖了这个 latent」这件事，把被覆盖 latent 的 `ImproperUniform` 声明当作**没有声明**，而不是当作一个相冲突的声明。
3. 今天 bayesmith 里**没有任何东西比较两个 graph 的节点**，所以这个检查无家可归；而 `Distribution` 对象是否有结构相等也未经确认（本文未查）。

## 6. 精确的与近似的

### 6.1 精确

1. **零填充嵌入**（§3.1）：`R_i E_i` 与 scatter 逐位相同（有限元素下），不引入耦合。
2. **QR 组合**（§3.2）：`U^T U = G` 精确；我本次实测 gap `0.000e+00`、`F` 相对 `2.806e-16`。
3. **不相交局部 nuisance 的边缘化与组合可交换**（§3.7）：`7.1e-15 ~ 1.4e-14 nats`。**操作上的注意见 §3.7.1。**
4. **共享 nuisance 提升进共享块**（路线 (i)）：均值 `2.2e-16`、精度 `7.1e-15`。
5. **一致置换与 fold 顺序**：物理点上 `log_prob` 逐位不变（**除非联合精确亏秩，那时 `offset` 不是良定义的——§3.8.1**）。
6. **层次 `eta` 在 likelihood 内解析**（§4.3）：`<= 6.5e-13`，可 `jit`、可 `grad`。
7. **线性-高斯 nuisance 的 profile = marginal**（`S` 钉住时，§4.4）。
8. **三个 offset 重组成一个 log-det**（(5.2)，`1.8e-15`，附四条修正）。

### 6.2 近似，按后验保真度分层

**Tier 1 —— 处处精确的后验**

1. **精确可存储项**（在其携带的参数上线性-高斯，nuisance 闭式积掉）。丢失：原始数据与重建模能力。代价 `O(width^2)` 每次求值，与 `n_i` 无关。
2. **不压缩，活在势能里**。什么都不丢，代价是每个 leapfrog step 一次完整前向 + 梯度，且原始数据必须永久保留。混合 NUTS 实测与 (1) 不可区分：mixed mean `[0.33003, -0.67076]` sd `[0.09777, 0.10383]`，full mean `[0.33084, -0.67244]` sd `[0.09635, 0.10346]`，差 `[-0.0084, +0.0163]` 后验 sd 对 MCSE `~0.029`。

**Tier 1.5（本文新增，由 §4.3 的驳回产生）—— builder-backed 精确项**
保留充分统计量（与 `n_i` 无关的固定和），每次求值重建 `R, z, offset`，其中 offset 携带 theta 依赖的 log-det。**精确**（`n=20000` 时相对 `1.15e-14`）。丢失：**并集折叠的能力**——它不能 QR 折进 `R_E`，必须逐数据集保留。这个 tier 在原 Q5 的分层里根本不存在，而 `chain_marginal` + `HyperTransition` 就坐在这里。

**Tier 2 —— 精确到 `O(1/n)` 抑制的受控误差**

3. **对 nuisance 做 Laplace、保持活的**。线性-高斯 nuisance 下精确（此时它就是 (4.4) 的重排）。携带 theta 依赖 log-det，必须可微分穿过。
4. **profile nuisance**。`H_zeta` theta 无关时与 marginal 在 theta 上**相同**；否则丢掉 (4.4)——一个移动众数的 theta 依赖 Occam 项。**标签必须说明是哪一种。**

**Tier 3 —— 只在展开点附近是后验**

5. **theta 上的 Laplace，压缩存储**。保留 `L_i` 的一个位置与一个曲率，别的全丢。**要求 `L_i` 有真正的极大值——而多数据集分析里的单数据集项通常没有**：实测秩 1 设计对 2 维 theta，`information` 特征值 `[2.14e-17, 4.91032]`，`slogdet(H)` 给 sign `0.0`、logabsdet `-inf`，`log_prob` 沿零方向在 `c = -50, 0, +50, 1e4` 处全是 `-8.2622444081`（**平脊延伸到 1e4 以外**），而项本身对 dense 参考精确到 `1e-15`——这是 Laplace **程序**的缺陷，不是表示的缺陷。作为**后验贡献**退化的伪 Laplace 仍然可用（`H(theta-theta^)` 对沿零空间滑动 `theta^` 不变）；坏掉的是找 `theta^`（无界优化）。自然的补救——用先验正则化——把 `pi` 放进项里，正落在 §5.2 的 `pi^{k+1}` 上。
6. **在选定 `theta_0` 处线性化，压缩存储**。只在 `B(theta_0, rho_i)` 内保留后验。**一旦数据没了，外面的部分静默且原则上不可侦测。**

**5 与 6 的排序是条件性的，不是全序。** `L_i` 在 `S_i` 的每个方向上都信息充分且大致高斯时，5 在上（其展开点由数据决定，不会被选坏）；`L_i` 弱或在某些方向亏秩时（**多数据集的常态**），5 根本没有展开点而 6 的切模型良定义、信赖半径可算，于是 6 在上。**没有对两者都成立的排序。** 而且联合后验远离两个展开点时（后来某数据集主导），两者都错，只有重新线性化有用——而数据已经没了。

### 6.3 线性化：误差、score 恒等式、信赖半径

`Delta(theta) := log L - log L~ = et^T w - 1/2 ||w||^2`，`w = N^{-1/2}(mu - mu~)`，`et = N^{-1/2}(d - mu~)`。求导：

```
d Delta/d theta = (d-mu(theta))^T N^{-1} J(theta) - (d-mu~(theta))^T N^{-1} J(theta_0)   (6.1)
```

——**真模型的 score 减去切模型的 score**。对 `Delta` 的中心差分验证：相对 `5.9e-9, 1.7e-10, 1.1e-10, 8.1e-11, 4.0e-9`。

**记录一次失败**：更整洁的单项形式（只留 `(d-mu)^T N^{-1}(J(theta)-J(theta_0))`）**是错的**，与有限差分差 1.2 到 207 倍。作者写了它、跑了它、它失败了。**一个从未求值过的符号推导正是本 programme 最常发现出错的东西。**

**(6.1) 的失效条件被驳回并更正**（原 Q5 C6）。原文写「对任何可微 `mu` 都是恒等式，所以不会失效」——限定词只加在 `mu` 上。它还**默默要求** (i) 有效协方差 theta 无关、(ii) 切映射与 score 写在同一坐标里。两者在本文档指名为活跃的场景里都被破坏：

- **Radiometer 噪声** `sigma_k = f|mu_k(theta)|`（§4.4 自称是 rheplicant 的常态）：可存储的切项必须同时冻结 `mu` 与 `N`。实测 9 个格点，两种 `N` 读法都失败（相对 `0.38 ~ 1.38`），9 个中有 7 个至少一个分量**符号错**。
- **nuisance 先验宽度本身是共享 latent**（§5.5 的 D1，明确要求携带）：`mu` **仿射**，切映射精确，(6.1) 依然预测**恒等于零**，而真值 `d/ds = 10.0332148351`（闭式）/ `10.0332148483`（有限差分）。(6.1) 没有任何一项能看见 `dC/dtheta`。
- **坐标不匹配**（切模型在 `u = log a` 上仿射、score 写在 `a` 上）：相对 `0.038 ~ 1.28`，含符号翻转。

**更正**：(6.1) 的 `N` 是**有效协方差**且必须 theta 无关；不满足时该数据集按 §4.3/§6.2 属于 Tier 1.5 或 Tier 1(2)，**根本没有线性化项可诊断**。

**Gauss-Newton 丢掉的曲率**：

```
F_true = F_GN - SUM_k (d_k - mu_k)/sigma_k^2 * d^2 mu_k/d theta d theta^T   (6.2)
```

实测 `F_GN = 34.142415`，丢掉项 `-0.656354`，和 `34.798770`，对 2e6 点求积 `34.798902`（相对 `3.8e-6`，受求积限制）。**这一项有符号**：线性化的宽度可能太窄也可能太宽（实测 sd 比从 `1.0298` 到 `0.5351`）。**任何「线性化是保守的」的说法都是假的。**

**信赖半径，且它随 n 收紧**：

```
|shift| / sd_post  <=  ||et|| * ||dJt||/||Jt||  +  ||w||                    (6.3)
sqrt(n_i) * (后验主体上的相对 Jacobian 漂移) << 1   且   ||N^{-1/2} r|| << 1   (6.4)
```

实测诊断量 `sqrt(n)||dJ||/||J|| = 0.053, 0.518, 0.880, 2.107, 3.586, 5.108` 对应众数误差 `0.002, 0.029, 0.015, 0.337, 1.663, 5.649` 后验 sd。

**`sqrt(n_i)` 是要害且反直觉**：线性化偏差不随数据增多而缩小，而 `sd_post` 按 `1/sqrt(n_i)` 缩小。**数据越多的数据集，其信赖半径必须越紧。** 在 pilot night 上安全的容差在 campaign 上不安全。

**与 `exact/linearity.py` 的 `WEIGHTED_RTOL = 1e-3` 的关系**：那个常数回答的是**另一个问题**——模型**是不是**仿射（诚实答案是处处零偏离），而且它在**先验** sd 的倍数 `DEFAULT_SCALES = (1e-3, 1, 1e3)` 上探测。本文的问题是一个**已知非线性**模型的切平面在**后验主体**上够不够好——一个那个分类器从不看、且在压缩时还不存在的区域。本包没有这个常数，而且由 (6.4)，正确的那个**不是常数**，是 `O(1/sqrt(n_i))`。

**危险在于它从存储对象里不可见**：实测 `theta_0 = 4.0`（众数错 5.6 sd）时 factor 形状 `(40,1)`、全有限、`information = 122.1066`（对比 `theta_0 = 0.7` 的 `32.9394`）——**坏项读起来比好项约束得更好**。`offset` 在 `theta_0 = 0.7, 2.5, 4.0` 上**完全相同**（`-36.7575`），因为 `compress` 的 offset 根本不依赖设计。而 `SqrtInfo` 的字段里**没有 `theta_0`**。

### 6.4 混合累积（k 个精确 + N−k 个不精确）

```
U(theta, {zeta_i}_{i in X})
  = - log pi(theta) - [ O_E - 1/2 || R_E x(theta) - z_E ||^2 ]
    - SUM_{i in X} [ log p(d_i|theta,zeta_i) + log p(zeta_i|theta) ]        (6.5)
```

`numpyro.factor` 精确进入势能：`log_density` 对 dense 参考 gap `0.00e+00 / -2.13e-14 / 8.53e-13 / -6.82e-13`；`potential_energy` 在非约束空间与 `-(log_density + log|dA/du|)` 差 `1.11e-16`。

**但「U 是负对数联合后验、加性常数恰为零」被驳回了**（原 Q5 C3）。`U` 是负对数**未归一化联合密度** `p(theta, zeta_X, d_1..d_N)`，与后验相差 `-log p(d_1..d_N)`——**正是范围修正拿掉的那个量**。实测：`U - (-log 联合) = 1.4e-14 ... 5.7e-14`（作者的算术是对的），而 `U - (-log 后验) = -37.631038` 在四个点上都一样，且闭式 `log p(d) = -37.6310381769`，Laplace 独立复核 `-37.6310381406`。**原论断唯一的内容就是那个常数，而它在那一维上错了。它只在 `p(d) = 1` 时成立**（例如 `N = 0`——恰是它什么也没断言的那个 fixture）。

**更正**：`U` 是精确的负对数**联合密度**（未归一化）；后验相差 `+log p(d)`，这个 offset 不为零且没有被携带。这不影响 MCMC（势能只需定到常数），但任何把 `U` 的绝对值当密度读的消费者必须知道。

**三条结构性规则**（每条被破坏都是静默的、看起来健康的错误）：

- **(R1) 归约 graph**。交给 NUTS 的 graph 必须**删掉** `i in E` 的观测节点与已积掉的 `zeta_i`。否则数据被计两次。
  **但 R1 的症状描述被驳回了**（§2.9）：「每个宽度精确除以 `sqrt(2)`、均值不动」是平坦先验产物，而且这个数字在 bayesmith 里从未被测量（Q5 自己的「what I did not run」承认是从 rheplicant 引用的）。
  **而且 R1 在共享 nuisance 下不可满足**（原 Q5 C4 被驳回）：一个 nuisance 同时被压缩数据集与活数据集携带时，R1 说要删掉「its integrated zeta_i」，但活数据集需要它，删不掉。对手实测：mean 偏 `+3.35` 后验 sd，宽度膨胀 `1.62×`，对 MCSE 是 `108 sigma`；控制组（nuisance 真正局部）gap `4.4e-16`。而且这种项**走 bayesmith 自己的 API 就能造出来**（`compress` 覆盖 `("theta","zeta")` → 加 zeta 先验行 → `marginalise(("zeta",))`，对 dense 吻合 `1.1e-14`），且结果与一个合法地从未携带 zeta 的项**逐位不可区分**。**这是 §7.9 拒绝项的来源。**
- **(R2) 先验只用一次**（§5.2）。
- **(R3) 坐标**。项必须建在与 NumPyro site 相同的坐标里。
  **机制描述被更正**：`numpyro.factor` **不接收任何 Jacobian，也不需要**——项是数据上的密度，不是 theta 上的。故障是真的（错坐标下 offset 差 `-1.7994 nats`，后验均值 `1.2827 → 3.6899`），但原因就是「似然在错误的点上求值」。原诊断会让读者去找一个不存在的 Jacobian。
- **（本文新增）一个 factor 若发在 `numpyro.plate` 内部会被乘以 plate 大小**（实测比值精确 `5.000000`，plate 为 5）。bridge 在 plate 内发 Probabilistic 节点，一个写在那个循环旁边的第二 factor slot 与此只差一级缩进。

**factor slot 的归属**：`numpyro.factor` 今天只用在一处——本次实读 `bridge/numpyro_bridge.py:86-95`，为 `graph.joint_prior`。**那个 slot 是错的家**，而且不只是命名问题：`JeffreysPrior.information` 拒绝一个携带 proper 密度的被覆盖 latent，并要求被覆盖 latent 声明为 `ImproperUniform`；而似然 factor 需要相反的东西——共享 `theta` 必须**保住**它的先验。所以需要一个与 `joint_prior` **不相交的第二个 graph 级 factor slot**。§0 关于「joint prior」一词的警告在代码层面是一次真实碰撞，不只是文风。

## 7. 拒绝清单

每条给出它保护的数学陈述。按「今天有多不设防」排序。

### 7.1 复数 `factor` / `target`（**必须拒绝，今天完全不设防**）

**保护的陈述**：组合定理 (3.7) `U^T U = M~^T M~`。

**为什么失效**：`log_prob` 算 `-0.5 * jnp.sum(residual**2)`——双线性型 `r^T r`；而复 QR 的 `Q` 是**酉**的，保 `r^H r` 不保 `r^T r`。`information()` 是 `factor.T @ factor` 无共轭。

**我本次的最小验证**（`final/verify.py`）：一个共享复标量 `g`，`R_1 = [[1j]]`、`R_2 = [[1]]`、`z = 0`：

```
claimed  sum_i E^T R_i^T R_i E_i = 0j          (手算：(1j)^2 + 1^2 = 0，无任何舍入)
combine(t1,t2).information()     = (2.0000000000000004-0j)
t1.log_prob + t2.log_prob        = 0j
combine(...).log_prob            = (-1.0000000000000002+0j)
```

**0 对 2**，绝对误差等于真值全部。没有任何 StructureError、没有警告。

**可达性**：不是构造器滥用——`compress` 本身接受复设计块，返回 `factor.dtype == complex128` 而 offset 是 float64（**「常数都对」恰是读起来正常的那部分**），组合两个这样的项给相对 `1.36e+00`（F）与 `1.40e+00`（b），对数密度差 `3.48e+02`。`compress_epoch` → `marginalise` 全程也不拒绝：一个圆对称复高斯 **满足 §4.1 声明的两个前提**（模型对 `zeta` 精确仿射；先验高斯且对角），返回 `-8.32893246906838 + 3.1747698843570067j` 对真值 `-26.180767170210`——**实部错 17.85 nats，外加一个对数概率里的虚部**。realify 路线（bayesmith 自己的 `ComplexNormal` 规定的那条）给 `-26.180767170210`，吻合 `1e-12`。

**本次实读确认**：`grep -rn complex src/bayesmith/evidence/` **零命中**。而 `optimize.py::_refuse_complex` 与 `diagnose/local.py` 已有明写理由的拒绝，`exact/block.py::real_parts` 存在正因为「the map from complex coefficients to data is R-linear but not C-linear」，`exact/fisher.py` 三处分支于 `is_complex`。**`evidence/` 是唯一既不处理也不拒绝复数的 kernel family，而本包的目标域是 visibility。**

**修法有两半，选哪一半取决于 `ComplexNormal` 的语义，卷宗没有人选**：(a) 在 `SqrtInfo.__check_init__` 拒绝；(b) 在 `log_prob` 与 `information` 里加共轭（`jnp.abs(residual)**2` 与 `factor.conj().T @ factor`）。**本文的建议是 (a) 加上一个 realify 层**，理由是 §9.4：realify 的列序本身是设计决策，藏在 `log_prob` 里会让它不可声明。

### 7.2 非有限 `factor` / `target` / `offset`（必须拒绝）

**保护的陈述**：(3.9) 的 offset 记账。`combine` 没有有限性守卫，`offset` 变 `nan`。方向不对称且危险：**factor 里的 nan/inf 污染 F 的 8/9 格与整个 b；target 里的 nan/inf 让 F 看起来完全健康（0/9 nan 格）而 offset 与 b 是 nan**——一个检查 `information()` 的审计会读到干净的结果。加上 §3.1.1 的 `0*inf = nan`：污染会扩散到该数据集从未命名的 latent 列。

`N` 个独立压缩的数据集的暴露面是单 graph campaign 的 `N` 倍。rheplicant 有 `reject_bad_term`（本次实读 `memory.py:160`），bayesmith 这一侧没有逐项准入闸。

### 7.3 混合 dtype（必须拒绝）

float32 + float64 静默提升。实测把「精确」降级到 `relF = 1.04e-08`。两个不同 session 压缩的数据集很容易 dtype 不同。

### 7.4 标签正确而列散射错误的项（必须拒绝，需要新机制）

**保护的陈述**：`x_i = E_i x`，即嵌入定理 §3.1。实测 `5.599938 nats`、`||dF||/||F|| = 1.038`、秩 `5 → 4`，`combine` 不抛。这是多数据集嵌入层**最可能**的出错方式。需要 §9.2 的列见证。

### 7.5 两个 graph 对共享 latent 的先验分歧（必须拒绝，谓词见 §5.7）

含 `JeffreysPrior` / `ImproperUniform` 的例外规则。

### 7.6 混合 `estimator`（必须拒绝）

**保护的陈述**：`SUM_i log L_i` 是某个模型族里某个模型的对数密度。`full` 与 `gls` 的和不是任何数据集在任何模型下的对数密度，且差额在 `sigma` 依赖 theta 时是 **theta 的函数**（§5.5 D2）。rheplicant 拒绝（`memory.py:227-235`）；bayesmith 无对应标签。多数据集下每个数据集可能由不同的人压缩，这是**最可能的准入故障**。

### 7.7 秩为 0 的项 + improper 先验（必须拒绝）

**保护的陈述**：(H5)。实测：秩 1 项对 2 维 theta + `ImproperUniform`，势能有限、光滑、二阶可微——按 §6.4 的每一条判据都「valid」——NUTS 顺利跑完，零方向游荡到 mean `1.2e17`、sd `7.0e16`。**没有后验。** 全 flag 掉的数据集（`n_seen = 0`）是同一情形的极端。`combine` 没有秩闸也没有有限性闸。

### 7.8 相关（非对角）nuisance 先验

**部分更正**：原推导说「nuisance_prior cannot express it and does not refuse」。实测**它拒绝**——传完整 `(q,q)` 协方差或其 Cholesky 都抛 `ValueError: Cannot broadcast to shape with fewer dimensions: arr_shape=(3,3) shape=(3,)`。**未定型的拒绝（ValueError 而非 StructureError），不是静默通过。** 真正的危险是它**接受**长度 `q` 的边缘 std 向量——那正是用户会打的东西——而 (5.2) 在相关 `S` 下错到 `1.611920 nats`。设计要点（应当是 `StructureError` 并给出正确的一般形式）成立；原论断的机制描述不成立。

### 7.9 一个 nuisance 同时被压缩项与活数据集携带（必须拒绝）

**保护的陈述**：(H2) 的不相交性，跨 E/X 划分。§6.4 (R1) 在此**不可满足**。实测 `+3.35` 后验 sd、`1.62×` 宽度膨胀、`108 sigma`。而生成的项与合法项**逐位不可区分**，所以这个拒绝只能建立在**声明**上（`iota` + 每数据集的 nuisance 归属），不能建立在项的检查上。

### 7.10 一个 latent 在一个 graph 里是 survivor、在另一个里是 per-epoch nuisance（必须拒绝或提升）

**保护的陈述**：(H3b) 跨 graph。若 `s` 在 `G_1` 里被积一次、在 `G_2` 里被对独立先验积 `N` 次，则 `L_1` 与 `L_2` 是**不同模型**的边缘，它们的乘积不是任何模型的似然。

**这个情形在卷宗五份推导里全部缺席**，而它不是假想的：本次实读 `rheplicant/inference/graph_bridge.py:324-341` 的 `_refuse_scopes_without_a_graph_spelling` **今天就拒绝** `scope='per_epoch'` 与 `scope='linked'`，并给出理由与去处。**任何以「声明 iota」开头的设计都必须说清这个拒绝会怎样，而卷宗无一处说了。**

### 7.11 针对过期并集框架构建的项（必须拒绝或重嵌入）

当数据集 `N+1` 引入一个新的共享符号时并集框架增长，此后每个已存项的 `names`/`shapes` 都与新框架不符，`combine` 抛异常。重嵌入按 §3.1 是精确且免费的——**但卷宗任何一处都没说过这件事，也没推导「重嵌入确实是一次选择而非一次重排」这个检查**（§3.1.1 表明这正是静默错误最可能发生的形状）。**这个拒绝在任何增长中的 campaign 的第二个数据集上就会触发。**

### 7.12 超出信赖半径的线性化项（必须拒绝，检查是累积器的性质）

**保护的陈述**：(6.4)。与 `estimator`、`prior_share` 不同，这不是项自己的性质——一个后来的、更有信息的数据集能把累积后验拽出早先项的信赖半径，**追溯地**使一个写下时完全合格的项失效。所以检查必须在**每次准入**时以及累积器每次变化时重跑。操作定义未定（§10.3）。

## 9. 真正需要新建的东西

### 9.1 跨 graph 身份映射 `iota`（最上游，一切依赖它）

```
iota : (graph index, latent name) -> shared symbol
```

**必须是声明**（§3.1.2，被 `trace.py` 的 `_owner` 决定所强制），且多数据集后验**只相对于 `iota` 才是良定义的**。

**卷宗从未给出它的良构条件。本文给出：**

1. **函数还是关系**：偏函数。未映射的 latent 是局部的。
2. **纤维一致性**：`iota` 的每个纤维必须在 **shape、dtype、以及先验声明**（按 §5.7 的谓词，含 Jeffreys 例外）上一致。**shape 分歧的正确处置卷宗没有推导，本文也不能定**（§10.2）。
3. **传递性**：三个 graph 上必须传递。这不是自动的——`iota` 声明为一族 `(graph, name) -> symbol` 的映射时自动传递；声明为两两配对时不自动。**用符号形式，不用配对形式。**
4. **规范列序**：`U` 的序必须是 `iota` 声明的确定性函数，不是任何 per-dataset dict 的迭代序（今天 `compress` 从 `tuple(design)` 取列序，即调用者 dict 的构造顺序）。
5. **（卷宗完全没碰的情形）在向量 latent 的分量上可以是偏的吗？** `G_1` 声明 `theta` shape `(5,)`，`G_2` 只测分量 0 和 3。**这是普通的异质仪器。** `E_i` 恰是为它设计的机器，但 §3.1 把 `E_i` 定义在整 latent 粒度上，而 `names`/`shapes` 表达不了分量级选择，所以 `combine` 会拒绝它。**这是设计必须决定的一件事，而没有推导触及它。**

### 9.2 列见证（column witness）

嵌入层必须是并集框架项的唯一生产者，并随项发出它占据的并集列下标元组，使 `combine` 校验散射而非标签（§7.4）。

**约束**：`SqrtInfo` 没有这个字段，而加一个字段会改动 campaign scan 依赖的 pytree treedef（`names`/`shapes` 是 `eqx.field(static=True)`）。**三个候选归宿，本文不能定**：住在 `SqrtInfo` 之上的 wrapper；嵌入层自己维护一本独立台账；或者推广 `shapes`。见 §10.1。

### 9.3 第二个 graph 级 likelihood factor slot

与 `joint_prior` **不相交**（§6.4）。协议可以照抄 `joint_prior` 的（`over` + `log_density(graph, values)`），`SqrtInfo` 已经同时提供 `names` 与 `log_prob`。**归约 graph（删掉已压缩数据集的观测节点与已积掉的 latent）必须与挂 factor 是同一个操作**，不能是调用者约定，否则数据被计两次而没有症状。而且**不要在 plate 内部发它**（§6.4 末）。

### 9.4 realify 层

`ComplexNormal`、`exact/block.py::real_parts` 与 `graph_bridge` 对复 latent 要求 `ComplexNormal` 都已存在。缺的是**数学**：并集列序是按分量交错 `(Re, Im)` 还是分块？`E_i` 在 realify 下存活吗（只有当两个 graph 以相同方式 realify 时才存活）？`G_1` 把某量声明为复、`G_2` 把同一物理量声明为实数对时怎么办？**卷宗三次诊断出这个缺陷、零次推导它。**

### 9.5 从 rheplicant 移植的准入闸

`estimator` 标签（§7.6）、`prior_share` 见证（§5.2）、`(product, content-hash)` 的 `inputs` 规则（§4.2）、逐项有限性（§7.2）。本次实读确认它们全在 `rheplicant/inference/{memory,compressed}.py`，bayesmith 这一侧全无。

**注意 `_reject_shared_inputs` 是一个已发货的、纯声明式的探测器**（对手实测：共享 `("gain_soln","sha:9f1c")` 的两个 epoch 被 `StateValidationError` 拒绝；换 hash 则**放行**（所以它有分辨力，不是一刀切）；声明 `Factorization(represents=...)` 后也放行，即它结构性地认出了「提升」这条补救）。它不求值任何密度。**这修正了 Q4 B6 的措辞**：正确说法是「**没有逐项数值检查**能侦测它」，而不是「只有联合参照能」——差别是承重的，是「需要联合 oracle」与「需要一个 provenance 字段」的差别。

（对手还构造了一个逐项**数值**探测器：读每个项自己的 nuisance 后验、对独立抽样零假设检验聚集性，`N=96` 时 `-7.34 sigma`、8 个对照全清白；但 `N=2` 时 0% 检出，需要 `N≈32` 才过 3 sigma。所以「结构上不可能」在两数据集情形对、在 campaign 尺度错。）

### 9.6 nuisance 先验的类型分裂（跨 graph 版本）

`FixedNuisancePrior`（数值，压缩时消掉）vs `HyperNuisancePrior`（builder，likelihood 内消掉），使错误选择成为**类型错误**而非静默平坦的 `eta` 后验。先例是 `chain.py` 的两类 transition。**但 §8.4 的更正意味着这要从零建**：`hyper` 今天按 epoch 键控 per-epoch latent，跨 graph 共享的 nuisance 超参无处安放。

### 9.7 Tier 1.5 的存储契约

由 §4.3 与 §6.2 的驳回产生，卷宗任何设计里都没有：一个 builder-backed 项存的是**充分统计量 + resolver**，不是 `(R, z, offset)`。它**不能** QR 折进 `R_E`。累积器因而是混合的：一个折叠好的 `SqrtInfo`（全部 pin 住的项）**加上**一份 builder-backed 项的清单，每个 leapfrog step 逐个 combine。这改变了「累积器宽度由并集宽度决定」这句话的适用范围，也改变了成本模型（§10.4）。

## 10. 未决问题，以及能了断它们的测量

### 10.1 列见证住在哪里

`SqrtInfo` 没有字段，加字段会动 campaign scan 依赖的 treedef。三个候选见 §9.2。
**判定测量**：建一个 `(见证 in wrapper)` 与 `(见证 in SqrtInfo)` 的原型，测 `fold_epochs` 在 1000-epoch campaign 上的 `jit` 编译时间与每 epoch 时间（`campaign.py:218` 的注释记录了 treedef 变动会每 epoch 重 trace，且未向量化版本编译要 5.4 s——那是可复现的基线）。若 wrapper 版本编译时间不变，问题了结。

### 10.2 shape 分歧的正确处置

`combine` 拒绝 `((2,),)` vs `((1,2),)`（正确，因为 ravel 是 row-major，`(2,3)` vs `(3,2)` 只是巧合等宽），且拒绝信息只插值 `names`，于是调用者读到 `['a'] vs ['a']` 作为解释。**在多数据集层，shape 分歧是预期故障而 name 分歧不是，所以这条信息会被读成工具 bug。**
未定的是**应该**怎么办：shape 分歧是一次 ravel 序声明（合法，需要一个被声明的 reshape），还是一个建模错误（拒绝）？两者都可达，而答案决定 `E_i` 还是不是选择矩阵。
**判定测量**：不是数值测量，是一次设计裁决 + 一个真实的异质仪器案例。§9.1(5) 的分量级偏映射是同一裁决的一部分。

### 10.3 线性化项的准入检查怎么操作化

「累积后验的主体落在 `B(theta_0, rho_i)` 内」需要一个可执行定义（哪个分位数？在哪个度量下——累积 Fisher 的，还是项自己的？），而累积器的 Fisher 是现成的、后验的分位数要采样之后才有。
**判定测量**：用累积**精确**那一半的 Laplace 椭球作为采样前代理，在非精确半主导的情形下与真实 NUTS 后验的 `rho_i` 违反判定比对，扫 `k/N` 与非精确项的相对信息强度。

### 10.4 并集框架与 Tier 1.5 的成本何时不可承受

朴素并集框架是 `O((SUM_i n_local,i + n_shared)^2)` 稠密。而 §9.7 的混合累积器在**每个 leapfrog step** 上对每个 builder-backed 项做一次 `((rows_i + q_i) x (q_i + p + 1))` 的 QR，且**只有全部 `q_i` 相等才能 `vmap`**（否则按 `q` 分组，每组一次 traced 调用）。
**判定测量**：扫 `(N, q_i 分布, p)`，测每次势能求值的墙钟时间与编译时间，对照「不压缩、活在势能里」的基线。这决定 §6.2 tier 1 与 tier 1.5 在实际 campaign 上的分界。**卷宗完全没测过。**

### 10.5 `refuse_undeclared_coherent_error` 能否推广到 N 个 graph

它今天是单个布尔量（`diagnostics.py:142`）。多数据集下需要每共享符号、每共享子集一份声明吗？
**判定测量**：在 `_reject_shared_inputs` 的语义下构造两个共享子集部分重叠的场景（`zeta_a` 被 {1,2,3} 共享、`zeta_b` 被 {2,3,4} 共享），检查单布尔声明是否能同时正确放行合法情形并拒绝违规情形。

### 10.6 数据集的身份是什么

`SqrtInfo` 有五个字段、**没有任何身份**。(H4) 需要「不重复计一次观测」——一个关于诸 graph 观测节点并集的陈述。真实场景（一次定标扫描同时用作 calibrator 与 science target）**在卷宗与本文都未解决**。
**判定测量**：先做设计裁决——身份是 `(graph id, observed node name, content hash)` 三元组，还是观测数组本身的 content hash？后者能捕获「同一份数据经两个 graph 进来」，前者不能。造一个双 graph 复用同一扫描的 fixture，测两种身份定义各自的拒绝率与误拒率。

### 10.7 非高斯情形的定量

本文全部闭式都是线性-高斯。定理 1 及其假设与分布无关，但 §2.7 的闭式（乘积 = 删掉一个协方差块的联合）不是，§2.8 的 `sqrt(N)` 律是关于秩一 deflation 的陈述。**共享 nuisance 误差在非共轭数据集上长什么样，无人测量。** 这要紧是因为 graph 层已经把任何非高斯观测节点路由到 NUTS，异质 campaign 必然撞上。
另有一条实测提示：非高斯共享尺度 nuisance（`f_i = lam*eps_i`）给 `Cov(f_1,f_2) = 1.10e-03`（在 MC 精度内为零）而 `Cov(f_1^2, f_2^2) = 3.515425`——条件相依、乘积形式错、**误差在二阶矩里完全不可见**。所以离开高斯之后，协方差框架连误差的**大小**都刻画不了。
**判定测量**：一个 StudentT 观测 + 共享 nuisance 的两数据集 fixture，用长链 NUTS 对比联合与乘积后验，扫共享强度。

### 10.8 `check_linearity` 从未在 evidence 层被调用

`grep` 确认（上游 map 的结论，本文未复查该 grep）。一个对 latent 非仿射的模型会在零点被静默线性化。本文所有「精确到 1e-15」都是对**实际被求值的那个仿射模型**精确。
**判定测量**：在 `compress` 与 `compress_epoch` 的入口加一次 `check_linearity` 调用，测它在真实 campaign 上的代价与误报率。

### 10.9 consensus 约定在真正分布式拟合下是否要支持

§5.3(2) 证明**标量 `prior_share` 在子集共享下无法正确编码任何 consensus 约定**（后验协方差非对角元被打成精确 0）。所以要么放弃 consensus，要么 share 必须**按符号索引**：约束是 `SUM_i s_i = 1` **每个共享符号一次**，不是每个 campaign 一次。今天没有任何东西按符号索引 share，而且 `audit()` 的 `prior_shares_sum` 已经是弱见证（`share` 只是 `QuadraticLikelihood` 的属性，`ReducedBasisLikelihood` 无论携带什么都记 0）。
**判定测量**：设计裁决 + 一个按符号索引的 share 台账原型，在 §5.3(2) 的相关先验 fixture 上验证它能恢复真值（`[0.4955489614, -0.2885756677]`，非对角 `+0.029674`）。

## 13. 一句话总结

**联合后验 = 一个共享先验（只施加一次）× 每数据集边缘似然的乘积**；乘积在定理 1 的五条假设下成立，而这五条**必须被声明与拒绝，不能被测量**（§2.5 的仿真探针是唯一例外，且只在压缩之前可用）。项的合并是精确的、可交换的、`O(width^3)` 的——嵌入是选择矩阵右乘、QR 保 Gram、offset 吸收角落——**只要框架由一个被声明的 `iota` 唯一确定，且列散射有见证**。真正的工程难点不在代数（代数在本 checkout 里已经对到 `1e-15`），而在于：**没有任何东西声明跨 graph 的身份，没有任何东西给项一个身份，没有任何东西拒绝复数，没有任何东西在压缩之后能看见共享结构——而压缩正是把那个信息销毁掉的操作。**
